# The theme studio

Status: unit 1 (mode, dock, Themes tab) and unit 3's server and client-core half done 2026-09-25 (lane L1); units 2, 4, 5, 6 next. D12's `bundle ` scope folds into `theme `: Decided 2026-09-25: recommendation (completion wave). Requested 2026-09-19, the day [Plan 117](../docs/theme-bundles.md) shipped. Replaces 117's gallery, creation dialog and variant editors. Keeps 117's contracts, server library, archive and resolver, and Plan 123's wallpaper library, renditions and palette-scope preview.

Plan 117 built the right data: a theme is a light and a dark variant, each with app colors, code colors, a wallpaper and a material, customizable per variant, portable as one archive. It then put that data behind the wrong door. Choosing a theme is a settings row; the row lives in a settings page that opens as an editor tab, so the editor — the surface a theme changes most — is replaced by the page that is supposed to show the theme. Creating one is a modal whose backdrop blurs the app you are trying to see. The preview inside each card is nine lines of a fake file. Wallpaper, app colors and code colors each have a separate widget and a separate dialog for what is one decision.

The principle this plan builds on: **the app is the preview, and you keep using it.** Nothing in the studio renders a miniature of the workbench. The workbench stays live, full size, unblurred, and repaints as the user browses. The studio is a thin layer of chrome over it, and it is not modal: with a draft theme showing, the user opens files, switches tabs, scrolls a diff, runs a command in the terminal, reads a chat reply — and the draft stays on screen through all of it, until they decide it is right and commit it. Once that is true, the cards can be small, the dialog can go, and the five widgets collapse into tabs of one place.

## What is wrong

| Area       | Finding                                                                                                                                                                                                                                   |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Place      | A row in a filterable settings list, inside an editor tab. Half the viewport is the file tree and terminal, the editor is gone, and the cards get a 280px grid inside a scroll box.                                                       |
| Preview    | Cards render a 9-line snippet, a swatch row and `$ ready`. No sidebar, no tabs, no selection, no diff, no chat, no terminal output, no wallpaper under real content. Keyboard focus previews the live app; hover does not; click applies. |
| Creating   | `Create a theme bundle` is a modal. Its backdrop blurs the workbench, so the only real preview is hidden while editing. `Preview` is a button. Opacity, blur and saturation are raw number inputs.                                        |
| Halves     | `Light version` / `Dark version` are toggle buttons in the dialog. Editing one hides the other; there is no way to see both, or to know which one the app is currently in.                                                                |
| Five doors | Theme, palette, code theme, wallpaper (two tiles + dialog), material: five widgets, three dialogs and a palette scope for one decision. Fonts and density are settings and stay so; the other five are the theme.                         |
| Wallpaper  | Bound into the variant, but chosen through a dialog inside a dialog. No relation between a wallpaper and colors in either direction: nothing derives colors from an image, nothing sorts images by the colors you have.                   |
| Words      | "Bundle", "variant", "part", "material", "customization", "Use theme defaults" — the storage model leaked into the labels. The user picked a theme and moved a slider.                                                                    |
| Keyboard   | Four palette scopes preview on arrow — `theme ` (syntax only), `colors `, `wallpaper `, `color ` (mode) — and none of them is the theme. The whole-theme choice, the one that matters, has no keyboard path but a settings search.        |
| Entry      | Not in the command palette by name, not in the titlebar menu, not on first run. `Control+,` opens settings; from there it is a search for "Theme bundles".                                                                                |
| Exit       | No draft. Every change writes a customization at once, so "try, then decide" is "change, then undo one field at a time". Escape restores a focus preview and nothing else.                                                                |
| Terminal   | The pane behind the row repaints; nothing in the row shows terminal colors beyond four ANSI swatches. Sixteen ANSI colors, cursor and selection are never seen against real output before choosing.                                       |
| Thumbnails | Cards crop the wallpaper to a 140×55 strip; nothing conveys the image. The picker dialog's cards do, at 165px, in a dialog that cannot show the image on the app.                                                                         |

## Decisions

| Decision                         | Behavior                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1 — a mode, not a page          | The studio is a workbench mode: a `studio` flag in the layout store, entered by command, palette or the Appearance row, left by Escape, Apply, or the close control. The workbench renders as it is — same panes, same documents, same terminals — and gains a dock along the bottom. No dim, no blur, no modal. The workbench is fully usable underneath: open files, switch tabs, open a diff, type in the terminal, read the chat, use the command palette. The draft and its preview survive every one of those; the studio only ends on Apply, Escape from the dock, or the close control. With no folder open the dock sits over whatever the root shows, and D9 gives the editor something to show. |
| D2 — the dock                    | A `PaneBar`-height header (name of the draft, dirty mark, Light / Dark switch showing which one the app is in, tab strip, Revert, Apply, close) over a content strip of one fixed height. Tabs: **Themes**, **Colors**, **Code**, **Wallpaper**, **Surfaces**. The dock is opaque (`bg-popover-solid`); the workbench above it is the preview, the dock is not. It can be collapsed to the header alone so the whole workbench shows.                                                                                                                                                                                                                                                                      |
| D3 — one draft                   | The studio owns one `ThemeDocument` draft plus a `customized` flag, seeded from the selected theme with its saved customizations applied. Every control edits the draft; the draft previews through `previewBundle` on every change, so the app is always showing the draft. Apply writes the selection and both variants' customizations in one request. Escape or Revert discards the draft and the preview; a dirty draft asks once. Nothing reaches settings, the boot mirror or the library until Apply.                                                                                                                                                                                              |
| D4 — Themes tab                  | A horizontal strip of cards, arrow keys move, Enter applies, hover or focus previews. A card is identity, not a preview: name, a wallpaper crop for the mode the app is in, six swatches (background, foreground, accent, three ANSI), a `customized` dot, source badge for imports. Selecting a card replaces the draft; the strip's selected card stays framed while other tabs edit it. `New from current`, `Duplicate`, `Import…`, `Export…`, `Delete` are a menu on the card and a `+` tile at the end.                                                                                                                                                                                               |
| D5 — Colors tab                  | App and terminal colors for the mode the app is in. Left: the palette catalog as swatch rows, choosing one previews. Right: the existing color editor (`palette-editor` fields, `deriveFromAccent`, `deriveFromBackground`, the contrast readout) editing a copy that the draft references. Editing a bundled palette forks it into a user palette the way 117 already does; the studio does the fork silently on first edit and names it after the draft.                                                                                                                                                                                                                                                 |
| D6 — Code tab                    | The syntax theme list for the mode, with the real editor behind it as the only preview; chat code blocks already follow the editor theme, so they repaint too. Preview goes through `previewEditorTheme` in `color-theme-store.ts`, which already overlays without writing. The tab shows the current theme's name and the `tree-sitter` fallback. The always-on `CodeThemePreview` panel goes.                                                                                                                                                                                                                                                                                                            |
| D7 — Wallpaper tab               | Plan 123's picker body, inlined: sources, uploads with drop and paste, Omarchy sections, filter. Choosing previews on the app for the mode shown. Two additions: a **Matches** sort that ranks images by OKLCH hue and lightness distance from the draft's background and accent, and a **Colors from this image** action (D8). The wallpaper dialog and the two-tile row go; the `wallpaper ` palette scope stays as the quick path.                                                                                                                                                                                                                                                                      |
| D8 — colors from a wallpaper     | `POST /themes/wallpapers/:id/colors` quantizes the display rendition with `sharp` (64×36 raw pixels, median cut in OKLCH, eight clusters with weights) and caches the result beside the renditions. `paletteFromWallpaperColors(clusters, mode)` in client-core picks background from the largest cluster near the mode's lightness, accent from the most chromatic, derives the rest through the existing `deriveFromBackground` / `deriveFromAccent` path and nudges text pairs until the 4.5:1 readout passes. The result is a user palette the draft references; the user edits from there.                                                                                                            |
| D9 — a sample file               | `Open a sample` in the Code tab opens one bundled TypeScript file as a read-only virtual document and closes it on exit. That is the whole stage: it exists for a fresh install or a folderless root, where nothing else is open. Everything else a theme touches — diff, terminal, chat — is previewed by opening the real thing, which is what the live workbench is for. No fixture transcripts, no terminal script, no layout snapshot.                                                                                                                                                                                                                                                                |
| D17 — focus stays where it is    | Opening the studio moves focus into the dock once. After that, keys mean what the focused surface says: arrows and Enter in the dock move and apply, Escape in the dock leaves the studio, and the same keys in the editor, terminal or chat are theirs. The dock registers as a focus area, not an overlay, so it never captures keys from the panes. Moving between dock and workbench is the existing focus-area cycling; the command that opened the studio refocuses the dock when it is already open.                                                                                                                                                                                                |
| D10 — Surfaces tab               | Pane opacity, content opacity, blur and saturation as sliders with live values, plus three presets: Solid, Frosted, Clear. Dragging previews at frame rate through the same draft path; the material stylesheet write is the only per-frame cost.                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| D11 — the words                  | Theme. Light and Dark. Colors, Code, Wallpaper, Surfaces. "Customized" as a dot and a `Revert` that resets the draft variant to the theme's own values. No bundle, variant, part, material or customization in any label, title, toast or aria name. Contracts keep their names.                                                                                                                                                                                                                                                                                                                                                                                                                           |
| D12 — quick switch               | The `theme ` palette scope changes meaning: rows are whole themes, the highlighted row previews the app through `previewBundle`, Enter applies, Escape restores, the last row is `Open theme studio…`. The syntax picker moves to `code `. `colors `, `wallpaper ` and `color ` stay. `ctrl+k ctrl+t` and `workbench.action.selectTheme` map to `theme `, since that is what the chord means to a VS Code hand.                                                                                                                                                                                                                                                                                            |
| D13 — entry points               | Command `Appearance: Theme studio` (no default chord; the palette row, a `Theme…` item in the titlebar menu beside `Settings…`, and the Appearance section of settings reach it). Appearance in settings becomes one summary row — current theme name, both wallpaper crops, `Open studio` — with fonts, density and reduce-motion below it as today.                                                                                                                                                                                                                                                                                                                                                      |
| D14 — both halves                | The dock header's Light / Dark switch flips the preview mode without writing `workbench.colorTheme`; `\` toggles it. The Themes card shows both halves; every other tab edits the half the app is showing and names it in the tab header. The app's real mode is restored on exit.                                                                                                                                                                                                                                                                                                                                                                                                                         |
| D15 — bytes ahead of the pointer | The Themes strip and the Wallpaper grid prefetch the display rendition for the focused card's neighbours, so arrowing never shows a wallpaper arriving. Thumbnails come from the existing `/thumbnail` route.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| D16 — mobile and narrow          | Below 900px the dock becomes a sheet over the bottom half; the tabs stay. The workbench above it is still the preview. Nothing about the studio requires the sidebar or the terminal to be visible.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

Out of scope: per-pane themes, scheduled light/dark switching, video wallpaper, fonts and density in the studio, a public theme gallery, the TUI (it follows the shared keys as today).

## Implementation units

1. **Mode and dock.** D1, D2, D3, D11, D14, D16 with the Themes tab only (D4): the draft store, `previewBundle` on every draft change, Apply as one mutation with a `mutationKey`, Escape with the dirty prompt, mode switch. `dom` tests over the real in-process server: arrow previews and nothing is written; Apply writes selection and customizations in one request; Escape after edits leaves settings untouched; the mode switch never writes `workbench.colorTheme`.
2. **Tabs.** D5, D6, D10, then D7 by moving Plan 123's picker body into the tab. Tests: an edit on a bundled palette forks once and the draft references the fork; slider drag previews and Apply writes one material patch; a wallpaper choice lands in the right variant.
3. **Wallpaper colors.** D8 server and client-core, the Matches sort, the action in the tab. Server tests on a fixture image with known clusters; a client-core test that every generated palette passes the contrast readout for both modes.
4. **Sample file.** D9: the virtual document opens, previews, and is closed on exit; a test that leaving the studio leaves no tab behind.
5. **Entry and quick switch.** D12, D13, the settings summary row, the deletions, the words pass over every label. Command inventory and settings page tests updated.
6. **Proof and ship.** Scenarios against the mesh, screenshots read back, `bun run settings:reference`, `bun run deploy --server`, this plan deleted and the reference rewritten.

Units 1 and 3 touch different files and can run concurrently. Unit 2 needs 1.
