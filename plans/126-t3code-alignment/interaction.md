## Findings and implementation slices

### [INTERACTION-01] Match queued follow-ups and the default send behavior

- **Priority/confidence:** P1 / HIGH.
- **Evidence:** Upstream `packages/contracts/src/settings.ts:438` defaults `followUpBehavior` to `queue`; `apps/web/src/components/ChatView.tsx:7630` queues running-turn content, including attachments/context, and applies the alternate-submission inversion; `:8604` sends one message per tool-completion/end boundary, gated by requests/connection/settings. Local `apps/web/src/features/chat/components/chat-view.tsx:289` immediately builds a steer for every busy session; `components/chat-input.tsx:150` only permits busy Codex sends, blocking other drivers. `state/chat-message-intents.ts:12` is an optimistic dispatch queue, not a retained user follow-up queue. Upstream `ChatView.tsx:3971–3983` restores the drained queue before awaiting interrupt; `:7203–7247` appends it after the current draft and holds attachment overflow for explicit Send now.
- **Impact:** Identical Enter sends interrupt/correct immediately locally when upstream waits for a safe boundary. Users cannot collect follow-ups, Send now, remove one back to the editor, or stop and recover pending content.
- **Effort/risk:** L / HIGH: ownership across Stop, tool events, dispatch acknowledgment, and connection recovery.
- **Fix scope/dependencies:** Add an environment/session-owned queued-message model and full draft snapshots, wire timeline rows and composer intent, register the setting in the settings registry with upstream default, and retain explicit immediate steer. Depend on attachment/context contracts where supported; do not postpone text queue behind every optional context type. Provider capability handling must come from runtime parity work.
- **Acceptance:** Queue A and B during a running turn; a tool boundary sends only A, the next boundary sends B. Pending approval/question holds both. Clear a connection gate without another tool event and the due head resumes. Stop during attachment upload drains/restores exactly once **before** awaiting the interrupt RPC. With a nonempty draft and more than eight combined attachments, fill available composer capacity and keep every excess attachment visibly queued with an explicit-action hold; a later tool boundary must not send that overflow. Interrupt rejection leaves recovered content available. Failed delivery holds the head with visible recovery and never duplicates a turn. Alternate send reverses configured queue/steer behavior. Session/environment switches cannot redirect queued work. New setting is live, documented, and defaults to queue.
- **Verification:** V1 plus new `state/tests/queued-follow-ups.test.ts` and new browser scenario `chat-queued-follow-ups`. Use real orchestration with an injected external provider boundary; include uncertain acknowledgment and Stop/upload concurrency.
