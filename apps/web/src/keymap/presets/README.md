# Window keymap presets

Zed and ours start from the same translations of Zed assets/keymaps/default-linux.json and default-macos.json at commit a84689073d296dfd39987bc7dd478e43ef76d83a. Unmapped actions stay in the data with their original context and action for the Settings report. Linux rows also serve Windows. Ours began as an exact copy. Plan 206 explicitly requires Mod+[ / Mod+] to navigate between documents from an Editor, so its four conflicting Linux/macOS indent/outdent rows become Workspace navigation bindings. The rows retain their upstream action and record the authorized deviation. Zed keeps its original indent/outdent keys. Ours also loads the VS Code application rows for every command that no Zed row binds on that platform; `ours-fregat.json` records each of those keys that moved because Zed uses it in an overlapping context, with its reason. `ours-fregat.test.ts` fails when an application command lacks an `ours` key or an added key matches a Zed key in an overlapping context.

The VS Code application rows were extracted from Fregat command metadata before the window-dispatcher cutover. The runtime table keeps its 78 active rows and their normalized keys; excluded application-default rows, duplicate raw chords, and redundant preset filters are removed. Named Editor packs supply its Editor layer. Terminal application defaults live separately in apps/tui/src/commands/presets/default.json.

The rich `zed.json` inventory is authoritative. `ours-patches.json` stores the four indexed changes and their upstream identities. Settings loads `inventory.ts` through its browser-resource query and mutation; the keyboard runtime imports only the generated `runtime.ts` table. The table preserves executable and reserved rows in source order, including terminal arguments and upstream command ids. Unmapped and unsupported keys remain in the full report.

After changing the inventory, regenerate the synchronous table with `bun apps/web/scripts/generate-preset-runtime.ts` from the repository root. Add `--check` to verify it. Run `bun install --frozen-lockfile` and `bun run build:workspaces` first. The generator uses the root `typescript-api` dependency to derive `PlatformCommandId` from the live registration types, validates those IDs against the pure shared catalog, and checks each patch's row identity. It reads the authoritative Zed JSON directly and executes no browser handlers. Unresolved or nonliteral command types fail generation. `preset-data.test.ts` checks the bare Bun CLI, exact live command membership, generated table, and frozen semantic hashes captured at fd1729638c6c7fc1b78244f05a4acba7dfa66ea8 across every preset, platform and shell-key mode. Update that control only when the preset contract intentionally changes.
