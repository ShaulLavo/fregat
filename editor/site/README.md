# Singapore documentation

Astro serves ordinary HTML prose under `/docs`. Hand-written Markdown uses Astro's Markdown processor; Starlight owns MDX, the package list, generated API reference and Pagefind. Navigation is normal page navigation. The document scrolls on phone and desktop. The home page has its existing inline editor, and `/demo/` is a separate app that the landing page never loads.

Fenced examples use Singapore's document paint, captured during the build. `scripts/capture.ts` builds a browser-only capture entry and starts owned loopback servers on explicitly allocated free ports. `src/manual/examples.ts` requests each distinct source/language once. Capture opens an actual editor with the site's theme and font, saves `captureSnapshot({ scope: 'document' })`, and emits `mountPaintSnapshot` HTML at seven bounded column widths. Container queries select the largest fitting width. All row geometry and line breaks come from Singapore; the site does not implement line breaking. Colour spans keep JavaScript-off snapshots readable. A small blocking paint-only script in the head calls `preparePaintSnapshotHighlights`; the script beside each root calls `activatePaintSnapshotHighlights` before its first visible frame. It restores the captured text nodes, preserving CSS Highlight shaping. Both light and dark paints are emitted. The servers and browser close in `finally`.

Examples start static. A quiet **Make live** button is their only activation path. On idle, the editor module is loaded and examples within 600 px of the viewport prepare behind inert, invisible hosts. Preparation never focuses an input. A ready button switches the same-sized box immediately and focuses its input with `preventScroll`. An early click announces preparation while the static example stays visible. Each live editor uses content-height mode and word wrap, with document scrolling. There are no animated transitions. A later resize reflows the live editor naturally.

Fonts are preloaded on both manual and Starlight pages. Metric-matched local fallback faces share a font stylesheet. Optional font display avoids a late swap on a slow first visit; cached fonts are available on following pages. The skip link explicitly focuses the main region.

From the Fregat checkout root, install with `bun install --frozen-lockfile` and build editor packages with `bun x turbo run build --filter='./editor/packages/*'`. Install Chromium for build-time capture with `bun --cwd editor/site x playwright install chromium`. Run `bun run --cwd editor/site build` to check samples, generate the API reference, capture examples and validate rendered links. Preview with `bun run --cwd editor/site preview --host 127.0.0.1 --port 4329`, choosing an unused port. Capture artifacts live in gitignored `.capture/`.

After building, `bun run --cwd editor/site test:browser` covers Chromium and WebKit at 320, 390, 768 and 1280 px, static browsing, JavaScript-off readability, phone scrolling, explicit activation, focus, no nested scroll, layout shifts, and early clicks. Tests skip a browser with a stated reason when absent. Browser tests start and stop their own loopback preview. On Arch Linux, follow the repository's WebKit setup instructions after downloading WebKit.

Examples live in `src/examples`. The sample checker compiles each authored JavaScript/TypeScript fence independently, using separate JSX settings for React and Solid. TypeDoc generates each package's public declaration entry points and excludes unchecked example tags. Keep `typedoc-plugin-markdown` aligned with other documentation workspaces; a unit test checks its resolved module identity. The docs workspace pins TypeScript 6 for TypeDoc; published packages and sample checking use the repository's TypeScript 7 compiler.

`starlight-links-validator` validates reference links and anchors. A rendered-HTML check validates Astro component links too. Source and contribution links point to Fregat, the source of truth. Hosting and the public domain belong to the hosting workflow.
