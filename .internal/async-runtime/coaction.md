## What Coaction actually manages

Coaction is a state runtime with optional transport. Its shared mode has one write authority and client mirrors. The authority can run on a page, dedicated Worker, SharedWorker, or injected transport. “Main” names the authoritative side, not necessarily the browser main thread. Clients read/subscribe locally and invoke remote methods; direct client `setState`/`apply` is prohibited. The isolated default core entry avoids the shared transport dependency graph.

Primary evidence: [threading model](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/docs/architecture/threading-model.md), [create modes](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/packages/core/src/create.ts#L91), [isolated local creation](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/packages/core/src/createLocal.ts).

This does not supply a CPU admission policy, priority scheduler, worker pool, document affinity policy, or process supervisor. The application supplies Worker instances. Store destruction disposes subscriptions/transports; the core paths inspected contain no Worker creation/termination or native worker-error supervisor. The behavior of an underlying transport on worker death requires separate qualification.

## Sequencing, recovery, and settlement facts

1. Each authority lifetime gets an epoch; transport sequence starts at zero. A nonempty emitted patch update increments sequence. Sequence is a projection transport counter, not a domain document revision and not an operation identifier. Full sync returns one atomic `{epoch, sequence, state}` tuple. [Authority initialization](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/packages/core/src/handleMainTransport.ts#L80), [emission](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/packages/core/src/asyncClientStore.ts#L280).
2. Mirrors apply only the next sequence for the current epoch, ignore older/duplicate updates, and request full sync on a gap or epoch change. Full sync rejects a sequence below its requested minimum and ignores an older same-epoch snapshot. Connection generations prevent callbacks from an earlier connection installing data after a reconnect. Applying state uses rollback of epoch/sequence on failure. [Client sync](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/packages/core/src/asyncClientStore.ts#L140).
3. A remote action response includes authority epoch and resulting sequence. The client waits for its mirror to reach that sequence before resolving the action, including when the response describes failure. If patches do not catch up, `executeSyncTimeoutMs` triggers full sync. The default is 1500 ms. This timer starts after the action response: it is not an execution deadline or computation cancellation. [Client actions](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/packages/core/src/getRawStateClientAction.ts#L85), [default](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/packages/core/src/getRawState.ts#L18).
4. A response from the previous authority after the mirror moved to another epoch rejects with `ActionAuthorityChangedError`, `outcome: 'unknown'`. That preserves the possibility that a side effect already happened. An ordinary same-epoch action failure may likewise follow earlier committed writes; failure does not promise action rollback. No automatic idempotent replay contract exists. [Error and epoch comparison](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/packages/core/src/getRawStateClientAction.ts#L13).
5. Client destruction races pending transport promises against a destruction signal and rejects waiting mirror catch-up. It invalidates connection generation and removes listeners. Authority destruction checks before execution and after awaited execution, but supplies no AbortSignal to the action. External work already started by an action can continue. Treat “caller settled” and “execution stopped” as separate facts. [Client teardown](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/packages/core/src/asyncClientStore.ts#L111), [authority invocation](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/packages/core/src/handleMainTransport.ts#L166).
6. Execute wire messages carry action path and JSON arguments; expected authority epoch/generation and application idempotency key are not explicit fields in this protocol. Request correlation belongs to the underlying transport. The server validates discovered method paths, optional allowlists and authorization. Generation guards needed by a pinned actor command must therefore be an additional application contract. [Wire shapes](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/packages/core/src/transportProtocol.ts#L14).
7. No actor mailbox serialization appears in `handleMainTransport`: its async handler awaits the method directly. Native actions can interleave across awaits. Mutable-instance adapters document that overlapping async actions can publish coherent commits whose boundaries differ from action boundaries. A package promising ordered stateful commands must define scheduling separately. [Invocation](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/packages/core/src/handleMainTransport.ts#L109), [adapter async contract](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/docs/architecture/adapter-contract.md#async-actions-on-a-mutable-instance).

## Data, updates, caches, and backpressure

Shared state, arguments, non-void results, patch values, and full snapshots serialize as JSON strings. Validation requires a JSON tree and rejects typed arrays, ArrayBuffer, MessagePort, OffscreenCanvas, custom objects, undefined, nonfinite numbers, negative zero, cycles, and repeated references. Methods/getters are behavior outside transported state. These restrictions are stricter than browser structured clone. [Shared validation and serialization](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/packages/core/src/sharedState.ts#L96).

That boundary is reasonable for small actor metadata. It cannot carry our packed syntax buffers, terminal byte stream, rendering capabilities, or live piece-table/snapshot objects. Encoding typed arrays as number arrays would change bandwidth and ownership semantics; no performance claim supports doing so.

The update emitter sends each nonempty patch set with `respond: false`. It advances sequence before emission and reports failures; future gaps can recover through a full snapshot. There is no consumer-applied credit/ack protocol, bounded outgoing mirror queue, or slow-subscriber admission policy in these core paths. Full sync requests serialize behind `syncTail`, but there is no general latest-only update coalescer. These are source observations about the core; injected transports may supply additional behavior.

Do not confuse Coaction's local derived-value cache with our parser/tokenizer caches or retained document analysis. Actor caches should remain private to their owning worker; a mirror may expose counts, provenance, configuration and limits. A cache hit still needs the same actor generation and domain revision. A projection sequence is insufficient proof that a worker has synchronized a particular document.

## Zustand and React Compiler fit

`@coaction/zustand` is a whole-store bridge. It maintains subscriptions in both runtimes, routes Coaction changes into Zustand, preserves callable actions, and restores/rejects direct client writes. Its shared method contract is supported upstream; nesting the adapter as a Coaction slice is unsupported. Adopting it would add state ownership and write restrictions to an existing store, not merely provide an RPC transport. [Zustand bridge](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/packages/coaction-zustand/src/index.ts#L27), [support matrix](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/docs/architecture/support-matrix.md).

Upstream explicitly tests React Compiler behavior. Its fixture compiles an `observer` component and tracked-selector component, checks that optimization occurred, mounts under React 19, and checks sibling-path isolation and tracked-path changes. That is positive source evidence, not proof that arbitrary Fregat usage works. The React runtime itself uses render tracking, effect commit, external-store subscriptions and `React.memo` for `observer`. [Compiler fixture](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/scripts/check-react-compiler.mjs), [runtime](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/packages/coaction-react/src/runtime.ts#L619).

The README separately cautions about object identity used as an opaque hook dependency while deeper paths are tracked. Dynamic selector branches, suspended/abandoned render cleanup, retained mirrors and our compiler configuration remain integration questions. [React contract](https://github.com/coactionjs/coaction/blob/22cf104e4353932b747d40022d1c8570e13d3137/packages/coaction-react/README.md#compatibility).

Preferred package design: a framework-independent actor/mirror core with an optional adapter publishing immutable snapshots into caller-owned vanilla Zustand stores. Fregat continues to select those with `useStore`. Do not require Coaction stores, `observer`, or a second reactive graph to use scheduling/RPC/lifecycle primitives. This is an architectural preference, not evidence of a Coaction compiler defect.

## Fit with our accepted ownership decisions

Plan 099 preserves the existing buffer as sole content authority on the main thread, with document-owned publication and synchronization policy. Contributions retain typed APIs, independent worker state and execution policies. Publication does not wait for workers. Its chosen design centralizes the synchronization cursor/acknowledgment contract; a uniform message wrapper alone was rejected. Units 2–7 remain gated.

Current source has revision-bearing captured frames and one publication function: `editor/packages/editor/src/documentSession.ts:146` and `:1729`. Retained `documentAnalysis.ts:79` owns per-session queued revision/generation and rejects stale publication; Platform `workspace-document-service.ts:81` retains the buffer and analysis. These objects are not JSON store payloads. Keep these domain owners and derive actor commands from their exact captured revision.

E057's SAB text deletion is accepted and completed. Use strings/chunks plus incremental edit batches for document mirrors, packed transferable result buffers, and retain the independent atomic cancellation mechanism where available. A worker package must not revive shared text storage or demand cross-origin isolation. This is a scoped text-transport decision, not a prohibition on every future shared-memory use.

Plan 287 intentionally makes the terminal execution worker authoritative. Its host keeps a last-submitted-frame summary for synchronous UI needs; native/WASM state stays with execution. It specifies actor identity/generation, processed sequences, native revision, committed layout, ordered semantic events before command settlement, direct transferable output ports and explicit cross-port barriers. DOM/IME/extensions stay host-owned. This is a natural actor-plus-mirror application, but a generic JSON state mirror does not implement its binary stream, canvas transfer or displayed-frame identity.

The common package should allow each domain to place authority deliberately. Documents use main-owned truth with derived worker mirrors; terminals use worker-owned truth with a host presentation mirror. Moving document authority merely to match a store library would violate the accepted current scope. A future relocation needs its own synchronous-input/history/WorkspaceEdit design and approval.

## Concrete choices for our package

| Idea                                        | Decision and reason                                                                                                                                                                                                                    |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| One authority plus read-only mirrors        | Borrow for actor/control metadata and domain-specific summaries. Authority placement remains explicit per actor.                                                                                                                       |
| Epoch + sequence + atomic full snapshot     | Borrow recovery semantics. Validate epoch and base sequence before installing a patch; preserve the previous complete snapshot on failure.                                                                                             |
| Connection generation                       | Borrow stale-callback rejection. Keep endpoint generation separate from document incarnation, source revision, configuration and audience identity.                                                                                    |
| Action resolution after client catches up   | Borrow as an optional projection barrier. Define execution-complete, mirror-applied, submitted-frame and presented-frame separately. An RPC result should state which barrier it satisfies.                                            |
| Unknown outcome after authority replacement | Borrow and broaden to loss after dispatch. Distinguish definitely unstarted, completed, failed, cancelled and unknown; never infer rollback from a rejected promise. Retry mutating work only with declared idempotency/deduplication. |
| Entire Coaction store runtime               | Keep as an optional integration candidate, not a foundation dependency. It changes reactive state ownership and imposes JSON data semantics beyond worker management.                                                                  |
| Document authority relocation               | Exclude from this package planning outcome. Preserve Plan 099's accepted buffer/contribution ownership.                                                                                                                                |
| Automatic observer-based React integration  | Optional at most. Existing Zustand selectors are the default adapter contract; upstream compiler fixture is a useful qualification pattern.                                                                                            |
| SharedWorker/cross-window topology          | Optional endpoint adapter. Dedicated worker/local adapters must work without it; distinguish one shared authority from independent local fallback.                                                                                     |

Add what Coaction does not supply: bounded work admission, explicit stateful actor affinity, typed command scheduling, generation-scoped request settlement on crash/disposal, and cancellation acknowledgments that state whether computation stopped. A read-only command and an ordered mutation can have different concurrency policies. Avoid one serial queue across every actor.

For mirrors, choose two delivery contracts explicitly. Lossless event/operation streams need bounded admission and credits or acknowledgments; terminal bytes cannot disappear. Replaceable projections can collapse pending work to one latest complete snapshot or a composed patch with explicit base/target sequence. Dropping a patch from a delta chain requires recomposition or full sync. Recovery requests should coalesce and have bounded retries. Preserve actor/domain revision inside any replacement snapshot.

Revision acknowledgment belongs to the document contribution attachment, after the worker successfully applies source. Restart clears that attachment's acknowledged point and caches; a fresh generation receives a complete valid source before dependent work. Exact source revision is distinct from emitted mirror sequence. Scope cache reuse by document incarnation, revision/configuration and worker generation; release by domain leases and explicit limits, without transporting cache internals.

Alternative A: tiny optional projection protocol with caller-owned Zustand publication. This best fits our existing document and terminal contracts. Alternative B: Coaction for a small standalone metadata authority with native shared actions, leaving bulk streams outside it. Alternative C: no mirror package initially, only typed actors and acknowledged domain summaries. C has the smallest package boundary if reusable projection demand has not been demonstrated. All three preserve existing domain ownership.

Package placement and dependencies must satisfy [Plan 207's exact-mirror installation gate](../../plans/207-one-repo-with-mirrors.md). Keep source canonical in Fregat. Before Editor or ghostty takes a cross-family worker-runtime dependency, the exact consumer mirror must install and build without sibling workspaces; publishing-time rewriting of `workspace:*` does not establish this. Choose a dependency arrangement valid in root and standalone installs and publish any required runtime version before mirroring a consumer commit that needs it. Initial publication/authentication/trusted-publisher work remains a separate delivery gate. A local package experiment must not silently create a consumer whose mirror depends on unpublished root-only code.

## Bounded future experiments and correctness gates

These are future planning gates, not runs authorized or performed in this lane.

1. Protocol proof with one local adapter and one real Worker adapter: 100 numbered updates; duplicates, one omitted patch, epoch replacement and a delayed old full snapshot. Both adapters must converge to the same exact snapshot; invalid input leaves prior snapshot intact; stale-generation results never publish; every admitted request settles once within its declared bound.
2. Action outcome matrix: dispatch, commit, response, mirror application and dispose/crash at each boundary. A dispatched side effect with a lost response must report unknown unless the authority provides a trustworthy receipt. Cancellation must distinguish waiter cancellation from acknowledged stop. No mutating automatic replay without deduplication proof.
3. One captured document revision feeding two independent contribution adapters: edit bursts, missed history, close/reopen, logical-only changes and worker restart. Preserve synchronous buffer publication, one authority, independent consumer progress and revision-tagged cache hits. Keep string/chunk transport and packed buffers; no SAB text branch.
4. Terminal adapter proof: a small numbered output stream with resize/replay/disposal on the independent control port. Verify barriers, events-before-settlement, copied caller-owned buffers, transferred producer buffers and exact summary provenance. Suspend page rAF; execution/disposal settlement must still complete. No latency claim until presentation identity is qualified.
5. Slow-mirror boundedness: a fixed 10,000-update metadata burst with one paused consumer. Record queue length/bytes and snapshot recovery count; require the declared finite cap and exact final state. Separately prove lossless terminal output admission. Choose caps from domain demand, then measure; no invented throughput target here.
6. Optional React/Zustand adapter: reuse the upstream compiled-fixture pattern with our compiler configuration, explicit selectors, dynamic branches, object-valued selections, suspend/unmount/remount and mirror reconnect. Check current output and subscription cleanup. Benchmark only after correctness, using matched bounded workloads and CPU/memory/message accounting.
7. Optional two-client SharedWorker exercise: one authority, separate per-client generations, disconnect one client without destroying the actor, reconnect with atomic snapshot, then shut down the owning scope. Unsupported capability must expose an explicit topology choice; independent local fallback must not pretend to share state.
8. Standalone qualification: from exact package-family mirror trees, install/build with no root siblings and validate public package manifests/tarballs. Confirm required cross-family versions are published before consumer mirror delivery. This is a shipping prerequisite independent of local workspace success.

## Lane result

PASS: Current Coaction source/docs pinned; authority, sync, settlement, JSON, adapters, compiler qualification and our document/terminal ownership compared. Concrete borrow/adoption alternatives and bounded future gates provided.

ISSUES: Coaction is not our scheduler or supervisor; shared JSON excludes required binary/capability traffic; projection sequence is not domain revision; destruction is not execution-stop acknowledgment; full-store adoption would expand state ownership; backpressure and mutating idempotency need explicit contracts. These are design-fit observations, not filed defects.

BLOCKED: None for planning. Integration correctness, native worker-death behavior of `data-transport`, published-artifact parity and performance remain untested and require later experiments.
