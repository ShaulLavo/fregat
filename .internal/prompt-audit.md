# Model-facing prompts and recovery wording

Audited 2026-09-27 across the web app, TUI, server, shared packages and scripts. The macOS app contains editor code, with no model-prompt producer found. Six upstreams were inspected at the commits in the links below: Codex, OpenCode, T3 Code, Cline, Aider and Goose.

The audit follows text to provider inputs, generated-text requests, composer drafts and tool responses. It distinguishes authored instructions from user content, context serialization, provider-owned behavior and labels. A search for files named “prompt” misses post-edit diagnostic hooks and attachment serialization.

Run `python3 scripts/prompts/discover.py` from any directory to repeat the three searches: instruction names, transport calls and imperative text. The output is a candidate list for manual tracing. It includes false positives and cannot prove that arbitrary dynamically assembled instructions are absent. Tests, generated protocols and demo content are excluded from discovery; production call sites and their tests were inspected separately.

## Recovery behavior and labels

| Action    | Existing behavior                                                                                                          | Comparison                                                                                                                                                                                                                                  | Decision                                                                                                                         |
| --------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Carry on  | Appends exactly `Continue` as a new user turn in the same provider conversation.                                           | [Cline recovery buttons][cline-buttons] distinguish resuming a task from retrying an API request. [OpenCode compaction][opencode-compaction] has a longer continuation instruction for the different job of recovering after summarization. | Label **Continue**. Retain the exact one-word payload already fixed before this audit.                                           |
| Try again | Resends the stopped turn's user message and attachments into the same conversation. The partial answer remains in history. | Cline's **Retry** retries an API request. [OpenCode retry status][opencode-retry] describes an automatic request retry. Neither establishes a precedent for calling our append-another-message action a restart.                            | Label **Resend message**, a local behavior-based choice. Retain the tooltip explaining that the stopped answer stays in context. |
| Restart   | No such control exists in this stopped-turn component.                                                                     | Session reset, request retry and app-server restart are separate operations.                                                                                                                                                                | Do not imply any conversation is erased or rewound.                                                                              |

Source: [payload construction](../apps/web/src/features/chat/utils/turn-retry.ts), [buttons](../apps/web/src/features/chat/components/turn-retry-actions.tsx). Resending can repeat work already attempted by the agent; this audit changes its label, not its semantics. Replacing it with a true request retry would require a provider operation with a different history contract.

## Authored instructions

Each row covers the full producer, including its variants.

| Producer                                                                                                                                                        | Comparison and decision                                                                                                                                                                                                                                                                                                                                                                                  |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Codex Plan and Default mode overrides, formerly `codex-instructions.ts`                                                                                         | **Remove both custom blocks.** The [pinned app-server][codex-normalize] fills a null `developer_instructions` from its own mode presets. [Native Plan mode][codex-plan] also specifies the proposed-plan format our copy omitted. Send the selected mode on every turn and derive its type from the generated protocol.                                                                                  |
| Codex runtime identity suffix, formerly `<runtime_info>`                                                                                                        | **Remove with the override.** Model and effort remain wire fields. This also removes our request that the model describe itself as running in Platform; it is an intentional behavior change. [Codex context selection][codex-context] can prefer catalog instructions over the supplied mode override, so the suffix was not a dependable identity channel. Do not invent a replacement prompt channel. |
| [Claude system prompt](../apps/server/src/provider/adapters/utils/claude-query-options.ts)                                                                      | **Keep provider ownership.** Already selects the `claude_code` SDK preset, as [T3's adapter][t3-claude] does.                                                                                                                                                                                                                                                                                            |
| [Claude reasoning prefix](../apps/server/src/provider/adapters/utils/claude-reasoning.ts)                                                                       | **Keep.** The selected `ultrathink` option deliberately injects `Ultrathink:`; [T3's adapter test][t3-claude-tests] checks that exact input. This is a model-option contract, not decorative prose.                                                                                                                                                                                                      |
| [Plan implementation](../packages/client-core/src/chat/proposed-plan.ts)                                                                                        | **Keep for now.** The uppercase header and appended plan match [T3's plan builder][t3-plan] exactly. [Codex][codex-implement] uses “Implement the plan.” in the existing conversation and a longer instruction when clearing context. Platform also implements plans in a new session; deleting the plan body would break that case. Uppercase is a sourced choice, not evidence of a quality advantage. |
| [Artifact-template drafts](../apps/web/src/features/chat/utils/artifact-templates.ts)                                                                           | **Keep all ten variants.** Document, presentation, spreadsheet, site, Google Docs/Slides/Sheets, image, email and Slack match [T3's templates][t3-templates]. These insert editable drafts with a skill mention and an unfinished subject; they are not automatically sent.                                                                                                                              |
| [Initial session title](../apps/server/src/orchestration/title-prompt.ts)                                                                                       | **Keep.** Closely follows [T3's title generator][t3-titles]: durable task subject, length, JSON fields and refinement state. [OpenCode][opencode-title] and [Goose][goose-title] also use substantive title instructions. Their differing word limits are product choices.                                                                                                                               |
| [Regenerated title](../apps/server/src/orchestration/title-prompt.ts)                                                                                           | **Keep.** T3 separately handles later conversation evidence without making the latest intermediate step the title. Platform's fetched-link context is a local adaptation: retain its source/data boundary. No model-quality comparison was run.                                                                                                                                                          |
| [Commit subject](../apps/server/src/git/commit-message-generator.ts)                                                                                            | **Keep.** [Aider][aider-prompts] and [T3][t3-titles] specify concise imperative commit output and a 72-character subject. Platform asks for only a subject, treats the diff as data and disables execution. Aider's conventional-commit prefix is not a Platform requirement.                                                                                                                            |
| [Patch and checkout review](../apps/server/src/review/utils/prompt.ts)                                                                                          | **Add the missing introduced-bug constraint.** [Codex's rubric][codex-review] calls for discrete, actionable bugs introduced by the change and demonstrable affected code. Keep our schema instructions and different path rules: an isolated patch review cannot resolve checkout absolute paths. Branch, commit, uncommitted and turn targets all use this shared rubric.                              |
| [App error → Fix with AI](../apps/web/src/lib/agent-error-report.ts)                                                                                            | **Shorten to `Fix this error:`.** [Cline's fix command][cline-fix] uses a direct fix request plus evidence. Preserve the error code, operation, timestamp, log command and client identity. The application-specific opening adds no task information.                                                                                                                                                   |
| [Diagnostic → Fix with AI](../apps/web/src/lib/diagnostic-ai/utils/prompt.ts)                                                                                   | **Shorten to `Fix this …` plus location.** Cline supplies code and diagnostics. Keep our exact line/column, source/code, quoted message, bounded numbered excerpt and unsaved-buffer warning. Remove the speculative sentence about whether the diagnostic suggests a good workaround. Retain the quoted-context boundary. Hover, peek and Problems share this builder.                                  |
| [Git failure → Fix with AI](../apps/web/src/features/git/utils/failure-prompt.ts)                                                                               | **Use one direct fix request.** Cline's fix pattern plus [Aider's command/output context][aider-prompts] cover this use. Preserve the operation, repository, error and bounded ANSI-stripped output. Remove the second request to find and fix the cause.                                                                                                                                                |
| [Post-edit diagnostic feedback](../apps/server/src/provider/utils/agent-diagnostics-feedback.ts)                                                                | **Keep.** The [Claude hook](../apps/server/src/provider/adapters/utils/claude-diagnostics-hooks.ts) supplies newly introduced errors as `additionalContext`. [OpenCode's edit tool][opencode-edit] likewise returns LSP errors after edits. Platform's baseline subtraction and limits serve a concrete purpose.                                                                                         |
| [Question fallback and cancellation replies](../apps/server/src/provider/adapters/claude.ts)                                                                    | **Keep.** Empty-question fallback tells the model what failed and how to ask; cancellation and aborted approval report real outcomes. [OpenCode questions][opencode-question] also turn question outcomes into model-visible text. Platform's exact sentences are local, not upstream quotations.                                                                                                        |
| Approval outcomes and user-input answers in [Codex](../apps/server/src/provider/adapters/codex.ts) and [Claude](../apps/server/src/provider/adapters/claude.ts) | **Keep protocol values and user answers.** [Cline tool-denial responses][cline-responses] likewise report rejection. These are outcomes, not opportunities to add persuasion or a new continuation request.                                                                                                                                                                                              |

Provider-specific image encoding is transport, not wording.                                                                                                           |

The strings are authored by the model and user, not a hidden Platform task.                                                                                                           |
| [Web composed messages](../packages/client-core/src/chat/commands.ts), [TUI expansion](../apps/tui/src/agent-stage/utils/prompt.ts), draft stash, follow-ups, edited resubmissions and new-session commands | **Keep user text and context.** Traced through orchestration to `sendTurn`; no extra generic continuation paragraph found. Plan implementation and recovery are listed separately above.                                                                                                          |
| Claude cron/wakeup forwarding, Codex goal/compact commands and provider capability probes                                                                                                                   | **Keep provider ownership.** Claude forwards `cron.prompt`; goals and compaction use native operations. | SSH authentication prompts, confirmation dialogs, local summaries, logs, search previews and demo replies                                                                                                   | **Excluded from model prompt count.** The names can match discovery patterns, but these routes do not ask a production model to perform a task.                                                                                                                                                   |

## Verification limits

The audit compares source behavior and wording. It does not measure answer quality or claim that all six projects implement every Platform action. There is no universal upstream continuation sentence. Recovery labels are only comparable after tracing their operation.

Codex mode verification checks outbound default → plan → default requests and that the same thread survives. The fallback is established by the pinned app-server source, not by a paid live-model run. The shorter fix prompts retain their input evidence; tests check payloads, not model quality.
