> **Measured 2026-08-12 against `b23ee6a`.** The previous document
> (`docs/t3code-chat-parity-gap-analysis.md`) measured the **chat** dimension and declared N0–N4 complete. This sweep is
> wider: providers, git, worktrees, terminal, desktop shell, settings, distribution. Every row below was traced end to
> end — a capability whose only callers are its own tests is recorded as **absent**, not present. Our files are
> kebab-case; reference paths are camelCase under `/Users/shaul/Desktop/D/refrences/t3code`.
>
> Effort scale: **S** ≤ 1 day · **M** 2–4 days · **L** 1–2 weeks · **XL** > 2 weeks.

> **Client persistence is measured separately** in `docs/t3code-persistence-alignment.md`

## 1. Bottom line

**We are at roughly 65% of the reference's product, and roughly 75% of the parity we intend to build.** The previous
document's ~80% was honest _for the chat dimension it measured_, and that dimension survives this sweep largely intact.
The number drops because the denominator grew: outside chat, three whole subsystems are complete on the server and
reachable by nobody.

| Dimension                                              |                    Parity | Note                                                                                          |
| ------------------------------------------------------ | ------------------------: | --------------------------------------------------------------------------------------------- |
| Chat orchestration, timeline, approvals, checkpoints   |                      ~85% | Confirmed. Not re-litigated here.                                                             |
| Provider platform (instances, config, models, drivers) |                      ~40% | Two hardcoded instances; `reconcile()` never sees settings; two drivers; no text generation.  |
| Git workflow                                           |                      ~45% | Commit/push/pull/PR-create exist. No branch UI, no guards, no generated text, PR unreachable. |
| Worktrees / session isolation                          |                      ~15% | Full server service, **zero non-test callers**.                                               |
| Terminal                                               | ~55% of their feature set | One instance, memory-only history, no restart — but see below.                                |

| Desktop shell                                          |                      ~15% | A dev launcher, not an app.                                                                   |
| Remote / distribution                                  |                       ~5% | Almost entirely by choice — see §5.                                                           |

### Where we exceed the reference

This is not a rounding note. The reference is a chat client with a terminal drawer. We are a workbench that also has
chat, and four dimensions of ours have **no counterpart at all** on the other side:

- **A real code editor.** `packages/editor-{core,react,tree-sitter,minimap,find,gutters,scope-lines,diff,lsp,panes,typescript-lsp}` (11 workspace packages), consumed at `apps/web/package.json:37-47`. The reference's _only_ editor is `apps/web/src/components/ComposerPromptEditor.tsx`, a Lexical prompt box — `ls apps/web/src/components | grep -i editor` there returns that one file.
- **Language servers.** `apps/server/src/lsp/{registry,installers,proxy-session,stdio-rpc,typescript}` plus install manifests. The reference has none: `grep -rniIl "language-server|vscode-jsonrpc|textDocument/" apps packages` over the whole reference returns **zero files**.
- **A multi-pane workbench.** `apps/web/src/features/workbench/`, `packages/tree` — resizable panels, sidebar tooling, persisted layout. (The tiling surface manager — `InteractionSurface`, drag-to-split — was removed in `21d30b57`, 2026-06-18.) The reference has no split panes at all: `grep -rlI "react-resizable-panels|ResizablePanel|tiling" apps/web/src` → zero.
- **Workspace search (79 files) and an in-app structured log viewer (29 files).** `apps/web/src/features/search/`, `apps/web/src/features/logs/`. The reference ships neither; its diagnostics story is a settings row that reveals the log directory in Finder (`apps/web/src/components/settings/SettingsPanels.tsx:1346-1379`). Ours is a filterable, live-tailing JSONL browser reachable from two surfaces (`apps/web/src/features/workbench/components/sidebar-panel.tsx:132`, `apps/web/src/features/chat-mode/components/tool-pane.tsx:54-59`).
- **Terminal rendering.** `ghostty-web` (`apps/web/package.json:61`) against their `@xterm/xterm` (`apps/web/package.json:33-34`). We render better; they manage terminals better (§ M-G).

The honest summary: **we have built the harder half of a product they have not attempted, and left unwired the easier
half they finished.** Every high-severity gap below is a wiring gap, not a build gap — except ACP.

### The failure mode, again

The previous document named it: _"a feature complete on both ends with nothing joining them, passing every test it
has."_ This sweep found it in **six new places**: the worktree service, provider instance reconciliation, model
preferences, `thread-detail-sync-store`, `WorkingRow`'s plan slot, and the `Project Scripts` palette group. It is the
single most reliable predictor of a false "closed" in this repo.

## 3. Milestones

Foundation order still holds: **contracts → persistence → orchestration → transport → client store → UI.** A–B–C are
strictly ordered by dependency; F, G, H are independent of everything and of each other.

### M-A — Guardrails (no new surface until these hold)

`no-continuous-integration` · `attachment-bytes-uncapped` · `turn-input-uncapped` · `source-plan-reference-unvalidated` ·
`revert-orphans-attachment-blobs` · `dead-session-token-auth` · `login-shell-path-hydration` · `no-request-correlation` ·
`no-connection-status-surface`

Everything after this milestone adds reachable surface; this one makes sure a regression is caught, a paste cannot
exhaust the disk, a stale client cannot corrupt another thread's projection, and a broken socket says so. Two shapes to
copy from ourselves: measure the decoded byte length and persist _that_ (`Normalizer.ts:81-86`), and validate the plan
reference the same way `command-invariants.ts` validates everything else. `dead-session-token-auth` is a delete-or-fix
decision, not a build — per CLAUDE.md's greenfield rule, an auth mode nothing can satisfy should not survive the pass.

**Exit criterion — done when** a user can push a branch and watch the whole suite (including the two `*.browser.tsx`
tests that today run nowhere) pass or fail on it before merging; can paste a 200 MB image and get a clean rejection
instead of a dead server; and, when their laptop wakes, sees "Reconnecting — attempt 3" with a Reconnect button instead
of a conversation that quietly stopped updating.

### M-B — Make the settings document mean something

`provider-instance-config-never-applied` · `settings-providers-section-inert` · `model-preferences-inert` ·
`no-custom-models` · `no-provider-status-push` · `provider-env-vars-cleartext` · `no-cli-version-gating` ·
`no-general-preferences` · `assistant-streaming-not-configurable` · `editor-commands-not-rebindable` ·
`no-version-string` · `diff-word-wrap`

Order inside the milestone: **the registry↔settings link first** (`app.ts:62-75` currently builds both with nothing
between them), then the editor UI, then everything that reads the document. Building the UI first produces rows the
server ignores — the exact failure this codebase keeps producing. `provider-env-vars-cleartext` is a hard prerequisite
of the env editor, not a follow-up: do not ship a field that writes a token to a world-readable JSON the settings route
returns verbatim. `editor-commands-not-rebindable` is a wiring fix at
`app-runtime-content.tsx:18-22` — resolve overrides _before_ `editorKeymapLayersFromPlatform`, then delete the filter at
`keybinding-section.tsx:16-18`.

**Exit criterion — done when** a user can add a second Codex account on its own `CODEX_HOME`, disable it, type in a
model slug the probe never enumerated and select it in the composer, hide a model they never use so it leaves the
picker, rebind a find-in-file shortcut, and set the clock format — each surviving a restart, and the provider list
refreshing itself after `codex login` in a terminal without a reload.

### M-C — Session isolation: worktrees, end to end

`turn-start-worktree-bootstrap` · `worktree-per-session` · `thread-branch-never-set` · `terminal-worktree-scoping` ·
`project-scripts-unreachable` · `project-rename-unreachable`

The server half is done and has zero callers (`git/worktrees.ts`, routed at `git/routes.ts:51-59`). What is missing is
the command (`threadTurnBootstrapSchema` needs `prepareWorktree` + `runSetupScript`), the decider branch, the
`thread.meta.update` that stamps branch + worktreePath, and the composer's env-mode selector. `thread-branch-never-set`
is an S-sized fix with outsized leverage: it is what mounts `BranchActions` at all, which is what makes M-D's PR work
visible. Project scripts belong here because the setup script _is_ a project script with `runOnWorktreeCreate` set —
building the script editor twice would be waste; `project-rename-unreachable` rides the same project-meta dialog.

**Exit criterion — done when** a user can start a session on a new branch in its own worktree, watch the project's
setup script run in a terminal as part of that bootstrap, see the branch name in the session header, and have the
terminal beside that session already `cd`'d into the worktree so `git status` reports the agent's work and not the main
checkout's.

### M-D — The git workflow the branch unlocks

`branch-switching-ui` · `git-init` · `default-branch-guard` · `stacked-git-actions` · `pr-creation-has-no-review-step` ·
`disabled-action-reasons` · `status-missing-remote-context` · `long-action-progress-and-followups` ·
`pull-not-fast-forward-only` · `per-file-diff-stats` · `turn-diff-navigation`

`status-missing-remote-context` comes first inside the milestone — `hasOriginRemote` / `isDefaultBranch` /
`hostingProvider` on the status payload is the data `default-branch-guard`, `disabled-action-reasons` and the ladder's
rung selection all read. Extend `apps/server/src/git/service.ts:497-531` to the reference's shape (`--remotes`,
`origin/HEAD`, `worktree list --porcelain`, recency sort) rather than bolting a second query beside it.

**Exit criterion — done when** a user can open a folder that is not a repo and initialize it, create and switch
branches from the app, and take a change from "Commit" to an open pull request through one state-aware button that
streams each step's output, tells them exactly why any rung is unavailable ("Add an origin remote before pushing"), and
warns before the commit lands on `main`.

### M-E — Provider text generation

`no-provider-text-generation` · `generated-commit-and-pr-text` · `thread-title-generation`

One capability, four call sites. The previous plan rejected the commit-message call site alone as convenience; that
reasoning is sound for commit messages and wrong as a reason not to build the slot, because two of the other three
(thread titles, PR bodies) were _already accepted as open work_ in the same document. Add
`textGeneration` to `ProviderInstanceHandle` (`provider/driver.ts:60-67`), then `titleSeed` finally has a consumer and

## 4. What the previous plan got wrong

Nine "closed" claims do not survive. All nine share one root: they were verified as _built_, not as _reachable_.

1. **M10 — "`git-worktree-support`, `contracts-turn-start-bootstrap-worktree` — closed."** False. `git/worktrees.ts` has
   zero callers outside `git/routes.ts` and `git/tests/worktrees.test.ts`; `threadTurnBootstrapSchema`
   (`orchestration-commands.ts:116-118`) still has only `createThread`; and every thread is stamped
   `worktreePath: rootPath` (`chat-command-builders.ts:216`), which `session-provider.tsx:93-95` notes is the project
   root and permanent. No session has ever run in a worktree.
2. **N4 exit — "a branch can be pushed and a PR opened from chat."** Half true. Push and publish are reachable from the
   Changes panel (`git/components/header.tsx:85-93` → `--set-upstream`). The PR half is gated on `session.branch`
   (`stage-header.tsx:63`), which nothing ever writes, so `BranchActions` never mounts outside its own test.
3. **M8 — "`provider-settings-reconciliation`, `provider-multi-instance` — closed."** `reconcile()`'s only non-test
   caller passes a hardcoded constant (`provider-adapter-registry.ts:406`), nothing seeds `settings.providerInstances`,
   and the sole writer (`withProviderEnabled`) maps over an array that is always empty.
4. **N1 exit — "settings opens from a real entry point."** True, and it did not deliver the stated consequence. Two of
   the three sections render permanent empty states (`provider-section.tsx:13-14`, `model-section.tsx:16-17`) and the
   third excludes every editor command by design. Mounting the panel made **zero** new preferences reachable.
5. **N3 exit — "user keybindings can be edited and actually take effect."** Workspace commands only.
   `keybinding-section.tsx:16-18` filters out every `editor.*` id, and its comment says why.
6. **M4 — "`projection-cache-no-per-thread-status-or-error` — closed."** `thread-detail-sync-store.ts` is written by
   `thread-detail-subscriptions.ts:345,420` and read by `tests/thread-detail-subscriptions.test.ts:19`. Nothing renders it.
7. **M6 — "`composer-slash-model-command` — closed."** `/model` does not exist:
   `ChatInputSlashCommand = 'default' | 'plan'` (`chat-input-logic.ts:41`).
8. **N4 — "`git-stacked-actions` — closed."** A two-rung ladder shipped (Commit / Sync Changes). There is no
   commit+push, no PR rung, no Pull-when-behind rung, and no server composite reporting per-step results — and hook
   streaming, the reference's whole point, covers commit only.
9. **N4 — "project scripts landed with both ends attached."** The _discovery_ half landed. The contract's own comment
   (`chat-model.ts:128-133`) says scripts are stored on the project, the palette renders a `Project Scripts` group
   filtered on `saved` (`script-groups.tsx:27-28`), and nothing can ever write one. That group is dead UI.

Two accurate closures with residuals worth naming, not corrections: attachment blobs _are_ reclaimed on thread deletion
but not on revert (`revert-orphans-attachment-blobs`), and the plan-implement resync _does_ work for the open thread but
not for its rail summary (`plan-implemented-rail-badge`).

## 6. Convention notes for implementers

Per `CLAUDE.md`, applied to the paths above:

- **Kebab-case, group by feature then kind, no barrels.** New server work lands in the owning feature dir
  (`apps/server/src/git/`, `provider/`, `orchestration/`). New pure client modules go in `utils/`; do not grow
  `features/chat/lib/` further.
- **One component per file, one hook per file.** The provider-instance editor and the branch picker are the two places
  this will be tempting to violate — the reference does it in single 800- and 1 250-line files.
- **No prop drilling.** The plan panel reads from a narrow provider action, not props threaded through the tool pane;
  worktree/branch state belongs to the session provider that already owns `session.worktreePath`.
- **Never-nester.** The stacked-action rung selector, the branch-list merge (local + remotes + worktrees + default) and
  the reconcile diff are all guard-clause shaped. Keep nesting ≤ 3, no nested ternaries.
- **Theme tokens only.** Diff stats `diff-added`/`diff-removed`, blocked actions `warning`, failures `destructive`,
  plan-ready `info`. Provider status pills use `success`/`warning`/`destructive`, never a palette hue.
- **`tabular-nums`** on every number that moves: `+N/−M` diff stats, ahead/behind counts, plan step counters, reconnect
  attempt counts and countdowns, terminal restart counters.
- **Errors via `createStructuredError` / `defineErrorCatalog`.** New catalogs needed for worktree bootstrap, setup-script
  failure, attachment size rejection and branch checkout — never `new Error`.
- **Wide events, not extra lines.** Enrich the one event per operation: `worktreePath`/`baseBranch`/`setupExitCode` on
  bootstrap, `providerInstanceCount`/`reconcileAdded`/`reconcileRemoved` on reconcile, `declaredBytes`/`actualBytes` on
  attachment writes, `blobsReclaimed` on revert prune.
- **Tests are Vitest against the real in-process server** (`apps/web/test/fixtures.ts`, real `treaty` client,
  `MockProviderAdapter`, a real `git init` temp repo for every worktree and branch test). Run app tests with
  `bun --bun vitest`. `--project browser` hangs locally — which is precisely why M-A's CI job is the milestone that
  makes those two files mean anything.
- **Greenfield.** When M-B changes the settings document shape, or M-C changes what `worktreePath` means for existing
  threads, delete the stale state (the SQLite file, the projection cache, `chatModeSelection` in localStorage) or say
  what to delete. No migration code.
