# TUI command bindings

The shared command catalog now contains 198 rows. Web and TUI compose host handlers around
that metadata. Terminal defaults are authored with `platforms: ['tui']`; user overrides use
`keybindings.overrides`. Commands without a mounted handler do not enter the active palette.

This record preserves Plan 079's scope audit after completion. The runtime source is
[command metadata](../packages/client-core/src/commands/catalog.ts), and the terminal adapter is
[effective bindings](../apps/tui/src/commands/utils/bindings.ts).

## Foundation decisions

- Use explicit Linux-style Control resolution on every host. Never infer `Mod` from macOS. A Kitty capability probe may enable extra distinguishable keys, but every command with a Kitty extra below remains reachable through its legacy default or palette.
- Start with Ctrl+P for files, F1 or Ctrl+K p for commands, Ctrl+K s for settings, and named focus/dismiss actions. Ctrl+K is deliberately reserved as the app chord prefix even in app text inputs. Second strokes are plain letters or navigation keys, not Ctrl+S/Ctrl+J or control punctuation.
- Commands assigned to later slices are not inert foundation palette entries. Only register an available handler. A disabled registered command should show the exact current reason, such as no viewer tab, rather than claim success.
- Never register `workspace.toggleUiMode`, `workspace.showChatMode`, or `workspace.showWorkbenchMode`. New `workspace.openWorkbench` must take the selected project/worktree address and push a screen. `workspace.revealChat` pops to root. No global current project is introduced by a picker, quick access, or keyboard handler.
- The first file list may bring `toggleSidebarVisibility`, `focusFileTree`, and `findInFileTree` into 079. The strategy otherwise assigns the full tree to 080. A shell with no actual file list should not bind them yet.
- Keep twelve focus areas. A registration identifies the screen and selected environment/project in addition to its area. Text-entry status is a focus capability. Overlay close restores the captured origin; a stale/unmounted origin falls back to the current screen.
- Ctrl+Z belongs to job control. Do not advertise Ctrl+S, Ctrl+J, Ctrl+H, Ctrl+D, Ctrl+Z, Ctrl+Enter, Ctrl+Backspace, or Ctrl+punctuation as application defaults. Legacy Ctrl+I/Tab, Ctrl+M/Enter and Ctrl+[/Escape cannot be distinguished. Raw terminal mode does not restore distinctions already lost before the parser.
- The policy calls its collision list ten defaults but lists nine spellings. The live table also adds Ctrl+comma for settings and Ctrl+] for forward navigation, so validate the actual table rather than that count. The table below removes all these ambiguous application defaults.
- Ctrl+C and Ctrl+Z are terminal lifecycle actions. Process shutdown/suspend must restore modes, cursor and alternate screen. Kitty release events must not become command invocations. Terminal-face passthrough and attach get their own ownership policy in 080; do not let global shortcuts eat forwarded PTY input.

## Per-command disposition

`79` means foundation, `80` workbench, and `81` agent view. Later phase bindings are proposals to ship when the handler ships. `external-editor` means the operation runs inside $EDITOR and has no app binding. `cell-editor-reserve` requires the deferred native editor. `none` means no default; supported commands remain palette-reachable when their handler exists. Kitty extras are added to the legacy defaults. Unless marked with `@area`, bindings are global but remain gated by command availability. Web defaults below are the actual default Linux preset, retaining authored `Mod` spelling.
