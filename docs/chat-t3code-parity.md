## Verified behavior that should be preserved

The model picker carries model/effort options through draft selection and persists the project default. Existing sessions intentionally keep their provider instance. Runtime and plan/build mode choices are carried in turn commands. Image MIME validation and compression, file-tree mentions, slash and skill menus, IME Enter protection, Shift+Enter, terminal capture, stash, failed-send draft retention, and scoped text draft storage are reachable.

The transcript supports markdown, GFM through Streamdown defaults, math, Mermaid, syntax-highlighted code, file links into the editor, external link previews and context menus, selection copying as markdown, collapsed user messages, plan copy/download/expand, changed-file trees, and checkpoint diff/revert. Checkpoint revert confirms before dispatch and refuses while busy. Session selection keys ChatView by session ID, so a local send error does not leak between sessions. Earlier history has loading and retry states, and missing sessions have a separate state. Detail synchronization and the composer connection status are wired, unlike several claims in old reports.

Child-agent activity ownership and the missing agent panel remain high priority. The earlier report's claim that inline subagent lifecycle was already complete is false for the captured chat. The runtime and root workers own this correction; this worker should not invent child IDs from the current parent turn.

## Capability differences requiring honest scope

T3code supports arbitrary file uploads and per-question attachments. Platform's attachment contract currently models images only. This is a complete product capability, not a safe one-line MIME allowlist change. File-tree mentions already carry workspace references.

T3code also has browser annotations, review-comment citations, artifact-template cards, general app/MCP elicitation forms, and a side agent inspection/control system. Browser annotations and quote-review actions depend on product areas outside this chat repair. Codex file citation rendering and child-agent visibility belong here because the current runtime already emits those outputs. MCP approval protocol support must be coordinated with the runtime worker rather than simulated as ordinary command approval.

The reference permits follow-ups during running turns; it does not justify starting independent simultaneous parent runs or displaying a queued provider response as the currently active turn. The queued-versus-active distinction is part of the steering fix, not optional polish.
