## Concrete grafts from B

1. Keep one internal transaction owning reservation, pending record and endpoint generation. A's module split must never make consumers manually coordinate reservation rollback after clone/send/start failure.
2. Add B's optional owner inventory/close report to an explicitly shared budget scope when a real composition needs aggregate diagnostics or coordinated close. Do not require it for standalone FIFO/sweep/service consumers.
3. Add finite reserved control capacity plus a progress dependency contract. Control allocation alone is insufficient; see the required fixes below.
4. Adopt typed readiness/closure facts for subscriptions. Synchronous registration is distinct from producer installation acknowledgment, and subscription close must reveal graceful/forced/unknown cleanup.
5. Retain B's declaration that residency estimates are accounting, not a hard JS/WASM/GPU/process memory ceiling. Carry precision/uncertainty into inspection and measurement receipts.

Reject compulsory actor registration, speculative independent-job pooling, universal domain ErrorData in core, JSON-only bulk transport and automatic reactive-store adoption. A's private finite channel remains provisional pending its complete correctness/cost comparison with narrow Comlink.

## Plan consistency fixes

1. Plan-number collision exists: The draft async numbering overlapped concurrent planning. The final async stack is 328–334; compile-time data is 320 and virtualization is 327. Preserve both concurrent plans and their work.
2. Normalize pilot repetitions. A says 'two balanced paired runs'; Plan 334 says two AB/BA blocks with an optional extension to four blocks; my lane report fixes four pairs. Use four pairs comprising two complete AB+BA blocks for the new transport screen, with no automatic extension. Existing Plan 282's strict two/four-pair rule and Plan 283's four balanced pairs remain authoritative. More collection after an unresolved result needs the smallest cause/decision, not a generic repeat allowance.
3. Define new metric margins only when an owning domain accepts them from an applicable baseline. For the transport screen, use descriptive timing plus existing product gates and code/lifecycle benefit; do not imply baseline-derived numbers are approved merely because a researcher selected them. Plan 334 should retain no invented universal regression percentage.
4. Stage dependencies are conceptually sound if 334 consumes contract sketches rather than completed implementations. Spell out Q0/Q1 → transport choice/core completion → scheduler/consumer units → P0. Otherwise 329's dependency on 334 and 334's reference to 329–333 can look circular to a fresh executor.
5. Plan 332's 'all in-scope owners consume' can force a shallow wrapper around TypeScript LSP despite no benefit. Permit a documented no-adoption result for dependency/native protocol owners when only an unsupported/forwarding lifecycle wrapper remains. Migration completion should prove useful reuse and preserve ownership, not count imports.
6. Ensure fairness admission testing uses a finite dispatch-opportunity bound and actual ready work. A halted independent actor is not a fairness failure of another actor; a worker blocked synchronously cannot satisfy a scheduling promise by moving priority numbers.
