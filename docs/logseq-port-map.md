# Logseq Port Map

Pinned reference: `references/logseq` — logseq/logseq `fab2774` (2026-08-18). Every path, line number, and call-site count below was read at that commit. `references/db` (TanStack DB) and `/Users/shaul/Desktop/D/sqlite-wasm` are referenced where a substrate option depends on them.

Status marks how much of Logseq's **code** survives the move, not how good the feature is: ✅ **port** — transliterate; the logic is dense, hard-won, and its value is in the exact rules. 🟡 **reimplement-from-spec** — keep the design, throw away the code; usually because the implementation is welded to DataScript, Rum-era hiccup, worker RPC, or a browser workaround we do not inherit. ❌ **skip** — we already have it, our substrate deletes the problem, or Logseq itself abandoned it. Layer is where the result lives: `contracts` = `packages/contracts`, `platform-server` = `apps/server`, `platform-web` = `apps/web`, `editor-*` = the separate `@singapore-editor/*` repo. Effort is cost **in our stack**: S = days, M = 1–2 weeks, L = 3–6 weeks, XL = multi-month. Exposure is the licensing label defined under [License](#license).

## Reading Logseq as a porter

972 Clojure/ClojureScript files, 270,095 LOC. It is not one codebase but three, with very different port economics.

- **`deps/*` — the self-contained libraries, and the prime port surface.** `deps/db` 12,044 LOC · `deps/db-sync` 7,324 · `deps/outliner` 6,140 · `deps/graph-parser` 5,695 · `deps/common` 2,075, plus `deps/publishing`. These have explicit `deps.edn` boundaries, minimal app coupling, and carry the algorithms — tree algebra, ref derivation, query compilation, order keys, sanitization. Most ✅ rows below come from here.
- **`src/main/frontend/*` — app-coupled, usually cheaper to reimplement.** `components/` 34,968 LOC · `worker/` 23,407 · `handler/` 17,520. Two premises commonly stated about this tier are **out of date at `fab2774`** and change the plan: **Rum is gone** (zero files reference it — the UI is `io.factorhouse/hsx` + `io.github.logseq/rfx`, `deps.edn:5-8`), and **the main thread has no database** — `d/q|d/pull|d/entity` appears 290× under `worker/` and 2× in all the rest of `src/main/frontend/`. The renderer subscribes to exactly three slot kinds (`db/subs.cljs:49-54`) and never queries.
- **`libs/src` — the one TypeScript directory** (the plugin SDK, 5,585 LOC). No translation cost at all, which inverts the usual calculus: see [Plugins, themes, config, keybindings, and settings](#plugins-themes-configedn-keybindings-and-settings) — copying is trivial there, and that is exactly the problem.

Two orientation facts worth carrying into every module. First, `deps/graph-parser/src/logseq/graph_parser/schema/mldoc.cljc` (217 lines) is a complete malli specification of the parser AST — the highest leverage-per-line artifact in the repo, and it describes a third party's format rather than Logseq's own logic. Second, the codebase argues with itself in useful ways: `deps/db/src/logseq/db/frontend/rules.cljc:38-57` is a 20-line comment about datalog clause-ordering pathologies, and `:block/left` and `:block/path-refs` were both **deleted** after shipping. Those deletions are findings, not gaps.

## Substrate

Every decision below depends on what replaces Clojure's runtime. Read this section before any module section; several rows are ✅ or ❌ _only because_ of a choice made here.

### S1 — What replaces DataScript + datalog as the query layer?

**Logseq uses** DataScript pervasively but _locally_: 210 files, `d/entity` 1750 call sites, `d/transact` 485, `d/datoms` 248, `d/q` 223, `d/pull` 52 — concentrated in `worker/` (290) and `deps/db` (423), `deps/outliner` (358), `deps/db-sync` (173), `deps/graph-parser` (121). Recursion is load-bearing: `parent`, `class-extends`, `has-ref` are recursive rules (`deps/db/src/logseq/db/frontend/rules.cljc:8,15,29`). Logseq pins a **fork** of DataScript (`deps.edn:10`, sha `3f141af`) and reaches below its public API — `deps/db/src/logseq/db/common/entity_plus.cljc:48` derefs a private var to add map ops to `Entity`.

| Option                                | Verdict                              | Why                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| npm `datascript` 1.8.1                | rejected                             | The only option where query code transliterates 1:1 — but grepping the 467 KB dist for `datascript.storage.*` returns **nothing**. The lazy SQLite-backed index tree that lets Logseq open a 50k-block graph is absent from the JS build, so the whole graph must sit in memory. Also upstream, not Logseq's fork, so dynamic `:db/ident` schema and the `entity_plus` patch do not exist. |
| **SQLite (bun:sqlite + sqlite-wasm)** | **chosen**                           | Already ours: `apps/server/src/db/client.ts:65-72` (bun:sqlite + Drizzle + WAL + busy_timeout), migration ledger at `apps/server/src/db/schema.ts:9`. `WITH RECURSIVE` is native — the exact thing `rules.cljc` hand-tunes and warns about. FTS5 free, replacing Logseq's second database. Memory bounded regardless of graph size.                                                        |
| TanStack DB (`references/db`)         | rejected                             | `references/db/packages/db/src/query/ir.ts:9` has no fixpoint and `db-ivm/src/operators/` has no `iterate` — so `parent`, `class-extends` and `has-ref` are **inexpressible** as live queries. Collections are in-memory, so the 50k-block problem returns.                                                                                                                                |
| Hand-rolled TS triple store           | rejected                             | Writing a datalog evaluator is the easy half; making it fast is a multi-month specialist project on the critical path of everything else.                                                                                                                                                                                                                                                  |
| Plain normalized store + selectors    | **chosen, for the render path only** | The three hot access patterns (block-by-uuid, children-of, refs-of) are Map lookups, not queries.                                                                                                                                                                                                                                                                                          |

**Recommendation.** SQLite is the query engine; a plain Map-backed slot cache serves the render path. Split the work where Logseq's own boundary already splits it: the renderer reads `[:block uuid]` / `[:children uuid]` / `[:resource key]` slots; everything behind `:resource` (backlinks, saved queries, views, search) is SQL. Compile the user-facing query DSL to SQL, not to datalog.

**What this changes.** _Rewritten, not transliterated:_ ~275 `d/q`/`d/pull` sites, `rules.cljc` (360 lines → recursive CTEs), `worker/query_dsl.cljs` (812 lines → a DSL→SQL compiler), and the query-shaped helpers in `deps/db`. _Still transliterable:_ the ~1750 `d/entity` sites are mostly attribute reads that become property access on a row DTO; `deps/outliner` is tree algebra over parent/order and survives with an entity-lookup shim. _Newly cheap:_ ancestor/descendant traversal, backlinks, full-text search. _Newly expensive:_ we own invalidation and the open-schema representation.

### S2 — Storage layout, and how to represent an open user-extensible schema

**Logseq uses** SQLite as a **blob store for DataScript's persistent index tree**, not a row store: `create table if not exists kvs (addr INTEGER primary key, content TEXT, addresses JSON)` — "for use with datascript.storage" (`deps/db/src/logseq/db/common/sqlite.cljs:10`), written through an `IStorage` reify that transit-encodes each tree node (`worker/db_core.cljs:337-356`), connected via `d/restore-conn` / `d/create-conn schema {:storage storage}`. The tail is visible in the source: a 1000 ms `d/store` debounce and manual WAL checkpointing (`db_core.cljs:623-629`), a dedicated GC module (`deps/db/src/logseq/db/sqlite/gc.cljs`), and a bare `;; TODO: GC kvs table` in `deps/db-sync/src/logseq/db_sync/storage.cljs:32`. Three SQLite files per graph — `db`, `search`, `client-ops`. The `search` one is _real rows_: an FTS5 **trigram** virtual table with triggers (`worker/search.cljs:21,48,57`). The static attribute set is tiny (~20 attributes, `schema.cljs:56`, version `"65.33"`); everything user-facing is open — properties and classes are `:db/ident` entities carrying their own `:db/valueType`/`:db/cardinality` as data (`deps/outliner/src/logseq/outliner/property.cljs:256-269`). Ordering is fractional: `:block/left` has **0 hits**, `:block/order` has 574.

**Recommendation.** Rows + an EAV property side table + FTS5 as the shape; an append-only event log with materialized projections as the spine. Hot render-path columns (uuid, parent, order, page, title, updated_at, rev) stay real columns on `blocks`; everything user-defined goes to `block_props(block_uuid, property_ident, value, value_ref)`; FTS5 with the trigram tokenizer mirrors `worker/search.cljs:57` and deletes the separate search database. Do **not** copy the `kvs` blob tree.

**What this changes.** _Deleted, not ported:_ `common/sqlite.cljs`, `sqlite/gc.cljs`, the `IStorage` reify, the whole transit-blob path. _Transliterable with a shim:_ `outliner/property.cljs` (~1000 LOC of cardinality/valueType/ref branching) against an EAV accessor. _Near-verbatim:_ the FTS5 DDL and triggers at `worker/search.cljs:21-70` are already SQL. _Free:_ `logseq/clj-fractional-indexing` → npm `fractional-indexing`. The database also becomes inspectable with `sqlite3`, which Logseq gave up.

### S3 — How do React components subscribe to graph changes?

**Logseq uses** — and this is the premise most often stated wrongly — **`React.useSyncExternalStore`**, already. Rum is gone. Graph data does not flow through `rfx` either; it flows through a purpose-built slot store: `src/main/frontend/db/subs.cljs` (521 lines) holding `{:graph-id :generation :rev :slots :resource-slot-keys :warm}` with a 5000-entry LRU (`:33-37`) and a batched loader (`subs_loader.cljs`, 88 lines), bound at `db/hooks.cljs:28,71,100` with an `identical?` fast path on the source snapshot (`:57-71`). Snapshots are status-tagged `{:status :ready|:loading|:missing|:error}` and staleness is decided by `:block/tx-id` comparison, **not** deep equality (`db/subs.cljs:26-28`). Invalidation is pushed from the worker: `worker/render_delta.cljs` (162 lines) and `worker/render_affected_keys.cljs` (582 lines).

**Recommendation.** Transliterate the slot store and hooks into a plain external store read through `useSyncExternalStore` — we already use that primitive in 11 modules and run 40 zustand stores, so no new dependency. Keep TanStack Query for server RPC and away from graph data: it is request-keyed and time-stale, while graph data is push-invalidated and tx-stale. Do not port `rfx`; `keymap/` plus zustand already covers it and a re-frame layer would be a third state idiom.

**What this changes.** This is the cheapest decision in the port. ~750 LOC (`db/subs.cljs`, `subs_loader.cljs`, `db/hooks.cljs`) transliterates near 1:1; `render_delta.cljs` and `render_affected_keys.cljs` port with their attribute sets re-derived against our schema. The one non-obvious thing to copy verbatim: **staleness by revision, never by deep comparison** — deep-comparing block maps at 50k blocks is the naive TS choice and it is wrong.

### S4 — Where does the notes graph actually run?

**Logseq uses** a web worker for everything DB-touching: 70 files / 23,407 LOC under `worker/`, behind comlink (`worker/db_worker.cljs:44-50`) with **188** `def-thread-api` endpoints generated by a macro (`common/thread_api.cljc:14`), each hop transit-encoding both directions with per-call timing instrumentation (`:45-80`). Worker purity is enforced at runtime — `check-worker-scope!` throws if React is present (`:26-28`). Multi-tab coordination is hand-rolled master election over BroadcastChannel + `navigator.locks` (`worker/shared_service.cljs:11-36`), crediting an external implementation and a wa-sqlite thread: scaffolding built to work around the browser, not a design goal.

**Recommendation.** Bun server first, with the RPC surface shaped so a worker could back it later. Run the graph as another aggregate in `apps/server/src/orchestration`-shaped plumbing — commands in, append-only event log, projections, delta pushes over the existing WS (`ws-rpc.ts:82`, `streams.ts:275`). Do **not** build a web worker in the first pass: we have zero today (no `new Worker`/`SharedWorker`/comlink anywhere in `apps/web/src` or `packages/`), and building one means adopting all of Logseq's browser workarounds voluntarily. Keep the client interface a narrow async port — `loadBlock`, `loadChildren`, `loadResource`, `applyOutlinerOps` — so a later swap is an implementation change.

**What this changes.** The 23,407 LOC under `worker/` mostly ports as server-side modules with the transport swapped. _Deleted entirely:_ `shared_service.cljs`, `db_worker.cljs` bootstrap, `platform/browser.cljs`, `db_worker_node_lock.cljs`, OPFS pool management. _Reused, not written:_ WS RPC, event log, projection reactors, migration ledger. One caution: 188 endpoints is what this grows into, so the RPC layer must be typed and generated from the start — Logseq needed a macro for exactly this reason. `apps/web/vite.config.ts:56` already sets `worker: { format: 'es' }`; keep it as an escape hatch, not a plan.

### S5 — What replaces persistent data structures, core.async, multimethods, dynamic vars, transducers?

**Logseq uses** far less of Clojure's exotic runtime than the reputation suggests, and each was counted. **core.async is effectively dead** — 6 files, ~21 `go-loop`/`<!` sites; async is `funcool/promesa` in **358 files**, i.e. JS promises with a Clojure skin. **Multimethods: 8 total.** **Dynamic vars: 14 total**, all ambient config for one call tree. **Transducers: ~9.** Immutability is the one that is genuinely everywhere (447 atom sites in `src/main/frontend` alone) — but at the point that matters it is used for _identity_, not structural sharing: `db/hooks.cljs:57-71` compares with `identical?` and `db/subs.cljs:26-28` compares `tx-id`.

**Recommendation.** Frozen POJOs with reference equality for snapshots and DTOs; Immer only inside a specific store if a measured hot path needs it. **Reject Immutable.js outright** — it is neither structured-cloneable nor JSON-serializable, so it would reintroduce the 213-site serialization layer S6 deletes (note: `immutable: 4.3.9` sits in our root `overrides` but nothing in our source imports it — a transitive pin, not adoption). promesa → `async`/`await` essentially line-for-line; core.async's 6 files → async iterators or callbacks; 8 multimethods → discriminated unions with a `Record<Kind, Handler>` table; 14 dynamic vars → explicit parameters, or `AsyncLocalStorage` server-side where threading through a deep call tree is genuinely ugly; 9 transducer sites → array methods.

**What this changes.** The 358 promesa files are the single largest category of "looks Clojure, is actually just async" and convert nearly by find-replace. Multimethods, dynamic vars and transducers total ~31 sites — an afternoon. What _does_ need design: everywhere DataScript's persistent indexes were doing structural sharing vanishes with S1 and is replaced by SQLite pages, changing the model from "cheap snapshot" to "cheap query". Newly forbidden: any DTO carrying `Map`, `Set`, `Date` or class instances across the RPC boundary — enforce it in `packages/contracts`.

### S6 — What replaces transit as the cross-boundary format?

**Logseq uses** transit at every boundary — **213** `write-transit-str`/`read-transit-str` sites across `src` and `deps`, defined at `deps/db/src/logseq/db.cljs:30`. Every worker RPC hop encodes both directions and instruments deserialize/handler/serialize timings _separately_ (`common/thread_api.cljc:45-80,60-66`), i.e. the cost was significant enough to measure per call. The same encoding is the on-disk format (`worker/db_core.cljs:332,347`). The reason is structural: ClojureScript maps, keywords, sets and `Entity` instances do not survive structured clone.

**Recommendation.** Plain JSON DTOs, with rich types banned at the contract boundary. Block and delta DTOs in `packages/contracts` carry primitives only — uuid strings, epoch-millis numbers, string enums. Revisit a binary codec only against a measured payload, per the house rule.

**What this changes.** This is the port's one free win, and a naive transliteration would preserve it by reflex. All 213 sites, the helpers, the `datascript-transit` dependency, and the timing instrumentation built to watch them are deleted. It constrains every DTO (which is the same discipline S5 already recommends, so the two reinforce each other) and it makes the on-disk database inspectable — a real debugging asset given how much this codebase leans on wide JSONL logs.

### S7 — mldoc: consume the artifact, use tree-sitter, or something else?

**Logseq uses** mldoc on the render path: `package.json:176` pins `^1.5.9`, 28 files reference it, and `components/block.cljs:1009,4824` calls `inline->edn` per block title. The wrapper is `deps/graph-parser/src/logseq/graph_parser/mldoc.cljc` (417 lines), pulling four functions off the global and passing a JSON config built at `:64-82`. Crucially the AST is **formally specified** in `schema/mldoc.cljc` (217 lines), and `getReferences` is what populates `:block/refs` (251 sites) — it is the ref-extraction engine, not just a renderer.

**Measured, not estimated:** the `mldoc` 1.5.9 tarball is a single **424,120-byte** `index.js` (js_of_ocaml 5.4.0), **ISC** licensed, zero runtime deps, exporting `parseJson, parseInlineJson, parseOPML, getReferences, export, parseAndExportMarkdown, parseAndExportOPML, astExportMarkdown, anchorLink, timestampToString, rangeToString`. Last published 2024-08-03. It lives in a **different repository** from Logseq, so consuming it carries **no AGPL exposure**.

**Recommendation.** Both, for different jobs. Consume the mldoc artifact for parse-to-AST and ref extraction behind one narrow module (`parseBlock`, `parseInline`, `extractRefs`, `astToMarkdown`), with the AST types generated from `schema/mldoc.cljc`, and run it **where the graph lives** (the server, per S4) so 424 KB and a synchronous CPU-bound parse never reach the browser bundle. Keep `@singapore-editor/markdown` + tree-sitter for the editing surface — highlighting, folding, inline replacements need incremental reparse and byte ranges, which mldoc's whole-string JSON API cannot give. Treat the mldoc wrapper as a replaceable seam: write the AST types first.

**What this changes.** The parser is not ported at all — it is consumed. `schema/mldoc.cljc` → TS types is the highest-leverage 217 lines in this area. `mldoc.cljc`'s 417 lines port with about half deleted (the EDN round-trip disappears). The AST-walking renderers — `components/block.cljs` (5,299 lines) and `deps/publish/render.cljs` (1,611) — are reimplemented against our components, never translated. Because mldoc runs server-side, block parsing becomes async from the renderer's view, which the slot store's `:loading` status (S3) already models at no cost.

## Block/outliner data model, database, and file↔DB sync

24 modules — 10 port, 11 reimplement, 3 skip (2 of which are recorded rejections, not omissions). Paths are relative to `references/logseq/`; targets are relative to the platform repo root.

**Strategy.** This domain is where the port pays off best and where the substrate decisions bite hardest. The tree algebra in `deps/outliner` is pure, dense, and survives S1 intact once you hand it an entity-lookup shim — every one of the ✅ rows is a small file where each line is an invariant somebody learned the hard way (the cycle guard in move, the live-boundary re-read in insert, the ref-text substitution in delete). Everything shaped by DataScript's transaction model — the temp-conn staging layer, the datom-archaeology that derives canonical ops after the fact, the `kvs` blob store — is deleted rather than translated, because a SQLite transaction plus an event log gives us read-your-writes, atomicity and an op log for free. Two design rejections are recorded here as first-class rows so they are made deliberately: `:block/left` and property-values-as-blocks. The order to build in is: op vocabulary → dispatcher → the four tree primitives → refs → history.

### move-blocks

**Algorithm to preserve.** Never move a block into its own descendant — intersect the target's ancestor chain with the moved set and abort with zero writes, not a partial move. Never make a page a child of a non-page block. A move rewrites the moved block's parent and order and **nothing** on any neighbour. Multi-block moves process in document order with each block targeting the _previously moved_ block, which is what preserves relative order. The descendant `:block/page` rewrite must be repaired whenever the page changes — the one place a move is O(subtree) instead of O(1). Dropping a block exactly where it already sits produces zero transactions, which is what keeps an idempotent drag from dirtying the document and pushing an undo entry.

**Transliteration.** `(d/entity db (:db/id x))` re-reads inside the loop; `reader.block(uuid)` re-reads against the open SQL transaction, which is what makes the multi-block loop see block N−1's new order. `get-block-full-children-ids` becomes one recursive CTE — where SQLite beats their rule-based descent outright. Replace the `ex-info` reason keyword caught by string-matching the message with typed errors from `apps/server/src/notes/structured-errors.ts` carrying code/why/fix. Drop the property-value branch entirely.

**Risks.** The cycle guard is only correct on an acyclic parent chain — which is the invariant the repair pass exists to restore — so a cycle introduced by a bug makes the ancestor walk non-terminating. Add a depth cap. Skipping the descendant page rewrite in a first pass silently produces blocks whose page disagrees with their ancestry, breaking every page-scoped query afterwards.

### insert-blocks

**Algorithm to preserve.** Input blocks are already in document order — assert it. Every emitted block has both parent and order; a null is a hard error, not a fallback. The right-sibling boundary is **re-read from the live store at transaction time** and any caller-supplied boundary is deliberately ignored; Logseq has a regression test for exactly this, because a stale boundary from the renderer lets a concurrent insert sort the new block after the block that appeared in between. `keepUuid` distinguishes copy (fresh uuids, plus rewriting intra-selection refs to the new uuids) from cut/drag (keep uuids so inbound links survive). `replaceEmptyTarget` lets exactly one inserted block reuse the target's id, uuid and order. `blocksWithLevel` is one O(n) pass with two id→level maps that correctly treats a block whose parent is outside the selection as a new root.

**Transliteration.** Negative temp db ids disappear — mint real uuids up front, since we control identity and DataScript's upsert dance is unnecessary. The `loop`/`recur` threading a speculative db through `d/with` (so a later block sees a page created by an earlier one) becomes a plain loop inside the open SQL transaction, where the write _is_ visible. `walk/prewalk` entity replacement is unnecessary once ops carry uuids only. `get-target-block` is a seven-branch decision table (link redirect, move-up last-descendant redirect, top/bottom, Library) that is not derivable from a paragraph — keep it as its own module.

**Risks.** The largest surface in the domain and the most entangled with the property-value design we are refusing; expect real effort deciding which `get-target-block` branches survive that removal. Pasting a 1000-block outline must use the recursive-splitting N-key generator or the last key is 1000 characters — a property test, not a review comment.

### delete-blocks and cascading cleanup

**Algorithm to preserve.** Expand retractions to the **live** subtree at commit time, never from the caller — the renderer's idea of the subtree may be minutes old, and this is the difference between "delete removed the block" and "delete orphaned three descendants". Deleting a referenced block substitutes the block's _text_ into every referring block's raw title so the referring sentence still reads correctly instead of leaving a dangling `((uuid))`; do not rewrite a referrer that is itself being deleted. The cleanup is a **fixpoint**, not a single pass, so a deleted view's own dependents also go — and it tracks seen ids or it will not terminate on mutual references. A built-in entity anywhere in the batch aborts the whole batch rather than being skipped. Deleting a page retracts only its parent/order/page; the page entity survives for the recycle flow.

**Transliteration.** The atom of pending tx-data threaded through the `INode -del` protocol becomes a pure `(reader, blocks) => TxOp[]` return value — the protocol extension on DataScript's `Entity` type is the worst shape in `outliner/core.cljs`. The `:aevt` datom scan becomes an indexed query; the `loop`/`recur` fixpoint becomes a `while` loop with a `Set<uuid>`. Note a real hazard: `re-pattern` built by interpolating a uuid is a regex-injection surface — escape it or match with `indexOf`/`split` instead of `RegExp`.

**Risks.** The ref-text substitution rewrites user content on delete, so a bug here is data loss that undo must reverse — the delete inverse must capture the referrers' pre-state titles, not just the deleted subtree. Verify that pairing explicitly. The three substitution forms (`{{embed ((uuid))}}`, `((uuid))`, `[[uuid]]`) must be applied longest-first or the embed wrapper is left behind.

### indent-outdent-blocks

**Algorithm to preserve.** Indent aborts on a non-consecutive selection. Blocks already parented to the left sibling are dropped from the front of the selection, which is what makes repeated Tab converge instead of oscillating. If the left sibling has children, indent targets its **last direct child** as a sibling; otherwise the left sibling as a child. After outdenting, the block's former right siblings are swept underneath it — without that step, outdenting the middle item of a list appears to reorder the list, and it reads as a bug forever because nobody can articulate what is wrong. The sweep runs _after_ the outdent move and reads post-move state. Auto-expanding a collapsed indent target must be in the **same** transaction or the user watches blocks vanish for a frame.

**Transliteration.** `drop-while`/`take-while` become `findIndex` + `slice` with the conditions inverted into guard clauses. `concat-tx-fn` becomes flat array concat. Logical-outdent mode is the same minus the sweep, and it is a user knob — so it is a registry entry (`notes.outliner.logicalOutdenting`, window scope: pure preference, reaches no execution), registered in the same pass that wires it.

**Risks.** Outdent from a linked-references view needs the `parentOriginal` override because the visual parent differs from the real one; if we ship linked references before that, outdent there silently moves blocks to the wrong parent. Logseq throws `::missing-parent-original` rather than guessing — keep that.

### move-blocks-up-down

**Algorithm to preserve.** One deliberate asymmetry carries the whole module: "above X" in a visual outline means _after X's last descendant_, while "below X" means _after X_. Up: `anchor = leftSibling(leftSibling(first) ?? parent) ?? parent`, `sibling? = anchor shares the selection's parent`, then the target resolver redirects to the anchor's **last descendant** when the anchor is neither parent nor grandparent. Down: `anchor = rightSibling(last) ?? rightSibling(parent)`, no redirect. Abort when the anchor is null or is the page.

**Transliteration.** Nil-punning `or` ladders become `??` chains and read almost identically. `merge` into the opts map becomes object spread. The redirect lives in the shared target resolver, not duplicated here.

**Risks.** Only meaningful once move-blocks and the target resolver are correct; landing it early against a half-built resolver produces confusing failures attributed to the wrong module.

### Post-transaction pipeline and block-ref rebuilding

**Algorithm to preserve.** Refs = property keys (minus the exclusion set) + page-or-object property values + journal pages derived from datetime property values (allowlisted to user properties plus `:scheduled`/`:deadline`) + `[[uuid]]` tokens scanned from the raw title + tags + link, deduped, minus self, minus aliases of self. The two self-reference guards — by id _and_ by alias — exist to stop recursive rendering loops, and are the kind of thing you only add after seeing the infinite render. Refs are **replaced wholesale**, never diffed. Derivation is skipped for sync-download, undo-replay, remote and import transactions, or remote data gets rewritten locally and peers diverge.

**Transliteration.** `d/with` speculative application and report splicing disappear: refs are computed and written inside the same SQL transaction. `identical?` on boxed ids becomes `===` on uuid strings. The memoised page-or-object predicate becomes a Map cache scoped to the transaction, never module-level. The per-block revision stamp (`:block/tx-id = maxTx+1`) maps onto our event sequence number and is what the slot store compares for staleness (S3).

**Risks.** The `extra-tx-data` hooks (tag templates, missing properties, created-by, reverting disallowed changes) are app-coupled and will drag in the property-block design — take `rebuildBlockRefs` and leave them. Full-replace semantics mean a derivation bug silently _drops_ backlinks rather than adding wrong ones, which is much harder to notice; test that refs survive an unrelated edit. Do not port `:block/path-refs`: it was deleted in schema 65.11 because moving a subtree rewrote every descendant — compute ancestor refs at query time from the parent chain instead.

### Deterministic uuids

**Algorithm to preserve.** The journal uuid layout digit for digit — `00000001-YYYY-MMDD-0000-000000000000` — and the type prefix distinguishing built-in from db-ident-backed entities. Determinism across processes and machines: no randomness, no locale, no timezone-dependent day derivation. Two graphs (or two devices, or an import and a fresh create) that independently produce `2026-08-22` get the same entity and merge instead of duplicating.

**Transliteration.** String formatting only; nothing Clojure-shaped. The journal day arrives as the 8-digit `YYYYMMDD` integer Logseq uses — keep that as the parameter type rather than a `Date`, per the JSON-primitive boundary rule. The hash for ident-backed uuids must use the same algorithm over the same input string, so read the `.cljs` rather than inferring. (Note the tension with the _other_ survey's read of the same file under [Page surfaces](#page-surfaces-journals-navigation-and-graph-views), which argues for deliberately diverging on the hash — decide once.)

**Risks.** Timezone. If `journalDay` is ever derived from a `Date` on the server, two clients in different zones mint different journals for the same user day. Take the day from the client as an explicit number and never compute it server-side.

### Invariant repair passes

**Algorithm to preserve.** Duplicate orders: find the smallest sibling order strictly greater than the shared value as the end bound, generate N keys between, and assign to the tied blocks **sorted by uuid**. That tie-break is the load-bearing detail — it is what makes two peers converge on the same assignment with no coordination, where sorting by `created_at` would diverge. Cycle breaking retracts the offending edge and repoints to a safe target (a block's own page for parent cycles), one edge per iteration, bounded by an iteration cap. Repairs are transacted with a fix marker so they are excluded from undo and recognisable in logs. Enforce at commit time, not repair time, that no transaction gives a page a non-page parent. The ~40 rules in `validate.cljs` are a list of every way this data model has actually broken in the field and are worth more than the code.

**Transliteration.** `group-by` on a computed `[parentId, order]` tuple becomes a Map keyed by a template string — JS object keys are not structural, and this trap recurs in `tree.cljs`. The giant `cond` ladder becomes an **array** of `{ id, detect, fix }` rules, so each is testable individually. Datalog GC/cutoff scans become indexed SQL. Repairs are ordinary op batches with an internal marker on the event metadata, so they flow through the same funnel.

**Risks.** Repairs mutate user data with no user action, so a wrong rule is silent corruption at startup — ship behind a dry-run mode that logs a wide event with the planned fixes first. `cycle.cljs` is 372 lines mostly serving class-extends, which we may not have: port the parent-cycle half and leave the rest.

### Recycle (soft delete, exact-position restore, 30-day GC)

**Algorithm to preserve.** Write the three position breadcrumbs (original parent, page, order) in the **same** transaction as the move to Recycle — they cannot be recovered later. The restore fallback ladder in order: original parent if it exists and is not itself recycled, else the original page if valid, else **refuse** rather than dumping the block somewhere arbitrary. The refusal is the good judgement. A recycled subtree keeps its internal parent/order edges untouched — only the root moves and descendants get a page rewrite — which is why restore is cheap. Permanent delete goes through the same cleanup path as a hard delete or references dangle. GC does not enter the sync/op log.

**Transliteration.** The `reduce` with a `[txs, previousOrder]` tuple becomes a for-loop with a `previousOrder` local; that threading is how a batch of recycled blocks keeps its relative order, and it is also the pattern that replaces the deleted global max-key. `cond->` with `true` guards reads badly — plain ifs. The datalog GC cutoff scan becomes `WHERE deleted_at <= ?`. Thirty days is a user-facing retention knob and therefore a settings registry entry (`notes.recycle.retentionDays`), not a constant.

**Risks.** A recycled page keeps its title, so page-title uniqueness validation must exclude recycled pages or the user cannot recreate a page they just deleted. GC permanently destroys data on a timer: off by default until the restore path has tests, and one wide log event per sweep.

### Markdown→block extraction (file-graph import)

**Algorithm to preserve.** The three-case stack machine in `with-parent-and-order`, including the ragged-indent normalisation — a block indented 3 spaces sitting between a 2 and a 4 splits the stack at the level and adopts the level and `levelSpaces` of the first frame above — and the re-process-without-consuming behaviour on outdent. Nobody derives that correctly on a first attempt, and wrong produces subtly wrong trees. A block's uuid must be unique across the whole graph, not just the file: an imported `id::` that already belongs to a block on another page is **re-minted** and the `id::` line stripped from the text, rather than colliding (Obsidian silently lets duplicate `^id`s coexist and resolves links arbitrarily — the behaviour to avoid). Orders strictly increasing in document order. Page title resolution order: `title::`, then the filename decoded per format (`___` → `/`, `%XX` decoded), then the first heading. The post-import repair pass normalises journal uuids to their deterministic date-derived form and strips refs pointing at blocks that were never imported.

**Transliteration.** The surrounding parse is not ported at all — S7 consumes the mldoc artifact, so `extract.cljc`'s marshalling largely evaporates. The reverse-iteration accumulator exists because mldoc's AST puts property drawers and body _after_ the heading; keep it or do an explicit two-pass — the trick is not sacred, the grouping is. `loop`/`recur` with five accumulators becomes a for-loop with a small state object; the vector-as-stack becomes a real array. The global order max-key is replaced by a per-parent `lastOrder` cursor threaded through the walk.

**Risks.** Import is a one-shot path most users run once, so bugs surface as a permanently mangled graph with no obvious cause — it needs golden-file tests (a fixture vault in, an expected block forest out) more than unit tests. mldoc is two years unmaintained and unpatchable without an OCaml toolchain: keep it behind the single narrow module S7 specifies.

### Semantic op vocabulary (reimplement)

**Algorithm to preserve.** Validation of the whole batch precedes execution of any op — a malformed op fails loudly instead of half-applying. All entity references are uuids or stable idents, never numeric row ids, so an op is replayable on another device and after a reload. The non-obvious part is the split between the full ~30-op vocabulary and the smaller `semantic-outliner-ops` subset that participates in undo and sync: collapse/expand and the property setters deliberately do **not** enter history, which is why folding a block does not dirty a document.

**Transliteration.** malli's `(m/multi :dispatch first)` becomes a valibot variant over `{ op: 'move-blocks', ... }` objects — keep the tag as a string-literal field rather than Logseq's positional `[keyword, argsTuple]` so the union narrows in TS. Keyword args become camelCase booleans. Every payload is JSON-primitive per S6. Drop the property-value-block ops with the rejected design.

**Risks.** This is the widest API in the domain and it is frozen the moment the first event is persisted — an op shape change after that is an event-log migration, not a refactor. Resist shipping a raw `:transact` escape hatch: Logseq has one, and it is what forces the history layer to carry a raw-datom fallback.

### Op dispatcher and atomic batch commit (reimplement)

**Algorithm to preserve.** One semantic operation = one commit = one undo entry = one mirror write = one broadcast. Read-your-writes inside a multi-step op. Delete expansion and ref cleanup run at commit time from live state, never from the caller's snapshot, and inside the commit function so no caller can bypass them. An op whose target uuid no longer resolves is **skipped, not thrown** — history replay and remote ops routinely reference blocks that moved or vanished.

**Transliteration.** `batch-transact-with-temp-conn!` becomes `db.transaction(() => …)`: the entire staging layer Logseq built to get read-your-writes out of an immutable value disappears, because step 2 of a move sees step 1's write in the same transaction. The CAS retry loop disappears too — SQLite serialises writers and S4 gives us one. `d/listen!` plus a `volatile!` accumulator becomes handlers returning op results collected by the transaction body. `case` on an op keyword becomes `Record<OutlinerOp['op'], Handler>`. The commit appends **one** event under a new `aggregateKind`, widening the enum at `apps/server/src/db/schema.ts:37` plus a numbered migration.

**Risks.** The one thing SQLite does not hand us free is "no datoms produced → no transaction at all": a no-op drag must not append an event, or it pushes a phantom undo entry and triggers a mirror write. Nested batches need SAVEPOINT or an explicit depth guard — pick the guard, we control every caller.

### Canonical forward and strict inverse op construction (reimplement)

**Algorithm to preserve.** The inverse rule table, rule by rule: save-block inverts to a save-block restoring only the keys the forward op touched, using the **raw** title so it round-trips; insert inverts to delete of exactly the uuids that did not exist before; delete inverts to insert carrying the **full** pre-state subtree with `keepUuid` _and_ `keepBlockOrder` both true (without the exact orders, restore reshuffles siblings); move inverts per moved root to `[leftSibling, sibling:true]` or `[parent, sibling:false]` recorded from the pre-state; indent inverts by negating the flag only when a literal replay is safe, otherwise by explicit per-block moves; delete-page inverts three different ways depending on whether the page was a class (hard-deleted), today's journal (truncated) or ordinary (recycled). Three global invariants: **if any entry cannot be built the entire inverse is discarded** — a partial replay is worse than none; no numeric row ids may survive into a persisted op, asserted rather than warned; inverse _groups_ reverse at group granularity while entries within a group keep their order.

**Transliteration.** Roughly 600 of the 1309 lines are datom archaeology recovering facts we already have — our handler mints the uuids and holds the pre-state, so it emits `{ forward, inverse }` as a pair at execution time, which is also strictly more testable than deriving both from a diff. Dispatch colocates with the executor so a new op cannot be added without an inverse. The `mapcat` that distinguishes a single op from a list by testing whether the first element is sequential is a genuine footgun — return `OutlinerOp[]` from every rule. `selectedBlockRoots` returning an "incomplete" marker becomes `null`, and the caller's guard clause discards the whole inverse.

**Risks.** The description here is detailed enough that a faithful implementation will structurally resemble the original; if the AGPL boundary matters, this is the module to write from the rule table with the `.cljc` closed. Engineering-wise, the all-or-nothing rule is the one people delete under pressure ("surely a partial undo beats none") — it does not, and it needs a test asserting an unresolvable target yields zero ops. The delete inverse carries a whole subtree payload, so cap it or store it out-of-band before the event log gets fat.

### Undo/redo stacks and replay driver (reimplement)

**Algorithm to preserve.** Undo replays a semantic inverse through the **normal write API** rather than reversing datoms, so it respects validation and produces an ordinary syncable transaction. A replayed history action never generates its own undo entry. Forward/inverse swap on undo so redo works from the pushed entry. Any new local edit clears the redo stack. An entry whose targets no longer resolve is skipped and the driver recurses to the next one — it does not clear the history. Entries carry cursor/selection state; undo restores the first recorded cursor, redo the last. Entries carry ops only, never raw row data.

**Transliteration.** Atoms of `{repo → vector}` become one zustand store keyed by graph id. The injected `*apply-history-action!` atom becomes a constructor parameter. **Fix the truncation bug:** at 250 entries Logseq keeps `subvec 0 125`, dropping the _newest_ half — cap at N and drop the oldest. Leave UI-state (route/sidebar) entries out of the first pass rather than porting a second entry variant.

**Risks.** The real hazard is arbitration with the editor buffer's own 200-entry text undo, which is host-closed and offers no API to push a host operation onto it. A note block's text edit is text undo, a block move is outliner undo, and Cmd-Z must pick correctly. That has no precedent in either codebase — decide the rule before writing the store (likely a single platform stack owning both, with text transactions recorded as save-block ops).

### Sibling and tree navigation (reimplement)

**Algorithm to preserve.** Sibling navigation ignores non-outline children. A block whose parent is the page has no left sibling, and every caller must treat null as "use the parent". `consecutiveBlock?` is symmetric with two disjuncts: same page **and** (b2's left sibling is b1 **or** b1 is the last node of b2's-left-sibling's subtree). `lastChildBlock?` means "is this the last node of the parent's subtree in document order" and is defined recursively. `getNonConsecutiveBlocks` compares adjacent pairs only and therefore requires its input already sorted; a non-empty result switches move/delete/indent into scattered mode, which re-sorts the selection into page document order first.

**Transliteration.** This is where the substrate pays. Logseq's `get-ordinary-sibling` scans every child of the parent via the `:avet` index keeping a running best — O(siblings), guarded by a perf test asserting <100 ms on 1000 siblings. With an index on `(parent_id, order_key)` the same question is `WHERE parent_id=? AND order_key>? ORDER BY order_key LIMIT 1`, O(log n), and `get-sorted-page-block-ids` becomes one recursive CTE instead of an iterative DFS that re-sorts at every level on every call. The property-value "second notion of sibling" path (`db.cljs:427-495`) is deleted with the rejected design, removing about a third of the module.

**Risks.** Blocks with identical order keys make sibling navigation non-deterministic — exactly the state the duplicate-order repair fixes, so navigation and repair must ship together or the caret occasionally jumps. A recursive CTE over a deep page with no depth cap will follow a parent cycle forever; cap in SQL rather than relying on the repair having run.

### Derived entity attributes (reimplement)

**Algorithm to preserve.** Store a reference as `[[uuid]]`, render `[[Page Title]]` at read time from the ref set, and page rename becomes O(1) instead of O(referencing blocks). Two distinct notions of children survive even after property-value blocks are dropped: **outline** children (what the outliner traverses and renders) versus **raw** children (what deletion, subtree expansion and page denormalisation use) — confusing them is the bug class this file exists to prevent. Titles containing nested `[[…]]` are substituted nested-first or you half-substitute. A page whose title is ambiguous (two pages share it) is **skipped**, showing the raw token rather than a wrong link. Block refs are not substituted by default, because mutual block references would recurse forever.

**Transliteration.** The implementation is a getter trap reaching into DataScript internals (`@#'entity/lookup-entity`, a private var deref) wrapped in a try/catch that console-errors and returns nil — which is how you get a silently blank title in production. Ours is an explicit projection function over a row plus a resolver, which is also the only shape that works over a JSON DTO boundary (S6). Delete the try/catch: a resolution failure surfaces as a structured error. `:block/properties` derived by filtering an entity's own datoms becomes a join against `block_props`.

**Risks.** Projection must run exactly once, at the query boundary. Running it client-side too gives double substitution; running it before ref rebuilding renders stale titles. Pin it to one place and test that the raw form is what round-trips through save.

### Initial data and lazy page hydration (reimplement)

**Algorithm to preserve.** The renderer's view is partial by construction — any code assuming a query sees the whole graph is wrong. `load-status` is recomputed on every fetch, never cached, and every fetched child is tagged `:full` or `:self` so the renderer knows whether expanding needs a round trip. A page with 100+ children degrades to direct-children-only. Collapsed children cost nothing until expanded. Strip created-at/updated-at/tx-id/created-by from the payload; they are noise and a large fraction of the bytes.

**Transliteration.** `d/rseek-datoms`/`d/datoms` scans become SELECTs and the curated initial datom list becomes a handful of named queries. Expose **four** methods — `loadBlock`, `loadChildren`, `loadResource`, `applyOutlinerOps` — matching the three slot kinds the renderer subscribes to, and let everything else be a resource key; the 188-endpoint surface Logseq grew is the thing to avoid (S4). One line does not survive: `get-initial-data`'s first act is seeding the global order max-key, and we deleted that global.

**Risks.** Our transport is a WS hop rather than a `postMessage`, so the latency floor is higher and the slot store must absorb it — the `:loading` status is what makes that invisible, and skipping it produces flicker on every expand. "Oldest page with this name" as the resolution rule is a coin flip; replace it with an explicit id.

### Render delta and affected-key broadcast (reimplement)

**Algorithm to preserve.** One commit produces one delta: `{ rev, changedBlocks, deletedUuids, affectedResourceKeys }`. Membership-affecting attributes are **enumerated explicitly**, not inferred. Staleness is decided by comparing the per-block revision stamp, never by deep equality on block objects.

**Transliteration.** BroadcastChannel/comlink fan-out becomes our WS subscription frames, which already carry resume cursors and 25 ms coalescing (`apps/server/src/orchestration/streams.ts`). Transit is deleted (S6). The attribute sets become TS const arrays derived from our own column and property list — this is the half that is re-derived rather than translated, because it is schema-specific.

**Risks.** Over-broad key derivation is invisible (extra refetches) while under-broad derivation is a stale UI that looks like data loss — bias broad and narrow with measurements. The incremental search-index update that rides the same commit lands on FTS5, which our server does not have today: new work, not a port.

### Tree materialisation (reimplement)

**Algorithm to preserve.** The flat input must be document-ordered for level computation to work. Sort by order at **every** level, not once. Root level is 1, not 0. A block whose parent is outside the input set becomes a new root at level 1 — that rule is what makes copying a scattered selection produce a sensible forest.

**Transliteration.** One genuine trap: Logseq's `group-by` produces a map keyed by a nested map (`{:db/id n}`), which works because Clojure has structural map keys. JS Map keys are identity-based, so a literal translation silently produces one group per block — key by the uuid string. And one bug not to inherit: the recursion depth equals tree depth and is unbounded, so use an explicit stack.

**Risks.** Low. The only real hazard is reintroducing recursion for readability and blowing the stack on a deep import — the insert-blocks perf test asserts a 10,000-deep chain, so that depth is not hypothetical.

### Pages-are-blocks semantics and validation (reimplement)

**Algorithm to preserve.** The page/block-parent guard runs at **commit**, not at repair: every transaction is scanned for a page whose parent is a non-page block and rejected before commit, so the boundary cannot be corrupted even by a raw write. Today's journal is truncated, never deleted, so the daily note cannot disappear mid-day. Page rename touches zero blocks (refs are uuid-based) but page _delete_ walks referrers and substitutes the plain title back into their raw titles.

**Transliteration.** malli → valibot, consistent with the op vocabulary. The filesystem-hostile character rules overlap with the mirror's filename policy — define the character set **once** and import it in both places rather than letting two near-identical predicates drift. Title-collision checks become a uniqueness query, not an in-memory scan.

**Risks.** Title validation is user-facing and every rejected title is a small papercut; rules copied without their reason get relaxed later by someone who cannot see the harm. Record the reason inline, one line each.

### Markdown mirror (reimplement)

**Algorithm to preserve.** Filename normalisation and the deterministic uuid-ordered dedupe: NFC normalise, strip `<>:"|?*\/` and control chars, trim trailing dots and spaces, cap at 160, reject Windows device names, disambiguate colliding stems with ` (2)`. Write-if-changed by byte comparison so mtimes stay stable. Old-path deletion strictly **after** the new path is confirmed. Per-page job merging keeps the _earliest_ `oldPath`, so a page renamed twice inside one debounce window still deletes its original file. Transactions originating from disk must not trigger a mirror write or the loop never settles. Two pages claiming the same journal day abort mirroring for that page with a logged error rather than one clobbering the other.

**Transliteration.** promesa `p/let` chains become async/await — the largest "looks Clojure, is actually promises" surface in the domain (S5). The atom of `{repo → {pageId → job}}` becomes a Map plus a timer handle on a small service. The 1000 ms debounce and the feature toggle are settings-registry entries. Our `FileSystemService` already does atomic tmp+rename and app-save attribution, so mirror writes will not look like external edits to the watcher — reuse `FileChangeHub` rather than adding a second watch path.

**Risks.** Highest product risk in the domain: Logseq's mirror is strictly one-way and nothing reads it back, so editing a mirrored file has no effect and is overwritten. Users coming from Obsidian expect two-way. Either ship read-only-by-convention with a loud warning, or scope a genuinely different two-way design — do not smuggle it in as "the mirror, but bidirectional". Also, most of the 714 lines is rendering detail that only matters for Logseq-compatible output; if we do not want that, the renderer halves.

### with-parent-and-order

**Algorithm to preserve.** The stack is always ascending by indent width. The sibling case **replaces** the top rather than pushing, or the stack grows unbounded on a long flat list. Any positive indent jump is exactly one level deeper. An outdent matching an existing stack level does **not** consume the block — it truncates the stack, decrements the level, and re-processes the same block. An outdent matching nothing adopts the level and indent width of the first shallower survivor and parents to the last element below it.

**Transliteration.** `loop`/`recur` with a vector-as-stack becomes `while (i < blocks.length)` with an explicit array stack and an `i` that only advances on emit — the non-consuming branch is `continue` without `i++`. `split-with` → `findLastIndex` + `slice`; `butlast`/`conj` for stack replacement → direct index assignment. Drop the module-level `*max-key` atom entirely (it makes the function non-reentrant across pages) and pass the previous key as a parameter. In a file-first design, document position already _is_ the order, so keys are minted only for DB-side reordering, not on every parse.

**Risks.** The non-consuming outdent branch is where blocks silently vanish or the loop spins forever — it needs a fuzz test over random indent sequences asserting every input block appears exactly once, levels stay ≥ 1 (nothing clamps this upstream), and parents precede children.

### extract-blocks

**Algorithm to preserve.** A block ends where the next block **begins** (or at EOF), not at the end of its own AST node — that is precisely how property, timestamp and drawer lines end up inside the block's raw text. Trailing non-heading nodes accumulate and attach to the heading that precedes them, with the accumulator reset at each heading. A pre-block exists only when the first block's `start_pos > 0`, or when there are no blocks at all.

**Transliteration.** The reverse fold with seven loop bindings exists only to turn look-ahead into accumulate-then-flush; a forward `for` over the AST with one mutable `pending` slot flushed on the next Heading and at EOF is the same semantics stated forwards, with the end-position patch becoming `end = nextHeading.start ?? bytes.length`. Atoms used for out-of-band ref collection become a returned accumulator. `cond` dispatch on the node head becomes a `switch` on the AST union discriminant. The pre-block payload becomes YAML front matter for us — keep the span, parse it as front matter.

**Risks.** The last node's `end_pos` is null at EOF and every slicing consumer must handle it. A file with no heading node becomes entirely pre-block. The DB-export `cutMultiline?` special case suppresses the end patch and does **not** apply to us — copying it would truncate first blocks.

### extract-properties and parse-property

**Algorithm to preserve.** Key normalisation: lowercase; `/`, space and `_` all fold to `-`; `custom-id`/`custom_id` alias to `id`. Invalid keys are quarantined as literal text, never silently dropped. Double-quote wrapping is the user's escape hatch and must survive verbatim. Ref extraction drops URLs and asset links before anything else. Comma splitting runs over `Plain` segments of the **parsed** value, never the raw string, so `[[a, b]]` is one ref — and only for `alias`/`aliases`/`tags`, not `file-path`. `[[nested [[baz]]]]` yields the outer name with inner brackets intact _plus_ the inner name separately. The property key itself becomes a page unless excluded. The typing rules are arbitrary but load-bearing (a quoted string stays a string; a bare `\d+` becomes an integer) because users' existing files already encode them.

**Transliteration.** Replace the three parallel maps (`properties` / `properties-text-values` / `properties-order`) with one ordered `BlockProperty[] = {key, rawKey, rawText, value, valueKind, span}` — the triple is a documented drift hazard, and the span is what makes the write path O(1). Transducer chains become `.filter().map()` into a `Set`. `clojure.walk/postwalk` for block-ref harvesting becomes a typed recursive visitor. `valid-edn-keyword?` literally calls the EDN reader — replace with an explicit character-class check. The `:property/separated-by-commas` and `:property-pages/*` config keys become settings-registry entries at `application` scope. Port the survey's test oracles verbatim as the first test file.

**Risks.** Any regex alternation built from user page names is a ReDoS surface — escape and length-cap it. Typing is inferred per value, so one odd value changes what a column means; always keep `rawText` beside `value` so nothing is lossy and re-typing is free. `alias`/`tags` semantics leak into page identity, so a bug here changes which pages exist.

### get-block-content

**Algorithm to preserve.** Slice bytes → strip the bullet marker (`trimStart()` then `^[-]+\s?`, with the markdown-only guard that content starting `---` is returned unchanged) → de-indent at `level + 1`. Never reconstruct the text from the AST; this twenty-line function _is_ the round-trip fidelity story.

**Transliteration.** `cond->>` threading with predicates becomes sequential statements with guard clauses. `when-let` on `end_pos` becomes `end ?? byteLength`. Drop the normalisation step entirely: parsing must not normalise, so an org `:PROPERTIES:` drawer inside a markdown file stays verbatim and is rewritten only by the explicit importer. That single change removes the case where the in-memory title differs from the file bytes.

**Risks.** The `---` guard is prefix-only and markdown-only, so a block legitimately starting with a horizontal rule keeps its bullet. We parse front matter before block extraction, so verify the guard is still load-bearing rather than copying it blind — a dead guard here is a live bug later.

### remove-indentation-spaces

**Algorithm to preserve.** The prefix region is `line.slice(0, level)` where `level` is the caller's `astLevel + 1`. An all-whitespace prefix (or a line shorter than `level`) is **sliced**, preserving any further indentation — that is how deliberately indented content inside a block survives. A prefix containing content is **left-trimmed** instead. Getting the branches backwards destroys code blocks inside notes.

**Transliteration.** `safe-subs` (clamping substring) becomes plain `slice`, which already clamps. Destructuring `[f & r]` becomes `lines[0]` / `lines.slice(1)`. Port both worked examples from `deps/graph-parser/test/logseq/graph_parser/mldoc_test.cljs` verbatim as the first two tests, including the tab variant.

**Risks.** The all-whitespace branch can eat a tab where a space was expected, and the trim branch silently loses intentional indentation of code inside a block — both are known upstream defects. Reproducing them keeps round-trip parity with Logseq files; fixing them means files we re-save re-indent. Pick one deliberately and write the reason in a comment.

### mldoc AST bridge

**Algorithm to preserve.** Blank content short-circuits before the parser. The **Src full-content pass** is the piece nobody would rediscover: mldoc's `lines` array loses an indented fence's original indentation, so re-slice the original bytes from the node's own `pos_meta`, detect a leading `[\t ]+` run on the first line, and de-indent by that width with `removeFirstLine=true`. Offsets are UTF-8 bytes. The last node's `end_pos` may be null. Passes stay separate and inspectable, never fused into the parse call.

**Transliteration.** `cljs-bean` + `JSON.stringify` config becomes a typed `MldocOptions` object stringified once per format and cached. `goog.object/get` on the global becomes one module importing `mldoc` and reading `globalThis.Mldoc` behind a `.d.ts`. `clojure.walk/postwalk` becomes a typed `mapNodes` visitor. Do **not** copy the catch-all that swallows exceptions into `[]`: a malformed file must raise a structured error and emit a wide `notes.parse` event carrying byte length, node count, pass durations and total duration. Drop the page-property pass — `#+TITLE:` directives are Org-only and belong to the importer.

**Risks.** mldoc is 424 KB of js_of_ocaml, unmaintained since 2024, synchronous, CPU-bound, and unpatchable without an OCaml toolchain — keep it behind this one module, run it only server-side, and log per-parse duration from day one (Logseq never did, so parser-cost claims there are unfalsifiable). `enable_drawers`/`parse_marker`/`parse_priority` change which nodes exist at all, so pin the option set in one place.

### mldoc AST malli schema

**Algorithm to preserve.** The node inventory itself: the inline set (`Emphasis` with its Highlight variant, `Break_Line`, `Hard_Break_Line`, `Verbatim`, `Code`, `Tag`, `Spaces`, `Plain`, `Link`, `Nested_link`, `Target`, `Radio_Target`, `Subscript`, `Superscript`, `Footnote_Reference`, `Cookie`, `Latex_Fragment`, `Macro`, `Entity`, `Timestamp`, `Export_Snippet`, `Inline_Source_Block`, `Email`, `Inline_Hiccup`, `Inline_Html`), the tagged link-url union (`File | Search | Complex | Page_ref | Block_ref | Embed_data`), the timestamp shape (date / wday / time / repetition / active), and `pos_meta` on every top-level node.

**Transliteration.** Malli vectors become a TS discriminated union keyed on the tuple head, plus valibot schemas for anything crossing a route boundary. Every node stays JSON-shaped per S6, so parsed data survives the WS hop unchanged. Write it by hand from the schema, then pin it with a test that parses a fixture containing one of every construct and typechecks the result.

**Risks.** The schema is Logseq's _reading_ of mldoc's output and can drift from what the artifact actually emits — validate against real output rather than trusting the transliteration. Note the licensing asymmetry: the same types can be derived from mldoc's own ISC output, which is the cheaper path if AGPL exposure matters.

### Property line detection and read-side stripping

**Algorithm to preserve.** `^\s?[^ ]+::` marks a markdown property line — at most one leading space — and a run stops at the first line that is not one. Org drawer detection requires both `:PROPERTIES:` and an `:END:` matched as whole lines. Logbook stripping is a single fold with an in/out flag. Deadline/scheduled stripping keeps line 0 and drops a line that becomes empty.

**Transliteration.** `split-with`/`drop-while`/`partition-by` over line seqs become index loops returning **spans**, not new strings: `{ titleSpan, propertySpans[], timestampSpans[], logbookSpan?, bodySpan }`, so the write path splices without re-scanning and the editor can hide the same ranges as inline replacements.

**Risks.** `simplified-property?` allows only one leading space, so an indented property line inside a nested block is invisible and leaks into rendered text — a live Logseq bug. We de-indent before detection, which fixes it, _but only if that order is enforced_; a later refactor that detects before de-indenting silently reintroduces it. `removeDeadlineScheduled` matches the marker anywhere in the line, mangling prose that mentions `DEADLINE:` — anchor it to line start.

### split-macro-arguments

**Algorithm to preserve.** Five pieces of state — `pageRefDepth`, `scriptDepth`, `quoted`, `escaped`, `start`. `\` sets escaped; `"` toggles quoted and suspends all other interpretation; `[[`/`]]` and `^{`/`_{`/`}` adjust their depths; a comma splits only when both depths are zero and not quoted. Arguments are trimmed; blank input yields `[]`.

**Transliteration.** `loop`/`recur` with seven bindings becomes a `while` with local counters — materially easier to read in TS than in Clojure. Keep the worked example (`{{foo Ca^{ +2} ions, [[a, b]], "c, d"}}` → exactly three arguments) as the first test.

**Risks.** None structural. Only reachable if we ship macros at all; if we do not, skip it alongside `recover-inline-macros` rather than porting dead code.

### →new-properties (org drawer normalisation)

**Algorithm to preserve.** Exact whole-line matches for `:PROPERTIES:` and `:END:` via index lookup, not a regex, requiring `start >= 0 && end > start`. For each line strictly between: drop the leading `:`, split on the first remaining `:`, fold `_`→`-` in the key, apply the `id`/`updated-at` aliases case-insensitively, emit `key:: value` trimmed. Lines that do not split pass through; the marker lines are dropped.

**Transliteration.** `.indexOf` on a lines array stays `.indexOf` — the exactness is deliberate and a regex would be a regression. Wrap it as an **importer command** that rewrites the file once through the atomic-write path and records the rewrite on the event log so it is reviewable.

**Risks.** The failure mode is running it on the read path, which is exactly where Logseq runs it — so a markdown file containing a drawer has an in-memory title differing from its bytes on every read. Add an architectural test asserting it is never called from `block-content.ts`.

### Ref ⇄ uuid substitution (reimplement)

**Algorithm to preserve.** Order refs nested-first then longest-first so `[[foo]]` cannot clobber half of `[[foo-bar]]`. A `#tag` is a tag only at start-of-string, after whitespace, or after `(`, and may be trailed by punctuation; `#[[x]]` is never a page ref; a tag whose title contains a space must render `#[[title]]`. When two pages share a title, **refuse to rewrite rather than guess**. Never rewrite a self-reference; cap any recursive expansion by depth and by fixed point.

**Transliteration.** Because files are truth we never store uuids in block text, so the display-time direction disappears outright and only the dangerous half — rewriting on rename — survives. Logseq's `String.replace` over the whole block also hits code fences, URLs and inline code; reimplementing as span edits over parsed inline nodes deletes that bug class, which no faithful transliteration can. One left-to-right pass emitting `TextEdit[]` applied right-to-left; ref spans come from mldoc `Link{url:{Page_ref}}` / `Tag` / `Nested_link` nodes, so `Code`, `Src`, `Verbatim` and complex links are excluded _structurally_ instead of by a regex that forgets. Emit the rewrite as one event-log command with per-file `baseVersion` writes.

**Risks.** Rename is the most destructive command in the product: it needs a git checkpoint before the batch, a dry-run report, and a corpus round-trip test covering `foo` vs `foo-bar`, the title inside a fence, inside a URL, inside inline code, an alias, and a case-only rename. Partial failure mid-batch leaves the graph half-renamed unless the command is transactional over the event log.

### insert-property / remove-property (reimplement)

**Algorithm to preserve.** Property lines sit immediately after the block's first line with no blank line between them and form one contiguous run. Replacing an existing key edits in place and preserves order; a new key appends to the end of the first run; with no run and a title present the line becomes line 2, otherwise it is prepended. The result is right-trimmed. Removal takes the whole line including its newline. On org, the drawer is rewritten between the exact marker lines.

**Transliteration.** Logseq calls the parser on every property write to find the insert point — O(parse) to toggle a checkbox. We already hold the parsed block with byte spans, so `partition-by` over line seqs plus an atom flag becomes one scan returning `{ insertOffset, replaceSpan? }`. Apply as `TextEdit[]` on the live buffer when the note is open, and via `FileSystemService.write` with `baseVersion` + `expectedMtimeMs` when it is not — never a whole-file rewrite.

**Risks.** An off-by-one on the insert offset writes the property into the middle of the title. Property runs are exactly what a user reads in a diff, so any incidental whitespace change is churn: guard with "writing an unchanged value is a no-op" and pin with golden-file diff tests. If the note is open in an editor _and_ written server-side, the two paths must not both apply the edit.

### UTF-8 byte-offset slicing (reimplement)

**Algorithm to preserve.** mldoc reports UTF-8 **byte** offsets; JS strings are UTF-16, so `content.slice(start, end)` is correct only for pure-ASCII files. Encode and index exactly once per file and reuse it for every block — a per-block encode is O(n²) over the file. `end` may be nil, meaning "to end of buffer".

**Transliteration.** We deliberately choose a different algorithm from Logseq's per-block `TextDecoder`: build `byteToUtf16: Uint32Array` by walking code points once, then a slice is `text.slice(map[start], map[end ?? byteLength])`. Same correctness, one O(n) build instead of O(blocks) decodes. Assert in dev that a mapped offset never lands inside a surrogate pair.

**Risks.** The corruption is silent and only on non-ASCII, so the test must put multibyte characters in the **first** block — a trailing-only test passes with the bug present. Also assert the index is built once per parse; the natural "helper that takes the string" refactor reintroduces the O(n²).

### tree→file-content serializer (reimplement)

**Algorithm to preserve.** Fence length = `max(3, longest backtick run + 1)`. Heading level clamped to 1..6 with any existing `#` prefix stripped before re-adding, so re-serializing is idempotent. Continuation lines written at `(level-1)*indent + 2` spaces — the same constant the de-indenter strips. A blank block emits a bare `-` with no trailing space. Property lines at `blockIndent + 2` so they land inside the continuation region. Quote lines get `> `, blank quote lines get `>`.

**Transliteration.** Half of Logseq's version resolves DB entities and emits the mirror dialect, neither of which exists for us, and we never serialize a whole page on save — so this is only for create-from-template and export. `transient` vectors become `string[]` + `join('\n')`. Drop `propertyValueToString`'s entity resolution, the `*`-bullet dialect, and datetime journal-title rendering. Export the indent width as **one shared constant** imported by both reader and writer, and add a round-trip property test asserting `parse(serialize(tree))` deep-equals `tree`.

**Risks.** Writer/reader asymmetry drifts every multi-line block on the next save, invisibly, forever. Trailing whitespace on blank blocks is silent diff churn. The `heading: true` case makes heading level depend on tree position — reject it rather than reproduce it, or a block moved one level deeper silently becomes an `<h3>`. Property values held as sets have no stable order without an explicit order field; sort deterministically or every save reorders the file.

### Page title ⇄ filename codec (reimplement)

**Algorithm to preserve.** Title precedence: front-matter `title:` → filename stem → first heading. `nameKey` (lowercased, slashes stripped, path-normalized) is the lookup key while `title` is the display form, so two titles differing only in case are the same page. Journal detection tries the configured formatter then `MMM do, yyyy`, `yyyy-MM-dd`, `yyyy_MM_dd`, and the journal's id derives deterministically from the `yyyyMMdd` int — never random. Sanitiser: NFC, replace `<>:"|?*\/` and control chars with `_`, strip trailing spaces and dots, truncate to 160, reject blanks and Windows device names, disambiguate with ` (2)`, ` (3)` ordered by id.

**Transliteration.** The `:triple-lowbar` codec is **not** a bijection — a page literally titled `a___b` round-trips to `a/b`, and `%XX` decoding corrupts any title containing a literal `%` plus two hex digits — so we drop it and use the filename stem as the title with real directories for namespaces, which is lossless and readable by every other markdown tool. `memoize` on the journal converter is a real perf dependency (called per ref, not per page) → a bounded LRU Map. The formatter is a settings key at `application` scope, since it selects file paths.

**Risks.** Dropping the codec means a Logseq graph cannot be opened unmodified — that belongs to the importer, which decodes `___` once and writes real directories, and must be idempotent. Journal id determinism has to be pinned by a test or two machines disagree about the same day. The 160-char truncation plus dedup means a title change can move a file: that must go through the rename command, not a bare write.

### db-rebuild-block-refs (reimplement)

**Algorithm to preserve.** A block never references itself, checked by id in both directions — a fixed Logseq regression, without which a block mentioning its own id recurses forever at display time. Alias targets are excluded. Blocks created from a property value are not refs of their owner. Only a narrow set of date-valued properties creates a journal ref — scheduled/deadline plus user date properties, never `created-at`, or every block links to a journal. Property **keys** are refs as well as property values.

**Transliteration.** Logseq's version is a datalog join over uuid-refs already embedded in the text; ours derives refs from parsed inline spans and property values into a `note_refs` table. `d/entity`/`d/datoms` become one `delete from note_refs where from_block = ?` plus a batch insert per reparsed block, inside a single transaction so a reader never sees a block with zero backlinks mid-write. Ancestor traversal becomes a recursive CTE — native here, and exactly what `rules.cljc` carries a 20-line warning about in datalog.

**Risks.** Ref rows must be replaced atomically per block. Forward refs to pages that do not exist yet must resolve after a full index pass rather than being dropped, or the first import produces phantom missing links.

### construct-block (reimplement)

**Algorithm to preserve.** Identity comes from `id::` when present and parseable, otherwise a fresh time-ordered id. `collapsed` is lifted out of the property list and never surfaces as a user property. A markdown `#` heading forces level 1 unless the node came from a real list item. `created-at`/`updated-at` integers lift to block fields. A timestamp with no time and no repeater becomes the int `yyyyMMdd`; with either, it becomes a record.

**Transliteration.** The 11-step `cond->` chain is half DB-export concerns we do not have, and its central data structure — the three parallel property maps — is one we are explicitly replacing, so keep the ordering of the surviving steps and drop the rest. `d/squuid` becomes UUIDv7, or `crypto.randomUUID()` plus an explicit monotonic `createdAt`. Deep `cond->` chains become guard clauses assembling a plain object, one field per statement.

**Risks.** `collapsed:: true` in the file is a design mistake — fold state is view state and belongs in the workspace cache keyed by block id, which is where Logseq's own DB version ended up. Read it for compatibility if we must, **never write it**, or every fold dirties a file and produces a git diff.

## Outliner editing UX and keyboard model

**Strategy.** This is the domain where the product either feels like an outliner or does not, and almost none of it is derivable from a description — the value is in convergence filters, off-by-one caret rules, and guard-cascade ordering that exist because someone filed a bug. ### Indent/outdent and the move primitive

**Algorithm to preserve.** The convergence filters: `dropWhile(b => b.parent === left)` on indent and `takeWhile(b => b.parent !== parent.parent)` on outdent are what make repeated Tab on a mixed selection converge instead of oscillating, and neither is derivable from prose. The four move rejections — built-in block, target inside the moved set, target is a **descendant** of any moved block (walk the target's ancestor chain and intersect), and the no-op move. Only the _first_ block moves relative to the given target; every subsequent one moves as a sibling after the previously moved block. Indent auto-expands a collapsed new parent in the **same** transaction. Direct outdenting re-parents the last moved block's former right siblings. A non-consecutive selection aborts wholly rather than partially applying.

**Transliteration.** `d/entity` plus the `:block/_parent` reverse lookup sorted by `:block/order` on every call becomes a `ChildrenIndex = Map<BlockId, BlockId[]>` in order-key order, so left/right sibling is an array index ±1 — this single change removes most of the module's cost. The Clojure re-reads after each sub-move because the conn mutates mid-loop; in TS compute every destination order key up front from one immutable snapshot and emit a single `OutlinerOp[]` (but see risks). `:pre` assertions become `createStructuredError` catalog entries, never `new Error`. `parent-original` becomes an explicit optional parameter.

**Risks.** The descendant check is the only thing preventing a cycle and must be fuzzed, not exampled — we have precedent in the 15k-op tiling node fuzz (removed with tiling in `21d30b57`; recover from git history). Computing all order keys from one snapshot diverges from the reference when two moved blocks target the same gap; the reference cannot hit this because it re-reads, so either allocate the run with a single n-keys-between call or keep the re-read loop. The reference's outdent branch is five levels deep — extract named helpers to stay inside the house limit.

### Backspace-at-0 merge and forward Delete

**Algorithm to preserve.** The refusal guards and their order: journal first block; asset/comment block; zoom root; single-block wrapper or custom-query result; numbered-list item drops its number instead. `boundaryMergeAllowed = sameParent || !source.hasChildren` is four lines and is the entire subtree-swallowing defence. Five transaction shapes, of which case (iii) is the non-obvious inversion — when the previous block is blank, **delete that block and keep the current one**, precisely to protect the refs pointing at the block you are typing in. Children are re-parented in the _same_ op batch as the delete so nothing is transiently orphaned. The caret lands exactly at the join point. Forward Delete does nothing at all when the current block is collapsed.

**Transliteration.** The DOM walk for `prevNode` (all painted `.ls-block` elements minus embeds and property rows, index−1) is replaced by `visibleRows[index - 1]` from the renderer's flattened array, which already exists for virtualization and is correct-by-construction for collapse. The `__logseqBlock` property cached on the DOM node becomes a slot-cache lookup. **Do not transliterate the caret computation:** the reference uses `utf8ByteLength(prevTitle)` as the caret offset while the textarea indexes in UTF-16 — a latent bug for any non-ASCII previous block. Use `prevTitle.length` consistently. The five-branch `cond` becomes one function per shape behind a small dispatcher.

**Risks.** Correctness depends on the renderer owning an accurate flattened visible-rows array including collapsed subtrees, embeds and property rows; if that array is derived lazily or lags a transaction, Backspace merges into the wrong block. The reference bails entirely on iOS and relies on a native key bridge — we have no equivalent, so mobile/webview behaviour is untested territory. This is the module most likely to need a golden matrix: one case per guard × per shape.

### Enter-key split

**Algorithm to preserve.** `second` is **left-trimmed only**; `first` keeps its trailing whitespace; a selected span between the two is destroyed deliberately. The degenerate-case order: numbered-list blank → drop the number; non-blank → normal split; blank last-top-level-child → normal insert; blank otherwise → outdent if there is no right sibling. `insertAbove = blank(first) && !blank(second)`. The `sibling?` cascade resolves ref-query context, library pages, an explicit boolean, collapsed, then `!hasChildren` — **in that order**, with `hasChildren` awaited from the store rather than read off render props. Exactly one op batch per Enter so undo restores one keystroke. The new uuid is minted client-side with `keepUuid` so the caret can target it before the commit returns.

**Transliteration.** `p/let` chains become sequential awaits. `cond->` map building becomes an explicit object with early returns. `ui-outliner-tx/transact!` batching several side-effecting calls into one DataScript tx with an `:editor/edit-block-fn` in tx-meta becomes an explicit `{ ops, onCommitted(rows) }` dispatched over WS RPC. The attributes stripped before re-parse (`tags`, `alias`, `properties`, `warning`) become an explicit deny-list constant next to the parser wrapper.

**Risks.** Our insert is a WebSocket round-trip, so the window in which the caret has nowhere to go is longer than Logseq's — this module is only correct in combination with the pending-new-block buffer, and the two must land together. The `sibling?` rule reaches into render context (linked references, custom query, library) we have not designed; leaving those branches as TODOs produces wrong nesting the first time backlinks ship.

### Editing-state store and commit pipeline

**Algorithm to preserve.** The four `textRange` cases in order — a `[direction, column]` pair (for `:up` take `content.slice(0, lastIndexOf('\n') + column + 1)`, for `:down` `firstLine.slice(0, column)`), then `tailLen > 0` (caret exactly where an appended tail starts, which is how merge places it), then `pos === 'max'` or past the end, then plain slice. The textarea is the source of truth while focused and the store mirrors it. Every structural command force-saves first. `pendingTitles` keyed by block id prevents an in-flight save from making the next save believe nothing changed — a race nobody anticipates until they hit it. Auto-save is suppressed during IME composition and while an autocomplete action is open, and the 450 ms idle debounce is **skipped** when the value contains a `#tag` so ref parsing never runs mid-word. Editing identity is always `(containerId, blockId)`, never the block alone.

**Transliteration.** One global atom with ~40 namespaced keys and a `swap-state!` reducer becomes a narrow zustand store exposing domain actions (`beginEditing`, `setContent`, `flushPending`, `clearEditing`) — not a state blob. The re-arming timer becomes TanStack Pacer rather than a hand-rolled `setTimeout`. The DataScript transact becomes `applyOutlinerOps` over the existing WS RPC.

**Risks.** `containerId` exists because one block can be mounted in the main pane, the sidebar, an embed and a linked-refs section at once. Our workbench has an analogous notion but nothing wires it to a document; keying editing on block id alone means two panes showing the same note fight over the textarea and over `pendingTitles`. Decide container identity before writing the store. Our `WorkspaceDocumentService` already owns a `sync: 'file'|'settings'|'none'` union — a notes block is a fourth sync kind, not a fake file path.

### Move block up / down

**Algorithm to preserve.** One rule carries it: when moving **up** past a block that has children, the real target becomes `lastChildOrSelf(target)`, so you land at the bottom of that subtree. That is what makes repeated presses walk the visible outline instead of hopping levels. Up: `leftOrParent = leftSibling(first) ?? parent(first)`, `leftLeft = leftSibling(leftOrParent) ?? parent(first)`, `sibling? = parent(leftLeft) === parent(first)`, abort when `leftLeft` is null or is the page. Down: `right = rightSibling(last) ?? rightSibling(parent(last))`. The subtree always moves as a unit.

**Transliteration.** Against the ordered `ChildrenIndex`, `get-left-sibling`/`get-right-sibling`/`get-down` are array index ±1, so the whole module is roughly 40 lines of TS. The caret restore reads the new container id off the sibling DOM node when that node is a linked or embedded rendering — replace with the container id already on our visible-row record.

**Risks.** `lastChildOrSelf` drops the block _inside_ a collapsed sibling's subtree, where the user cannot see where it went; Logseq does this unconditionally. Gate the retarget on `!target.collapsed` and treat a collapsed sibling as a single unit — that matches what the user is looking at.

### Autocomplete trigger detection and lifecycle

**Algorithm to preserve.** Exactly one `action` is ever live. `actionData.pos` is captured **once** at trigger time and anchors both the popup position and the query slice, and must be invalidated when the caret moves left of it. Open conditions: `/` at line start or after space/tab; `#` at line start, after space/tab, or immediately after `]]`; caret wrapped by `[[ ]]`. Close conditions: space right after `/`; `##`; `# `; caret leaves the delimiters; more than 2 characters past the last match; Backspace over the trigger. The keydown pass order is the specification: page-search-plus-`#` rejection, pending-insert diversion, arrows clear, IME skip, modifier skip, type-over a closing pair, wrap-when-selected, action-already-active bail, then autopair. `wrappedBy`'s half-offset trick — before-markers at `i + len - 0.5`, end-markers at `i + 0.5`, the caret inserted as `[pos, between]`, sorted, then scanned for before/between/end consecutive — is a genuinely clever three-line answer to "is the caret inside these delimiters" and resolves the boundary cases correctly.

**Transliteration.** Three order-critical `cond`s become one explicit state machine with a transition **table** plus a separate keydown pre-pass for autopair — keep the table as data so the order is inspectable. Global `*matched-commands` atoms become store fields. The `((` block-ref path is dead in this checkout (it shows a warning toast) — do not port it. The fullwidth-CJK rewrite is a self-contained ±4-character longest-match scan and ports verbatim as a pure function.

**Risks.** Everything except `wrappedBy` here is arguably clean-room-derivable from the description; rewriting `wrappedBy` from its stated invariant (~15 lines) would let this module be relabelled if exposure matters. Page/tag search resolves on the **server** for us (mldoc + FTS5), so Logseq's 150 ms local debounce becomes a network round-trip and the popup needs a loading state the reference never had. IME behaviour is browser- and OS-specific and cannot be tested in happy-dom; the Rime and macOS Pinyin special cases are evidence of a long tail.

### Pending-new-block type-ahead buffer

**Algorithm to preserve.** While pending: single-character keydowns append to `typedText` and are stopped; Enter is swallowed with no second insert; Tab/Shift-Tab record `tabIndent` direction; Backspace pops the last buffered character or, if there is none, sets `delete`. On commit, apply `tabIndent` **before** opening the new block; open at offset `typedText.length` with `customContent = typedText + newTitle` and `skipLoad: true` so a store read cannot clobber the buffered text. The delete branch merges back into the _source_ block and then re-applies with the **latest** `typedText`, because the buffer may have grown while the delete was in flight — a second-order race that is discovered, not designed. Clear the buffer exactly once, in the commit callback or the error path.

**Transliteration.** `state/update-state!` on a nested atom path becomes a small module-level mutable object in `state/` (stateful, so never `utils/`). The callback threaded through transaction metadata becomes an `onCommitted(rows)` continuation on the RPC promise.

**Risks.** Only correct in combination with the Enter split — land them together or Enter is worse than not shipping it. Needs a test that types twenty characters plus a Tab inside an artificially delayed insert. Watch React 19 StrictMode: our app mounts under it and our dom tests do not, and a module-level mutable buffer cleared in an effect is exactly the shape that passes tests and dies in the browser.

### Clipboard: copy payload and paste dispatch

**Algorithm to preserve.** The nine-branch paste cascade in order — files, then code/math raw, then the internal same-graph payload, then the URL-over-selection family, then html→markdown, then markdown-tree / blank-line-split / inline. `keepUuid = (lastOpType === 'cut')`, and when the pasted set is exactly the set just cut, **revert the cut transaction** rather than re-inserting. `replaceEmptyTarget = emptyTarget && (!targetHasChildren || blocks.length === 1)`; when the target is empty _and_ has children _and_ the paste is nested, retarget to the target's left sibling or parent. Force-save any unsaved edit in the target before the transaction, and open the last inserted block for editing at the end. The graph-id equality check gating the internal path is two lines and is load-bearing.

**Transliteration.** The custom MIME `web application/logseq` carrying EDN becomes `application/x-platform-notes+json` carrying a plain JSON DTO from `packages/contracts` — no `Date`, no `Map`, uuids as strings, timestamps as epoch millis (S6). DataScript entity serialization with an attribute deny-list becomes a structural clone over the block row and its EAV rows. The markdown→block-tree parse must call mldoc server-side (S7), so paste becomes async and the caller needs an optimistic placeholder.

**Risks.** Dropping the graph-id check lets a cross-workspace paste reconstruct blocks with colliding uuids and silently corrupt refs. The Android `navigator.clipboard.read` in-memory fallback is irrelevant — skip it. Server-side parsing makes paste latency a network round-trip on a gesture users expect to be instant; measure before choosing between an optimistic client-side splitter and the authoritative server parse.

### Command step interpreter and text splicing

**Algorithm to preserve.** Replace the **last** occurrence of `lastPattern` in the prefix, never slice at a remembered index — that is what makes an earlier `/` in the block harmless. The six space-suppression conditions (CJK adjacency, a preceding `(`, `{{embed`, a preceding `#` with a `[[` pattern, property colons, triple backticks). `endPattern` advances `currentPos` past an already-present closer and `postfixFn` strips it. Refuse to write when a non-blank value would come out blank. The textarea value, the content store and `lastPos` are always written together, then `setSelectionRange`. `simpleReplace` re-selects `[newPos, newPos + selected.length]` so wrapped text stays selected. Commands that open their own sub-UI suppress the automatic state restore.

**Transliteration.** `defmulti handle-step` becomes `Record<StepName, (args, ctx) => void | Promise<void>>` executed sequentially with `await`. `p/doseq` becomes `for...of` with `await`. `util/replace-last` with a space-awareness flag is a ten-line pure helper. Model `restore: false` as the step returning `{ ownsFlow: true }` rather than a parameter threaded from the caller.

**Risks.** In Logseq plugins push into the same command vector; we have no plugin surface, so keep the registry a plain array in `state/` and resist making it an extension point before a second consumer exists — our own editor packages already carry an unwired `registerBlockProvider` as a cautionary example. Steps depending on UI we have not designed (date picker, template search, image upload) should be no-ops that log, never undefined table entries.

### Drag-and-drop drop-mode computation

**Algorithm to preserve.** `xOffset > 50` (100 on touch) → NESTED; first row and `abs(cursorTop - rect.top) <= 16` → ABOVE; otherwise SIBLING. Separator indent 48 px nested / 20 px otherwise, suppressed when the row's top flag disagrees with the mode. Those four numbers are the entire feel of outliner drag-and-drop. The drag payload is the whole **selection** when the dragged block is part of it, otherwise just that block. Alt-drop inserts a block **reference** instead of moving. An aliased or linked rendering moves the original block. Target resolution: ABOVE → `(target.parent, top)`, NESTED → `(target, sibling:false)`, SIBLING → `(originalBlock ?? target, sibling:true)`.

**Transliteration.** Global atoms read by every block row via `use-atom` become **one** store selector subscribed only by the hovered row and the separator — otherwise the separator re-renders every row on every pointermove, which we would feel immediately at outline scale. The external DataTransfer path (files → assets, text/plain → new block) reuses our existing attachment route.

**Risks.** The 50 px threshold is unitless upstream and was tuned against Logseq's row indent; verify it against our density (we recently made the file tree denser) or nesting triggers in the wrong place. Keep this drag state self-contained (the workbench tiling drag this originally had to avoid was removed in `21d30b57`). Journals are not drop targets at all upstream — decide whether we have an equivalent exclusion.

### Click-to-edit caret mapping

**Algorithm to preserve.** A two-pointer walk over lowercased markup and rendered text with three cases (equal → advance both; rendered char is `[`, `]` or space → advance rendered only; else → advance markup only), then four post-corrections in order: double `]]` → pos+2; a run of `` * _ / \ + ^ ~ $ ` `` → skip the run **only if** the reversed run exists on the current line; `](` with a `[` before and `)` after on the line → skip past the `)`; else stay. It always terminates because at least one pointer advances per iteration. On exception return `markup.length`, never 0. A stored `lastPos` from a previous edit of the same block takes precedence over the mapping.

**Transliteration.** `loop`/`recur` over lazy char seqs becomes a `while` over two indices. The capture half is already plain DOM and carries over unchanged — clone the range contents, delete the non-source decoration nodes, take `textContent`, detect a trailing break — only the decoration class name changes.

**Risks.** This module exists **only** because Logseq renders blocks as output and swaps in a textarea. If we render notes as source with `@singapore-editor/markdown` inline replacements (already production-wired, revealing source under the caret via `groupId`), the caret is always in source coordinates and this module is unnecessary. Decide the render model first — it is the highest-leverage decision in the domain. If we do keep the split, every non-source node the renderer emits needs a deliberate exclusion class or clicks land in the wrong place.

### Inline formatting toggle

**Algorithm to preserve.** Selection normalisation shrinks past leading and trailing whitespace before wrapping — which is why bolding a selection with a trailing space gives `**word** ` and not `**word **`. The already-wrapped test looks **outside** the selection (`value.slice(start-n, start) === p && value.slice(end, end+n) === p`), so toggling works whether or not the user selected the delimiters. Unwrap re-selects `[start-n, end-n]`; wrap with a selection puts the caret at `end + n`; wrap with no selection selects `[start+n, end+n]` so the caret sits between the delimiters. Five link cases with their forward offsets.

**Transliteration.** Nothing to translate — it is a literal port of index arithmetic, which is exactly why the license label matters here more than the engineering does. It is host-agnostic (a string and a selection range) so it belongs in the editor package alongside the caret primitives.

**Risks.** No technical risk. This is the cheapest module in the domain to buy out of AGPL exposure: eighty lines a competent engineer writes from the two invariants above in about an hour. If reducing derivative surface without losing behaviour is wanted, start here.

### Undo/redo with caret restoration (reimplement)

**Algorithm to preserve.** An entry is `[editorInfoBefore?, ops, editorInfoAfter?]` where editor info is `{blockId, containerId, startPos, endPos}` or `{selectedBlockIds, direction}`; undo restores from the **first** info item and redo from `last ?? first`. The snapshot is captured when the editor mounts on a block and consumed by the first transaction after that. A new local transaction clears the redo stack. An entry that is no longer invertible is **skipped** and the walk recurses, rather than poisoning the stack. A `historyPaused` flag suppresses re-recording during a restore.

**Transliteration.** Ops invert DataScript transactions by tx-id across a comlink boundary, validated by malli, keyed by repo atoms — none of that translates. We have an append-only event log with command receipts, causation and correlation, so invertibility comes back on the command result and the caret snapshot is inherently client state. **Do not copy the truncation:** at 250 entries the reference keeps `subvec 0 125`, retaining the oldest half.

**Risks.** `@singapore-editor/core`'s undo is text-only, host-closed, capped at 200 entries, with no API to push a host operation onto it. If notes render through the editor engine at all, Cmd+Z hits two stacks: the keymap must intercept undo/redo whenever the notes surface owns focus, and if block text is edited through an engine buffer rather than a raw textarea, text undo and structural undo diverge with no way to reconcile. Resolve the editing-surface decision first.

### Caret geometry mirror (reimplement)

**Algorithm to preserve.** The public surface — `caretRect(pos) -> {x, y, rowIndex}`, `rowTops(): number[]`, `posNearestX(rowIndex, x): number`. The nearest-x rule: in the target row partition character positions by `left <= caret.left`, take `a` = last of the first partition and `c` = first of the last, answer `a` when there were fewer than two partitions, else whichever of a/c is closer in x with a missing `a.left` treated as 0 and a missing `c.left` as +∞. First/last visual row = caret top equals `tops[0]` / `tops.at(-1)`. Cross-block column is counted in **graphemes** (`Intl.Segmenter`) and converted back on arrival as a prefix length. On measurement failure degrade to "last row" so Up/Down still crosses blocks.

**Transliteration.** The mechanism must go and is worse than described: `next-cursor-pos-up-down` re-renders one `<span>` per grapheme for the whole block and reads `offsetLeft`/`offsetTop` off every one, synchronously, inside the keydown handler — O(chars) DOM nodes and a forced layout per arrow press, on the block being typed in. Replace with one mirror div plus `Range.getClientRects()`. Collapse to **one** index space (UTF-16 offsets into the textarea value) and derive grapheme counts only where the cross-block column demands it; the reference keys span ids by UTF-16 offset while indexing children by grapheme index and must keep the two straight. Word motion needs no mirror at all and is a direct port of index arithmetic.

**Risks.** The mirror's typography must match the textarea exactly — font, width, padding, letter-spacing, word-break, tab-size — or every answer is silently wrong with no error. Needs real browser tests with both a proportional and a monospace font; our happy-dom lane fakes `getBoundingClientRect` and would pass a completely broken implementation. Compare row tops with a tolerance, never equality. RTL is untested upstream and will be untested here. A new `@singapore-editor` package costs bun link + root overrides + a Vite restart; putting it in `apps/web/src/features/notes/utils/caret/` instead is defensible but leaves the geometry with no browser-test home.

### Multi-block selection state machine (reimplement)

**Algorithm to preserve.** Four cases in order: currently editing → save, exit, select `[current]`; exactly one selected → append the adjacent visible block using the "skip" variant that steps over blocks already contained in a selected node; more than one and the key direction equals the recorded direction → append at that end; opposite direction → drop the last-added block. Direction is **sticky** until the user reverses. Shift+Up/Down escalates from text selection to block selection only when the caret is on the first/last visual row. Cmd+A escalates all-text → this block → parent → page with a terminal `selectedAll` flag. The floating action bar appears after 200 ms, cancelling any pending one.

**Transliteration.** The storage is the problem and is most of the code: `:selection/blocks` is a vector of live `HTMLElement`s mutated with imperative `.selected` class add/remove, and it synthesizes detached `<div blockid=…>` nodes for blocks virtualization has unmounted. Selection becomes `BlockId[]` in a zustand store with `selected` derived per row, and `getNodesBetweenTwoNodes` becomes an index range in the flattened visible-rows array — which deletes the synthesized-placeholder path entirely.

**Risks.** Drag-select and React fight if the row component does not own its own highlight — no direct DOM class mutation as a shortcut. The floating action bar is a floating surface and must use `surface-vibrancy`, not hand-rolled opacity. Keep this drag state in its own store.

### Collapse / expand (reimplement)

**Algorithm to preserve.** Expand-one-level scans levels 1 upward and expands exactly the blocks at the **first** level that has any collapsed block, then stops; collapse-one-level scans max downward and collapses the first level that has any collapsible block. Toggle re-reads the block from the store because the in-memory edit block does not track the flag; for a selection, the first block's state decides for all. Collapse is **both** a persisted attribute and a per-container UI flag, and the persisted write is skipped in linked-references contexts so folding a backlink is view-local. Save in-progress editor text first. One op per gesture so undo is one press.

**Transliteration.** `clojure.walk/postwalk` pruning plus `tree-seq` flattening becomes one pass over the flattened rows array the renderer already builds for virtualization — almost nothing of the Clojure survives the substrate change. Lazy loading of a collapsed block's children maps onto the slot cache's `:loading` status, which already models it.

**Risks.** Do **not** route note collapse through the editor engine's fold system: our production logs show `editor.syntax.structural_error` firing 997 times with "crossing fold ranges", and fold ranges cannot be contributed independently anyway (the syntax provider is first-wins). Note collapse must be our own row-level state. The per-container UI flag needs the same container-identity decision as the editing store.

### Title commit parser (reimplement)

**Algorithm to preserve.** Stored titles contain **UUID** references, never name references — that is what makes renaming a page O(1). A ref picked from an autocomplete keeps its identity via the known-ref cache even before the page exists in the index, which is what lets a freshly created page survive. Heading level is a **property**, not text, so changing it does not rewrite the title (and code/math blocks skip heading normalisation). Self-references are dropped. Markdown links of the form `[label](#tag)` resolving to a Tag page count as refs. A pipeline step afterwards removes now-orphaned page refs.

**Transliteration.** The parse itself is mldoc, consumed as an artifact (S7); everything around it is DataScript entity-map merging. `tree-seq` over the AST hunting Link nodes becomes a recursive walk over mldoc's JSON. `distinct` last-wins becomes a Map keyed by uuid built in order. One quirk must carry over verbatim: mldoc expects a list item, so the input is built as `"- " + title` or `"-\n" + title` depending on whether the first element is a block-with-title type.

**Risks.** Honest caveat on the label — mldoc is ISC and out-of-repo so consuming it is clean, but typing our AST from Logseq's malli schema is copying Logseq's expression of that shape. It describes a third party's format, which is why it is labelled clean-room, but the schema file is AGPL and the user should decide knowingly. `getReferences` is the engine behind backlinks and the graph view, so a silent regression corrupts the graph: this needs a golden-file corpus, not example tests.

### Linked references with include/exclude filters

**Algorithm to preserve.** `effectiveRefs(e) = ownRefs(e) ∪ effectiveRefs(parent(e))`. `allowedSubtreeRefs(e) = ∅` if `effectiveRefs(e)` intersects excludes, else `ownRefs(e) ∪ ⋃ allowedSubtreeRefs(children)`. A node matches iff **every** include is in `effectiveRefs ∪ allowedSubtreeRefs` **and** no exclude is in `effectiveRefs` alone. That asymmetry is the feature: includes may be satisfied by descendants, excludes only by self-and-ancestors, and a descendant under an excluded ref cannot satisfy an ancestor's include. Logseq wrote a docstring counterexample precisely because it is counter-intuitive — `[[foo]] > [[baz]] > [[bar]]` with include=bar, exclude=baz must **not** match foo. The DFS's three branches have distinct child-push behaviour (push on class-mismatch, push on non-match, do **not** push on unsatisfiable includes); swapping any loses matches or turns the traversal O(graph). `expandToTopRefs` walks up to and including the first node that is itself a top ref. Scope: page ∪ aliases, class pages also cover structural descendants, and a class's own instances are excluded from its backlinks.

**Transliteration.** `d/datoms :eavt` forward reads and `:block/_refs` reverse reads become **one** recursive-CTE fetch materialising `{id, parentId, refIds[], tagIds[], pageId, hidden}` for the top refs and their whole subtree into a `Map`; every child-ids call then becomes a Map lookup. A per-node SQL round-trip turns this from O(n) into O(n²) plus n latencies and is the single easiest way to ruin the port. `volatile!` memo maps become `Map<number, Set<number>>` closures inside the factory; keep the explicit stack rather than recursion, the trees are deep. Materialise rows only at the very end.

**Risks.** The docstring counterexample is the only real regression test and must be in the suite from day one. `effectiveRefs` recurses on parent with **no cycle guard** — the DFS has `visited` but the memo does not, so corrupt data infinite-loops; add the guard we know upstream lacks. Memoisation is only correct within one consistent snapshot: run the fetch and the filter inside one read transaction, and never hoist the memos to module scope. A page referenced by thousands of blocks pulls a large subtree — cap or paginate top refs before the filter runs.

### Recursive id-ref → title resolution

**Algorithm to preserve.** Replace refs **nested-brackets-first** so a shorter title cannot eat a substring of a longer one. Leave unknown ids verbatim, never blank them. Bound the replacement loop by depth **and** guard the BFS with a seen-set — mutual references need both. `#[[uuid]]` renders as a bare `#title` only when the title contains no space, otherwise `#[[title]]`. The page-ref pass must not touch `#[[…]]`. Regex metacharacters in page names must be escaped. Matching is case-insensitive on the page-name side while stored casing is preserved.

**Transliteration.** `clojure.string/replace` with a function replacement maps directly to `String.replace(re, fn)`; `re-seq` → `matchAll`. `sort-by` with a `[hasNestedBrackets, title]` key and a `>` comparator becomes one explicit comparator. `d/entity` ref reads become a `Map<uuid, {title, refs}>` prefetched by the BFS in one recursive-CTE round trip instead of N lookups. Keep the Safari `(^|\s|\()` capture-and-restore idiom even though the graph runs on Bun — the same functions run in the browser for live preview.

**Risks.** The lookahead and capture regexes are the fragile part and JS regex semantics differ subtly from Clojure's at the boundaries — test page names containing metacharacters, spaces, `#`, and non-ASCII. This is doubly load-bearing: it feeds both display **and** the search index, so an error makes blocks silently unfindable.

### Renderer resource store

**Algorithm to preserve.** The three-rule staleness test on an in-flight resource response — watch-all plus any change; dirty keys intersecting the resource's watch keys; dirty slots intersecting the slots this response hydrated — and that a stale response is **discarded and re-requested**, never accepted. Exactly one request in flight per slot key, with a queued reload flag instead of a second request. Revision comparison rather than deep equality when choosing between current and next slot. Reuse the current snapshot object when the two are equal so `useSyncExternalStore` skips the render. Children patches applied only when the client's `basisRev` matches the delta's `baseRev`, otherwise mark stale and full-reload. Resource slots drop on last unsubscribe while block/children slots demote to a warm LRU. Generation plus token checks so a graph switch drops in-flight responses.

**Transliteration.** Atoms with `swap!` returning new immutable maps, plus `volatile!` to smuggle out side-effect lists, become a plain mutable store class plus explicit `changed[]`/`reload[]` arrays returned from each apply function — frozen POJOs and reference equality, never Immutable.js (S5). `cljs.cache/lru-cache-factory` becomes a small Map-based LRU. The comlink transport and its transit codec simply do not exist for us. One deliberate deviation: the 2000 ms query debounce must **not** be a hardcoded `if (= :query (first resource-key))` in the store — it becomes a `debounceMs` field on the resource declaration, and the number a settings-registry key.

**Risks.** Highest debugging cost of anything in this domain — the failure modes are races that pass every deterministic test. Write the tests as explicit interleavings (delta between request and response; delta with a mismatched `baseRev`; unmount during load; graph switch mid-flight), not as end-to-end flows. The surrounding block/children slot machinery belongs to another domain's port, so this cannot land alone.

### Simple-query DSL: lexical pre-transform and reader

**Algorithm to preserve.** The five-pass pre-transform order and its sentinel round trip: quote page refs first (masking `#` inside them), then mask `#` inside quoted string literals, then rewrite ` #` to `#tag` and a leading `^#` to `#tag `, then unmask. A whole-string-quoted input bypasses straight to full-text mode. `simplifyQuery` collapses any `and`/`or` with exactly one operand, bottom-up to a fixpoint, and **never** removes a `not`. Timestamp-property resolution: lower-case, underscore to hyphen, registered ident else created-at/updated-at else null — where null means "this is a journal-day between, not a timestamp between".

**Transliteration.** `cljs.reader/read-string` with a `:readers` map becomes a hand-written ~150-line tokenizer and recursive-descent parser over seven token kinds — do **not** reach for an EDN or JSON parser. The `#tag` tagged-literal reader becomes a parser rule emitting a `PageRef` node. Pre-transform pass (b), which keywordizes signed durations so the EDN reader will accept them, **disappears**: our tokenizer accepts `[+-]?\d+(y|m|w|d|h|min)` as a duration literal, which is precisely why the parser is hand-written. Output is a discriminated union, which is what lets the compiler and the watch-key analyser stop sniffing shapes.

**Risks.** Low technical risk, high blast radius — every downstream module consumes this AST, and the query builder means it must also serialize back to a string. Fix the AST shape before writing the compiler. The documented example table is the conformance suite; without it the `#`-inside-page-name and `#`-inside-quoted-string cases regress unnoticed.

### Date, duration and dynamic-variable resolution

**Algorithm to preserve.** Journal days are `YYYYMMDD` integers and timestamps are epoch ms — never mixed in one comparison. `between` endpoints are sorted after conversion so argument order is irrelevant. The last-character duration switch, and which unit each letter means in each path: `m` means months in both while `n` means minutes. Journal offsets apply to _today_, timestamp offsets to _now_. Journal-between is inclusive at both ends; timestamp-between is `>= start` and `< end`. Time-of-day suffix decoding is direction-dependent, with `start` = midnight and `end` = 23:59:59.999, otherwise the suffix is `HHMMSSmmm` right-padded and each component clamped (so `today-25` clamps to 23:00 rather than erroring). Unresolvable inputs pass through unchanged.

**Transliteration.** cljs-time becomes date-fns, but every operation is **local** time while our graph runs server-side and "today" belongs to the client — pass `todayDay: number` as an explicit input and validate it, exactly as Logseq's worker does. `defmulti` becomes a classifier plus a `Record<Kind, Resolver>` table. The chrono NLP fallback stays behind a flag; it is locale-dependent and the least testable part. Drop the deprecated input forms (`1d-before`, `1w-after-ms`) rather than porting the rewrite path.

**Risks.** Timezone. Our boundary is a network hop to a server that may sit in another zone — get it wrong and `(between -7d today)` is off by one for half of every day. Test with a fixed clock in at least two non-UTC zones, one with a DST transition inside the queried range.

### SQLite FTS index schema

**Algorithm to preserve.** The **trigram** tokenizer — what buys arbitrary substring matching (and CJK) instead of prefix matching, at the cost of a much larger index, and the reason the short-query LIKE lane must exist. Trigger-maintained FTS shadow table where UPDATE is delete-then-insert, because FTS5 misbehaves otherwise. All writes go to the base table only; anything bypassing the triggers desynchronises the two permanently. `id == page` identifies a page row, which several ranking rules depend on. Validate that both id and page are uuid strings and **throw** on an invalid row rather than skipping — a silently dropped row is a permanently unfindable block. The index format version is written only after a complete successful rebuild.

**Transliteration.** The DDL and triggers are already SQL and copy near-verbatim; only the sqlite-wasm `.exec` wrapper changes to bun:sqlite (raw SQL for the virtual table, since Drizzle's typed schema does not cover it). Keep the memoised multi-row `INSERT … ON CONFLICT` builder batching 2000 rows in one transaction. Fix one thing rather than porting it: Logseq inlines quoted ids into `DELETE … WHERE id IN ('a','b')` — use bound parameters. The DDL goes into our forward-only numbered ledger with its ledger row in the same IMMEDIATE transaction.

**Risks.** Trigram FTS5 indexes are roughly the size of the indexed text, and this database already backs the orchestration event log under one WAL. Measure index size and write contention against a realistic vault, and seriously consider a separate SQLite file — Logseq runs three per graph for exactly this reason.

### Snippet windowing and term highlighting

**Algorithm to preserve.** Terms sorted **longest-first** and matched non-overlapping, so searching `foo foobar` does not let `foo` steal the position `foobar` needs; on collision advance one character; a term with no free occurrence is silently skipped. Marker splicing runs in **descending** index order so earlier indices stay valid. Window start scans backward to the last sentence-break character — with CJK punctuation (`，。；！？、`) in the break set — and begins after it. Only the first **two** matches get windows; more looks like confetti. Merge into one window when two matches are within 200 chars, split otherwise. The four-way outcome selection (fits / merged / prefix-already-shows-match-1 / match-1-straddles-the-prefix-boundary) exists so a highlight is never cut in half across an ellipsis. Boolean operator words are dropped from the term list first.

**Transliteration.** `(sort-by (fn [[order term]] [(- (count term)) order]))` sorts by a _vector_ key — write it as an explicit two-key comparator; it is the easiest line in the file to mistranslate. `re-matches` anchors the whole string while `re-find` does not; mistranslating that inverts several conditions. Replace the `$pfts_2lqh>$` sentinels with a structured `{text, ranges}` return — sentinels only exist because the value had to survive a transit round-trip, and our renderer already consumes ranges. This also deletes the strip-and-compare fast path.

**Risks.** Emitting ranges instead of sentinels means window arithmetic must translate offsets from the source text into the clipped snippet; an off-by-one there mis-highlights every result and is invisible in a test that only checks the text. Our existing `apps/web/src/features/search/utils/match-display.ts` (148 lines, single-window, no sentence boundaries, no multi-term) is the weaker incumbent and is replaced in the same pass, not kept alongside.

### Result fusion and ranking

**Algorithm to preserve.** Dedupe preserving first-seen order, because that order **is** each list's rank input. Merging duplicates takes the **max** of each score component, never last-writer. RRF: `Σ weight_i / (60 + rank + 1)`, keyword weight 1.25, vector weight 1.0. Deterministic final sort: score desc, then best rank asc, then id asc. The `1e-6 × rawScore` tie-break term exists only to order otherwise-equal results — the constants work at their current _relative_ magnitudes. Pages get a flat bonus only on the non-RRF path, because RRF already normalises across incomparable lists.

**Transliteration.** `reduce-kv` over a vector yields `(index, value)` — that is how RRF gets its rank; use `forEach` with its index. `(fnil + 0)` becomes `(map.get(id) ?? 0) + x`. `juxt` composite sort keys become one comparator. Until a second engine exists only the non-RRF branch is reachable; implement RRF anyway but behind the multi-list entry point, since a second engine is the entire reason the module has this shape.

**Risks.** Low. The main hazard is "tidying" the constants — no test would catch a rescaling. Add a comment stating the magnitude relationship, since that is exactly what the code cannot say for itself.

### Query-builder tree algebra

**Algorithm to preserve.** `[:and]` is the canonical empty tree and serializes to an empty query string. Removing the last clause of a group removes the group, recursively. `replaceElement` **splices** when the replacement is a collection whose head is not an operator — that is what makes unwrap work. `appendElement` rewrites the last index to one-past-the-end, which is how the `+` button always appends into the right group. Wrap and unwrap both special-case `loc == [0]`, because index 0 is the operator head, not a clause. A failed wrap or unwrap logs and returns the tree unchanged rather than throwing. Task values serialize as strings so multi-word statuses survive. The round trip is normalising, not textually identical.

**Transliteration.** `update-in`/`get-in` with vector paths become small `getAt`/`updateAt` helpers over a **readonly** nested array — type it readonly rather than copying containers to satisfy TypeScript, and allocate only where a real mutation happens. `subvec` splicing becomes `slice` + spread. `clojure.walk/prewalk` for both directions becomes a recursive map over the parser's AST, which **both** directions must share rather than defining a second tree shape. `{:pre […]}` assertions become guard clauses returning the unchanged tree plus a structured warn. The builder writes serialized DSL back into the note block, so debounce that rather than saving on every chip click.

**Risks.** Low individually, but this is the module that proves the parser's AST is bidirectional. Parser and serializer written against different shapes means every builder edit rewrites the user's query text in surprising ways. Build parser → serializer → algebra with a round-trip property test between the first two.

### Datalog rule library (reimplement)

**Algorithm to preserve.** The semantic contract of ~24 predicates: ref inheritance (`has-ref` matches a block whose _ancestor_ holds the ref, while `self-ref` is direct-only); `tags` expands to the tag plus all transitive `class-extends` descendants and excludes blocks carrying a link; the property-with-default family, where a class-declared property a block never set still matches when the queried value equals the declared default, and "has property" is satisfied by class declaration alone; the `public?` gate on simple-query properties and its removal for private-property; and the named-predicate → declared-dependency → transitive-closure structure itself, so predicates stay data with explicit deps rather than a pile of SQL string builders.

**Transliteration.** Each rule becomes `{ name, deps, build(args, ctx): SqlFragment }` in a plain registry. `extract-rules` + `get-full-deps` become a worklist closure over deps — **add the visited-set the Clojure omits**, since ours must not hang on a cycle. Recursive rules (`parent`, `class-extends`, `alias`) become named `WITH RECURSIVE` CTEs emitted once per query and joined, not per-predicate closures. `missing?` becomes `NOT EXISTS`; `get-else` with the `"N/A"` sentinel becomes `LEFT JOIN … WHERE value IS NULL`; datalog set args become bound parameter lists; `alias`'s two symmetric bodies become one `UNION ALL` over both directions. The three-body `tag-spec->tag` rule becomes one resolver in the resolve context, run at compile time, never in SQL.

**Risks.** This file decides what every query _means_, and a semantic miss is silent — the query returns fewer rows and nobody files a bug. Lift Logseq's `query_dsl_test.cljs` expectations as a black-box conformance suite over our own fixture graph. The recursive CTEs are the perf cliff SQLite has in place of DataScript's clause-ordering cliff: benchmark `has-ref` and `tags` against a 50k-block fixture before shipping.

### Simple-query → executable compiler (reimplement)

**Algorithm to preserve.** Dispatch order with first-match-wins (raw-clause passthrough, page-ref, string, boolean, between, property, task, priority, page, sample, tags). The **positional page-ref semantics**: at top level or inside an `or` it compiles to a direct self-ref; nested inside an `and` it compiles to an ancestor-inheriting page-ref — same syntax, different meaning by position, and load-bearing. The `::no-property-found` sentinel: an unresolvable property must match **nothing** (a null ident would match every property), while an unresolvable page drops its clause. Property value coercions and the default-value comparison that selects the `-with-default` predicate family. Task args capitalised per word vs priority args first-letter-only; `(task a b)` is OR, not AND. `sample` contributes no clauses and applies post-query. The `blocks?` flag is set in the prelude, before dispatch, so it fires even for forms that later return null.

**Transliteration.** The `*current-db*` dynamic var becomes an explicit `ResolveContext` parameter — keep resolve-at-compile-time, it is what makes queries fast, but not the dynamic binding. Out-param atoms become one mutable `CompilerState`. `(list 'symbol …)` datalog construction becomes a tagged IR (`predicate | and | or | not | all | raw`), which collapses the boolean shape-sniffing into a switch. The `(and [[a]] [[b]])` → append-`or` rewrite is a DataScript binding trick and must be **dropped**: our IR carries an explicit `all` domain node. Raw-datalog passthrough has no SQL analogue — either drop the feature or gate a raw fragment behind an explicit setting, but do not keep parsing the syntax and silently ignoring it.

**Risks.** Positional page-ref semantics is the trap: losing it makes nested queries quietly over-match, and Logseq's `nested-page-ref-queries` test depends on it. Compile-time resolution means a query compiles differently before and after a page exists — keep that, but make the empty-compile case opaque for invalidation or the query never recovers once the page is created.

### Query watch-dependency extraction (reimplement)

**Algorithm to preserve.** Conservatism expressed as an **allowlist**, never as a proof: only `between`, `block-content` and `page` are safe; every other predicate sets opaque, because class hierarchies and property configuration are invisible to an attribute scan. Opaque must also be set for a quoted full-text query and for a query whose compiled form is empty (otherwise it watches nothing and never updates when the missing page is created). The seeded baseline set (uuid, title, name, parent) is always included. The task carve-out earns both a global `['tasks']` key and per-attribute keys. An empty key set or opaque yields the watch-all sentinel.

**Transliteration.** `tree-seq` plus `keep` over qualified keywords becomes `walkIr(node, visit)` reading `predicate.name` and `predicate.attrs` directly — the information is explicit in our IR, so the whole analysis collapses to a short traversal. Keys become plain JSON tuples serialized to strings for Set membership. The advanced-query branch drops with raw datalog; symbols-vs-keywords disappears once rule and attribute nodes are tagged.

**Risks.** The failure mode is asymmetric and must stay that way — a missing key is a stale UI (correctness), an extra key is a wasted re-run (perf). Any refactor that makes the analysis "smarter" is therefore a correctness risk. Add a test asserting every newly registered predicate defaults to opaque unless explicitly allowlisted.

### Transaction → invalidation-key derivation (reimplement)

**Algorithm to preserve.** ~18 independent producers unioned together, never short-circuited. Consult **both** before and after state for anything identity- or membership-related, so an entity that stopped being a task still invalidates task queries. `refs` keys are emitted for the ref target in both states — that is what makes backlink panels update. `ref-scope` is emitted on any alias or class-tree change, because that changes _which_ pages' refs count and invalidates linked-reference views for a different page than the one edited. And the full `task-query-changed?` trigger list: a status value; block tags whose class transitively declares status; class-extends where either side declares status; class-properties naming the status property; ident / default-value / public? on the status property; title or value on a status closed value.

**Transliteration.** Datom filtering becomes a switch over our notes event types. Reads against `db-before`/`db-after` become either an event payload carrying the before-image (our log records causation and can carry one) or an explicit read inside the same transaction as the projection write, before it. Transducer chains become array pipelines into one `Set<string>`. Keep `attr`, `entity`, `refs`, `ref-scope`, `class-tree`, `tasks`, `task-attr`; the Logseq-domain producers (journals, comments, reactions, route-page) mostly drop.

**Risks.** The single largest source of "why didn't my query update" bugs, and every miss is invisible until a user complains. Because we lack datoms, the before-image discipline is genuinely new work and easy to skip — an event that does not carry one silently degrades its producer to "no key". Per the logging-first rule, emit the derived key set as a wide event on every notes transaction so a stale-UI report is diagnosable from `logs/`.

### Incremental search-index sync (reimplement)

**Algorithm to preserve.** Three attribute roles: **ref-affecting** (uuid, name, title, properties, alias) changes the indexed text of this block _and_ everything referencing it; **direct-visibility** (parent, page, order) changes the block's own breadcrumb; **page-hierarchy** changes a whole page subtree, because indexed titles embed the ancestor chain. Referrer expansion over reverse refs and aliases is why renaming a page re-indexes every block linking to it. Alias changes expand in **both** directions. Hidden status is computed before and after and compared, so a block that becomes hidden is removed even though its text never changed. Removals come from the before state, additions from the after state, deletions applied first. A block whose index result is now null joins the removal set rather than merely being skipped.

**Transliteration.** `:block/_refs` and `:block/_alias` reverse lookups become an explicit `block_refs(source, target)` join table indexed on target — the reverse index DataScript gives free is a schema decision for us. Entity-tree and page-descendant walks become `WITH RECURSIVE`. Before/after entity reads become a pre-image read inside the same write transaction.

**Risks.** Under-fanning is invisible: a stale row means a block stays findable under its old title forever and nothing surfaces it. Add a reconciliation pass that diffs index against source and reports drift as a wide log event. Alias-both-directions and page-move are the two cases most likely to be dropped in a first pass.

### Full-text search orchestration (reimplement)

**Algorithm to preserve.** Three cheap SQL strategies beat one clever one. Exact-title (`COLLATE NOCASE`) runs first, and if it fills the limit the FTS and fuzzy lanes are **skipped entirely** — this is what keeps typing an exact page title cheap. FTS5 trigram `MATCH` second. Subsequence `LIKE '%a%b%c%'` last, skipped when the query is multi-term and FTS already matched. In the fuzzy pass, pages are queried before blocks so pages win the candidate budget. `get-match-input` sanitization: map `and`/`or`/`not`/`|`/`&` to FTS operators, then wrap the whole thing as a quoted phrase whenever the query has a dangling operator or contains punctuation — user text must never reach FTS5 as syntax. Queries of ≤2 characters bypass the trigram index with a plain LIKE. A `/` also matches the last path segment. Direct page-title hits are prepended last so an exact page match cannot be crowded out. Dedupe twice: by id after fusion, by uuid after mapping.

**Transliteration.** `cond->>` pipelines become guard clauses. The per-pass try/catch keeps its shape but uses structured errors plus one wide log event per search carrying per-strategy row counts and durations. The four-way bind-order helper disappears with parameterized queries. Replace Logseq's fuzzy scorer with our `fuzzyRankScore`. Vector/embedding lanes and RRF are out of scope for the first pass.

**Risks.** FTS5 sanitization is the security-adjacent part: unescaped user input inside a `MATCH` expression is a syntax error at best and a pathological scan at worst — fuzz it. Lane skipping has semantic teeth: a bad exact lane poisons the whole result set with no visible symptom.

### Search index document construction (reimplement)

**Algorithm to preserve.** Reject closed property values, blank titles, and titles over 10k chars. Prefix the block's title with its **ancestor chain** so nested blocks are findable by context. Resolve `[[uuid]]` refs to titles **before** indexing — that is what makes searching a page name find blocks that merely link to it. Append the journal day for journals and alias titles for pages, recording which alias matched. Preserve original casing for pages and objects (the UI renders the indexed title directly) while NFKC-normalising and accent-stripping non-page blocks. Treat "no longer indexable" as a removal, not a skip.

**Transliteration.** `cond->`/`some->` threading becomes guard clauses with early returns. Entity predicates become SQL predicates in one `WHERE`. The per-block try/catch goes through `createStructuredError` plus one wide log event carrying the block id. `:include-vector-title?` and everything downstream drops with semantic search.

**Risks.** The ancestor-chain prefix is a coupling most people miss: a block's indexed text changes when an _ancestor's_ title changes, which is exactly what the sync module's page-move fan-out handles — build the two together. The casing asymmetry looks like an inconsistency worth tidying and is not; tidying it breaks result display.

### View data pipeline (reimplement)

**Algorithm to preserve.** Closed-value sorting compares the value's **position**, not its title. Date-typed properties sort by the underlying integer day, never a formatted string. Many-cardinality properties: SUM for number/datetime, `', '`-join otherwise — applied consistently or two rows with the same values sort differently by element order. `count` is the **filtered** count, not the returned page's length. A row whose group-by property is multi-valued appears in **every** matching group. Group keys order by a secondary property with non-journal pages after all journals. The `empty` predicate treats null, empty collection and empty string identically. Ref-valued filters match by target entity id, never rendered title. Sorting must be total, with the tie-break written into the comparator.

**Transliteration.** `partition-by` over a lazily sorted seq for major/minor sorting becomes a single `ORDER BY a, b, c` — the whole two-phase sort disappears, and with it the >10,000-row datom-index fast path (which was silently dropping rows with no datom for the attribute, so its absence is a bug fix). `memoize` on the value extractor disappears; the extractor was hitting the DB, ours is a column. The entity-vs-plain-map duality is deleted by normalising to row DTOs before this layer.

**Risks.** `LIMIT` interacting with a JS-side filter is the failure mode: paginate only after every filter has applied, or pages silently lose rows. Skipping this module entirely and letting each caller write its own SQL is how you end up with five subtly different sort orders across query results, backlinks and all-pages. Multi-valued group fan-out is the rule most likely to be missed, because a naive `GROUP BY` silently picks one value and looks correct.

### Boolean clause assembly (reimplement)

**Algorithm to preserve.** Exactly two things. De-duplicate child clauses **preserving first-seen order** — never via a hash set, because clause order is an evaluation-order contract and, for negation, a correctness one. And inside an `and`, all negative clauses come after all positive ones, so a negation is always evaluated against an already-bound domain; in SQL that is the difference between a correlated `NOT EXISTS` and a full anti-scan.

**Transliteration.** Roughly two thirds of the function exists to satisfy DataScript's `:where` grammar (collection-vs-list shape sniffing, conditional outer-vector wrapping, unwrap-single-and) and is **deleted, not translated**. `build-and-or-not-result`'s branching becomes a `switch (node.kind)` over the tagged IR; `collect-vars` is unnecessary because IR nodes declare their own dependencies.

**Risks.** Small module, but the not-after-positive ordering is easy to lose in a rewrite and its symptom is a slow query rather than a wrong one — it will never show up in a test, only in a profile. Assert the ordering on the emitted IR directly. Worth recording as a capability we gain: `(or (priority a) (not (priority c)))` is documented as not working upstream because the compiler never emits `or-join`/`not-join`; ours gets it free.

### Unlinked references (reimplement)

**Algorithm to preserve.** A block counts as an unlinked mention when its title contains the page title case-insensitively **and** it does not already reference the page, is not a link block, and is not built-in. Matching is substring, so mid-word hits are expected behaviour and must not be quietly "fixed" into word matching without a deliberate decision. The section stays lazily mounted behind a cheap existence check.

**Transliteration.** The full-index `:avet :block/title` datom scan is rejected outright: it becomes `SELECT id FROM blocks_fts WHERE title MATCH ?` minus a `NOT EXISTS` against `block_refs`, with the existence check collapsing into the same query with `LIMIT 1` — which also fixes the upstream bug where the existence check and the full list use different engines and can disagree.

**Risks.** Trigram FTS needs three characters, so a two-character page title finds nothing through FTS and needs the LIKE fallback the orchestration module already carries. FTS5 phrase matching is token-based: verify against substring semantics on a fixture set, and if they diverge make FTS the candidate generator with an explicit substring filter.

### Search index build (reimplement)

**Algorithm to preserve.** One build per graph at a time, with a build id checked each iteration so a newer build silently supersedes an older one — a superseded build is not an error and must not be logged as one. The index format version is written only after a complete successful rebuild. Progress is monotonic and emitted only when the integer percentage changes. Worth keeping from the embedding path even without embeddings: on a batch failure, binary-split and recurse so one poisonous document is isolated rather than the whole batch lost.

**Transliteration.** Half the module exists because the index is built in a browser worker sharing a core with the UI — the 8 ms budget, the event-loop yield, the input-idle poll with its 2000 ms fail-open TTL. All of that is deleted; the graph runs in a Bun process, so it becomes batched transactions with an `await` between them. Progress goes out as a wide log event plus a subscription frame.

**Risks.** The build-id supersede check is load-bearing: without it two concurrent rebuilds interleave writes into a truncated table and produce a half-empty index that looks fine. A full rebuild also puts sustained write pressure on the same SQLite file as the orchestration event log — measure the impact on chat latency, or move the index to its own file.

### Content ref conversion (uuid ⇄ title)

**Algorithm to preserve.** `sortRefs` descending on `[hasNestedBrackets, title]`, applied **identically in all four directions**; tag-form replacement strictly before bare-form; the `(^|[^#])` page guard and the `(^|\s|\()…(?=[,.\)]*($|\s|\)))` tag guard; the `if (!ID_REF.test(content)) return content` bail-out; a BFS `seen` set plus fixpoint check so mutual block refs terminate; and the total-on-strings rule — an unknown uuid is left verbatim, never dropped.

**Transliteration.** `sort-by f >` over the heterogeneous vector `[boolean string]` needs an explicit comparator (`true` before `false`, then `b.title.localeCompare(a.title)`) — do not rely on JS default sort. `(?i)` inline flags do not exist in JS: build with `new RegExp(src, 'i')`. `loop`/`recur` fixpoint becomes `while` with a `prev !== next` check capped at `maxDepth`. The single db dependency — the same-name page count behind `replacePagesWithSameName: false` — becomes an injected `sameNamePageCount(title)` callback so the module stays dependency-free and testable in contracts. Refs arrive as frozen `{uuid, title, isPage}` DTOs.

**Risks.** Silent data loss is the failure mode: a wrong sort or a dropped guard rewrites a substring of the wrong title and there is no undo at the storage layer. Mitigate with a property test asserting `titleRefToIdRef(idRefToTitleRef(x)) === x` over generated titles including nested brackets, spaces, `#`, and prefix pairs (`Foo` / `Foo bar`). If we forbid `#` in titles outright (validation already does), the `HashTag-` escape branch is dead code and should be deleted rather than ported, or it silently mangles a legitimate `HashTag-` substring.

### Page delete and ref rewriting

**Algorithm to preserve.** The exclusion set: drop the page itself and every ref whose _owning page_ is the page being deleted, **before** computing any rewrite. The single-collector rule — the mutation batch and the replayable ops both derive from one `pageRefRewriteTargets()` call, so they cannot diverge. Title update and ref-row deletion land in the same transaction. The four-way dispatch: built-in refuses, today's journal **truncates** (blocks retracted, page entity kept, so the auto-creator cannot race it), class/property hard-delete, everything else recycles.

**Transliteration.** `:block/_refs` reverse navigation becomes `SELECT block_uuid FROM block_refs WHERE ref_uuid = ?` — the reverse index DataScript gives free. The `:avet` scan for stripping a deleted property from every node becomes `DELETE FROM block_props WHERE property_ident = ?`; re-rooting subclasses becomes an `UPDATE`. `[:db/retract …]` vocabulary becomes our own tagged mutation union applied inside one `db.transaction()`. The `save-block` ops appended to tx-meta become events on the same aggregate stream, so replay and undo see ordinary block edits rather than an opaque delete side-effect.

**Risks.** A crash between the title rewrite and the ref-row delete leaves phantom backlinks, so it must be one SQLite transaction — trivially available to us, unlike DataScript. Property and class deletion are irreversible by design (no Recycle), so a single shared confirm dialog will promise a trash can and lose schema; wire the dispatch decision into the confirm copy as Logseq does.

### Linked references with filters

The only addition from this sweep: the unlinked-mentions half must **not** be ported as written — it is an unindexed `:avet :block/title` full scan, survivable upstream only because the UI first asks a capped existence question. Back ours with FTS.

### Render-resource subscription engine

**Algorithm to preserve.** A resource key is a serializable, structurally comparable tuple — functions and live entity handles are rejected at the boundary, which is what stops a db handle being closed over in a cache key. **Watch keys must over-approximate what was read**: the full closure — target, every ancestor, and every ref whose title got embedded in a label. `getSnapshot` must be referentially stable or `useSyncExternalStore` loops. Status is four-valued: `missing` (page not found, renders an empty state) is distinct from `loading`. Slot merges from different sources assert equality on collision. The projection cache recomputes only on source identity change, then reuses the previous projected value if equal.

**Transliteration.** Keyword-headed vectors as first-class cache keys with structural equality is the biggest friction: define `slotKey(kind, ...args): string` producing a stable joined string and key every Map by that, never by object identity. `def-thread-api` worker RPCs become typed handlers on our existing WS RPC, with resource subscription joining `subscribeShell`/`subscribeThread` as a third variant; the comlink hop and transit codec disappear. Multimethod-ish dispatch becomes `Record<ResourceKind, ResourceRenderer>`. `identical?` becomes `Object.is` over frozen objects. Keep TanStack Query off this path.

**Risks.** The failure mode is stale UI with no error — the hardest class to notice in review and the easiest to misattribute — so watch-key derivation needs a test per resource asserting a rename three levels up invalidates a breadcrumb. Our transport is a WebSocket rather than a `postMessage`, so the latency floor per uncached read is higher and the warm LRU must absorb it; size and measure that cache rather than copying the 5000-entry constant blindly. Request limits (1000 blocks / 25 children / 25 resources per batch) exist for a reason — forgetting to batch a large page surfaces as a mysterious cap rather than an error.

### Page creation with namespace splitting

**Algorithm to preserve.** The step order: sanitize before validate; probe for an existing page by **both** title-and-types and journal-uuid before deciding to create; resurrect a recycled page rather than duplicating it; split the namespace only for non-journals; assign the deterministic uuid **last** so it overrides the generated one. `create` stays **pure** — it returns mutations and never writes; a thin `create!` transacts. Creating an existing page is idempotent and returns the existing uuid so the caller can navigate. Every non-journal root page is parented to Library, so "no parent" stays a reliable marker for journals and built-ins. Namespace chains never mix pages and classes — an existing page where a class was wanted is dropped, never silently converted. Journals are exempt from the `/` validation.

**Transliteration.** `de/entity?` distinguishing a live entity from a plain tx map is load-bearing in three places, and TS needs an explicit tagged union (`{kind:'existing'…} | {kind:'new'…}`) — this is the likeliest transliteration bug, since both shapes have `uuid`. `map-indexed` with backward peeking becomes a plain indexed loop. The datalog parent-name lookup becomes a join with an index on `(parent, name)` — which is also what makes `a/x` and `b/x` legally coexist. `ex-info {:type :notification}` becomes `createStructuredError` with code/status/why/fix, surfaced as a toast.

**Risks.** Idempotence: a create path that misses the existing-page probe produces duplicate journals under concurrent tabs, and because journal uuids are deterministic that surfaces as a primary-key conflict — so make the uuid the PK. `create` returning mutations without writing is easy to erode; the first caller that transacts inside it makes the function untestable and unbatchable. The tag-parsing pre-processing lives in the _caller_ upstream, so porting `create` alone leaves `#` titles failing validation with a confusing message.

### Page title validation rules

**Algorithm to preserve.** Validators **throw and abort before any mutation**, so they compose in front of anything. Journal titles are the sole exception to the `/` rule, expressed by consulting the date parser rather than a flag. The rule that carries a whole user-visible feature: uniqueness is **suppressed** when the only tag two same-named pages share is the generic `Page` marker and both carry more than one tag — that is what makes "Apple #Company" and "Apple #Fruit" possible, and deleting it stops same-name pages working with a confusing duplicate error. Parent-scoped uniqueness lets the same title live in different namespaces. Removing `#Page` from a page is refused when it has no parent, when its parent is Library, or when it has page children. Class-extends cycles are checked against each child's structural descendants.

**Transliteration.** Three literal datalog queries selected by a `cond` on entity shape become three parameterized lookups — note the parent-scoped variant joins the candidate's parent against the subject's parent, which is easy to drop when flattening to one query. `ex-info` maps become `defineErrorCatalog` entries with structured fields rather than a formatted string, so the toast can name the conflicting tags without string surgery. The class-descendant check becomes a recursive CTE, natively cheaper than the datalog rule Logseq hand-tunes.

**Risks.** `normalizeDate(title, null)` runs the **full 28-formatter path**, so character validation is expensive and is invoked from a rename field that a UI will naturally call per keystroke — keep the skip-for-known-journals shortcut or debounce to commit. These validators are also the only thing standing between content-ref conversion and a title containing `#`; relaxing the rule later without handling the escape starts mangling text.

### Recycle bin

Same module as [Recycle](#recycle-soft-delete-exact-position-restore-30-day-gc) under the data-model domain; that section carries the prose. Two additions from this sweep: permanent delete and GC must expand a page root to its full page-tree **and** each page's block subtrees, deduped, or entities leak invisibly — assert row counts before and after. And the 30-day sweep runs against a `deletedAt` index; without it, it is a daily full scan.

### Breadcrumb segments and visibility budget

**Algorithm to preserve.** Segments arrive **root-first**. Dedupe by `uuid ?? id` happens _before_ budgeting, because the page can appear both as the page segment and as the first ancestor. `keepFirst = 1`, `suffixCount = min(nearestCount, total - 1)`, hidden = the middle slice — plus the rule that if exactly one segment would be hidden, show it instead of an ellipsis and report `overflow: false`. `hidden` must be exactly the complement of prefix+suffix, since the dropdown recomputes it from a deeper fetch and the two must agree. Each segment carries `titleRefIds` so the renderer knows which refs its label depends on. Per-variant budgets and `loadDepth` (block page 4/2, header 4/1, search 3/1, inline 3/1) are tuned data that costs nothing to take.

**Transliteration.** The `re-matches` (whole string) versus `re-find` (substring) distinction is deliberate and is the easy porting bug — `RegExp.test` has `re-find` semantics, so every `re-matches` site needs explicit anchors. `case` on a keyword becomes a switch over a string-literal union; `subvec`/`take-last` become `slice`. The ref-title resolution inside label normalisation calls into the content-refs module at depth 10, which is why this lives in contracts alongside it. `withBreadcrumbRefTitles` patching a partially-hydrated entity becomes a plain merge of a `Record<uuid, title>`.

**Risks.** Reversed segments produce backwards breadcrumbs that look plausible in a two-level test and wrong in production — assert root-first explicitly. The markdown stripping is regex-based and deliberately does not parse, so nested emphasis degrades gracefully; someone will "improve" it by routing it through mldoc, which is a server round-trip on a label that must render synchronously. Note that intent in the code.

### Favorites as ordered graph blocks

**Algorithm to preserve.** Favorites go through the same insert/delete/save block operations as ordinary edits, so they participate in undo and history for free — a raw write silently loses that, and nobody notices until a user complains Cmd-Z skipped a step. One favorite block per page; the toggle checks state before acting. **Reorder permutes link targets** against the existing ordered blocks rather than rewriting order keys: zip the desired order against the existing blocks in their current order and rewrite only the targets that differ, so the skeleton and its keys stay put and cost is O(moved positions). Order is read from the sort-by-order-key pass, never from insertion order. Recycled targets are filtered on read.

**Transliteration.** `def-thread-api` worker RPCs become typed route handlers. The zip in `reorderFavorites` relies on Clojure's `map vector` shortest-wins semantics, which silently truncates a mismatched list — in TS assert the input is a permutation and throw a structured error, because the silent truncation is a data-loss path we should not inherit. Fractional keys come from our existing `order-key.ts`.

**Risks.** The reorder trick means a favorite's block uuid follows the **position**, not the page — anything ever keyed on that uuid (a comment, an annotation) would attach to the wrong favorite after a drag. Fine today, a trap later; record it in a comment.

### Graph layout engine

**Algorithm to preserve.** Mode selection thresholds (2500 all-pages, 10000 tags) and the full constant table as _data_, not numbers to round: golden-angle spacing, `radius = 15*sqrt(rank)`, ring gap 58 / node gap 42 / capacity `max(14, floor(2πr/42))`, angle offset `ring * 0.41` so rings do not visually align, charge −95/−180/−140 and link distance 58/118/82 per mode, tick counts 160/130/110/90/70 with a deliberate **3** for large tags graphs because cluster seeding already did the work. The simulation is stepped **manually** (`.stop()` then N ticks) so layout is synchronous and deterministic — never leave d3 running its own timer. `idx` on each simulation node is the index into the possibly-bounded input array and is how results map back. Grid mode duplicates a multi-tag object into K visual nodes with a `sourceId` back-pointer, and `displayLinks` **must** rewrite endpoints to the matching visual copy. Every node ends with finite x/y.

**Transliteration.** The cheapest port in its domain: the Clojure is already JS-interop-heavy (`#js` literals, `set!`, `js/Map`) and d3-force is a JS library. `#js` literals and `set!` become plain object literals and property assignment — and note that d3-force **mutates node objects in place**, so these must not be frozen; this is the one place the frozen-object discipline (S5) is deliberately suspended, and it should say so in a comment. `PersistentQueue` becomes an array with a head index (never `shift()` in a loop). `juxt`-based sort keys become chained comparators. Colours come out entirely — emit `kind` and let the component resolve theme tokens.

**Risks.** This is the module most coupled to Logseq's visual identity: a faithful port reproduces its look, which is a product decision the constants make for you. Grid mode returns before simulating, so its output is final — a later "let's also run a few ticks" change silently breaks the visual-node id contract. The reference renderer is PIXI (2677 lines, not a port target), so pairing this layout with a different renderer means the trailing node-radius and colour-as-int decoration should be stripped rather than translated.

### Graph settings persistence and client-side filters

**Algorithm to preserve.** A no-op filter returns the **identical** input object — reference equality is load-bearing, because the renderer distinguishes "no filter, render everything" from "filter to this set" by identity, and a rewrite that returns a fresh object every time silently does full work on every frame. `selectedTagIds: null` (all) and `[]` (none) are different states, and stored ids are intersected with currently-available tags on read so vanished tags do not linger. Every filter preserves "no link references a missing node". Time travel prefers the derivation's reported created-at range over scanning nodes and hides itself when the duration is not positive. Per-mode data cache with separate loading and error state plus a cancellation flag so a graph switch mid-fetch discards its result.

**Transliteration.** `identical?` versus `=` maps exactly to `===` on objects — that distinction is the point of the module, so comment it at each early return. **Delete the localStorage layer entirely:** `logseq.graph.settings.<repo>` and its try/catch-returning-defaults become `defineSetting` entries whose valibot schemas do the clamping the hand-written decoder did (depth 1–5, linkDistance 36–180, viewMode enum). Validation moves from read-time to schema-time, which is strictly better and is house policy. Note the scope rule: none of these values reaches execution, so `window` scope is legitimate here, unlike most knobs. Regenerate `docs/settings-reference.md` after.

**Risks.** The identity contract is fragile under refactoring — any well-meaning `return {...data}` cleanup breaks it silently. Guard with a test asserting `filterTags(data, allTags) === data`. Toggling one tag on a 50-tag graph materialises and writes all 49 others, which is fine in localStorage and less fine as a synced settings write; consider storing the _excluded_ set instead.

### Journal date parsing and formatting (reimplement)

**Algorithm to preserve.** `journalDay` is a **local** calendar day int, and every conversion goes through local-time constructors (`new Date(y, m-1, d)`), never UTC — midnight-adjacent journals land on the wrong day otherwise. The canonical lookup name is always the **default**-format rendering, independent of the display format, so changing the date format never orphans a key. Formatter precedence: user format first, then defaults. `capitalizeAll` before parsing. Parse failure returns null and falls through; it never throws. `dd.MM.yyyy` stays excluded — it mis-parses `2022Q4` and `2022/10`.

**Transliteration.** cljs-time is a goog.date/Joda wrapper whose pattern letters are near-misses against date-fns (`do`, `EEE`, `yyyy` vs `YYYY`), so this is a rewrite regardless — port the 28-format list by hand as data and add a test asserting each token round-trips a known date. `Intl.DateTimeFormat` cannot emit ordinals, so `do` requires date-fns or a hand-rolled suffix table. `memoize` on a 3-arg fn becomes a Map keyed by `` `${day}|${format}` ``. The graph-level format is threaded explicitly as a parameter, since this module stays pure. Reimplementing also lets us fix the documented `3/4/5` acceptance bug rather than faithfully reproducing it.

**Risks.** Timezone is the whole surface: a single UTC constructor shifts the journal boundary by up to a day for users east or west of the line, and the bug only appears near local midnight, so it survives every daytime test. Pin tests to non-UTC zones at both ends of the day. The 28-formatter path is genuinely slow and must never be reachable from a render or keystroke path — keep the cheap 4-formatter function as a separate export and name the expensive one `slow`.

### Deterministic UUID generation (reimplement)

**Decision conflict to resolve first.** The data-model sweep argues to [port this verbatim](#deterministic-uuids) for Logseq-graph interoperability; this sweep argues to keep the journal half exactly and **deliberately diverge** on the hash half, because `gen-block-uuid` depends on Clojure's Murmur3-derived `hash` and reproducing it bit-for-bit is only worth doing if we import Logseq graphs — which greenfield says we do not. Pick one knowingly: the divergence is a one-way door that makes any future Logseq import need a translation table.

**Algorithm to preserve.** The type-prefix scheme — 8 hex chars making an entity's kind readable off its id — and its permanence: once a prefix ships it never changes. `journalPageUuid(day) = 00000001-YYYY-MMDD-0000-000000000000` exactly, with the `0 < day < 100000000` precondition and right-padding so generated fields stay hex-valid. Idempotent template splice: journal-day segment plus template-block tail.

**Transliteration.** Keep `journalPageUuid` character-for-character — decimal string slicing, nothing to diverge on. If diverging, replace Clojure `hash` with a pinned, documented 32-bit hash (FNV-1a over the UTF-8 bytes, ten lines) and record in a comment that the choice is frozen forever, since changing it re-identifies every built-in page. `Math/abs` on a negative hash collapses ±n to the same id — keep that or use an unsigned hash and note the divergence. `d/squuid` (timestamp-prefixed, for index locality) becomes `crypto.randomUUID()` unless a benchmark shows the SQLite primary key benefits.

**Risks.** A right-padded hash producing a non-hex character would yield an invalid UUID string; the decimal-source guarantee makes this safe only if the hash is stringified as decimal, so assert `/^[0-9a-f-]{36}$/` over a few thousand generated idents.

### Latest-journals query (reimplement)

**Algorithm to preserve.** Descending journal-day order **is** the scroll order — the UI never sorts. Future-dated journals (created by templates and scheduled items) are excluded by comparing the day **value** before any hydration. Recycled journals are filtered here, not in the index. The result is uuids, never entities, so the list can virtualize without holding the graph. `today` is a local calendar day, so the boundary flips at local midnight — the same instant the auto-creator fires.

**Transliteration.** Twenty lines become one statement with an index on `journal_day`. `rseq` on a vector is O(1) and lazy; the equivalent is `ORDER BY journal_day DESC`, **not** `.slice().reverse()` on a materialized array — reversing a 10k-element array per render is the naive translation. Duplicate `journalDay` values are impossible for us if the journal uuid is the PK, so delete the dedupe step rather than porting it.

**Risks.** Missing the index turns the home screen into a full table scan on every invalidation. Emitting entities instead of uuids defeats virtualization and is the natural thing to do when the ORM makes joins easy — the whole point is that the list holds ids and each row subscribes to its own slot.

### Graph view derivation (reimplement)

**Algorithm to preserve.** Link dedup is ordered and **patch-in-place**: at most one edge per ordered `(from,to)` pair; a repeat pair upgrades the existing entry (sets the more specific edge type, fills in a label) rather than appending. A→B and B→A remain two edges. Orphan visibility is computed **after** link collection from the full linked-page set, never from a possibly-truncated link list — hence the two-phase approach on the large path; one-phase makes orphan-hiding depend on which links happened to fit under the cap. Recursive label resolution stays depth-bounded at 10 because ref cycles exist. A final pass drops links whose endpoints are no longer in nodes: nodes and links must agree or the renderer faults. Local graph's second-degree pass (edges among the neighbour set) is what makes it look like a neighbourhood instead of a star. Degree is counted from the **final** link set on both endpoints, feeding `size = floor(8 * max(1, cbrt(degree)))`.

**Transliteration.** 1049 lines of index-scan optimisation become three queries and a fold: `d/datoms :avet` becomes indexed SELECTs, `d/pull-many` becomes one batched `IN (…)`, the parent/extends fixpoint becomes one `WITH RECURSIVE`, `transient`/`persistent!` becomes a plain Map. Three things to fix rather than copy: parameterize the **one** visibility function over an accessor instead of shipping the entity-based and id-based twins; move `pageGraphNodeColor` out of derivation entirely (dark theme is currently an _input_, so node colour is baked at build time and a theme change forces a full rebuild); and drop the `uuid-or-asset?` label filter, which launders upstream data bugs at the presentation layer.

**Risks.** The 20,000-link cap truncates **silently** while still counting truncated links toward orphan-ness — reproduce that pairing or the large-graph view fills with false orphans, and emit the total so the UI can say "showing 20,000 of N". The 10,000-page threshold switches algorithms entirely, so the fast path is what ships to real users while the slow path is what gets tested. Without a fixture graph exercising cycles, aliases, self-references and excluded subtrees, the ancestor walks hang on the first corrupt row. Running derivation server-side means a 10k-node graph crosses the wire as JSON — measure this payload specifically, since S6 defers a binary codec until measured.

### Page routing and redirect resolution (reimplement)

**Algorithm to preserve.** Alias resolution happens **before** recents recording, or the recents list fills with alias pages the user never saw. The access guard (hidden-and-not-property, or built-in-and-private) runs before any navigation side effect, with the Recycle-page and dev-build carve-outs. Uuid form is preferred over title form in the address because titles change; the title form exists only for legacy links. Replace-not-push after a rename, so the pre-rename identifier is not left in history.

**Transliteration.** We have no router by explicit design, so "routes" are document-id prefixes plus the address projection and classification tables, which already solve URL encoding, push-versus-replace, and what is addressable. Reitit route keywords become our typed document tokens, which need a new letter in **both** halves of the codec. The 200 ms anchor delay and 100 ms scroll-restore timeout are empirical waits for a virtualized list to settle — do **not** port them; our editor exposes real measurement callbacks, and copying the polling reproduces a known bug class.

**Risks.** Adding a `note:` document kind is a checklist, not a registration: render branch, all three predicates in `file-backed-document.ts`, four sites in `workspace/utils/tab-model.ts`, `pathForWorkspace`, both halves of the token codec, the palette label, and an opener on `createEditorCommands`. Miss one and the failure is partial and silent — persists but is not addressable, or addressable but does not restore. Whether a note is an editor tab at all is an unsettled product question; if notes become a third `WorkspaceUiMode` instead, this module's target changes entirely and all seven `uiMode` consumers must be updated in one pass.

### PDF highlight coordinate system and rect optimisation

**Algorithm to preserve.** A persisted rect is `{x1,y1,x2,y2,width,height}` where the coordinates are absolute in the **capturing viewport** and width/height are that viewport's dimensions — the pair is what makes it resolution-, zoom- and DPI-independent, and neither half is meaningful alone. `optimizeClientRects`: sort by top then left; drop rects strictly inside another; then **three passes** merging same-line (`|dTop|<5 && |dHeight|<5`) rects that overlap or are within a 10 px gap, extending A's right edge to B's and removing B. Three passes, not a fixpoint. `fixSelectionTextBreakline`: replace newlines with a sentinel, then `'-'+sentinel → ''` (rejoin hyphenated line breaks), then sentinel-followed-by-a-Latin-letter → single space, then remaining sentinels → `''` (CJK needs no space).

**Transliteration.** Almost nothing to translate — the cljs layer is only bean marshalling and disappears. Add TypeScript types for `ScaledRect`/`ViewportRect` and **document that `optimizeClientRects` mutates the rect objects it is handed**, or a caller will pass live DOMRect-derived objects and be surprised. Keep the `usePdfCoordinates` branch only if we actually persist PDF-space coordinates; otherwise delete it and the old-format throw with it.

**Risks.** Provenance must be confirmed once more before merging — this reads as agentcooper/react-pdf-highlighter verbatim (the "You are using old position format" throw, the 5 px/10 px tolerances, the extendWidth formula) with no Logseq copyright header, but "looks identical" is not a license audit; carry the MIT notice in the file header. Inherited behavioural risks: the tolerances merge across a narrow column gutter in tightly-set documents, three passes can leave leftovers on a pathological run of tiny rects, and the de-hyphenation heuristic destroys legitimately hyphenated words ending a line. Placing this in the Editor repo is a judgement call (the `panes` package already proves that repo hosts non-editor DOM utilities); `packages/pdf-annotate` in the platform is equally defensible.

### Property/class registry (reimplement)

**Algorithm to preserve.** Three things, and getting the two indirections right matters far more than the field names. (1) A closed value may carry a boolean `choice-checkbox-state`, so the checkbox UI and the repeat engine ask "which choice is flagged true/false?" instead of comparing to a literal `done` ident — that is what makes user-defined status sets and user-defined two-valued properties work with zero extra code. (2) Property identity is a **stable string ident, never a numeric row id**; Logseq's own comment says leaking numeric eids corrupts the shared op log, and the same is true of our event payloads. (3) `valueType` (ref vs scalar) and cardinality live on the property entity **as data**, so the storage layer branches on data rather than a hardcoded switch.

**Transliteration.** The Clojure map becomes a `const NOTES_PROPERTIES = { … } as const` table mirroring `packages/contracts/src/settings/registry.ts`, with valibot schemas per value type and the key union derived from the table. `:db/ident` keywords become dotted string idents; closed values become a readonly array of `{ident, label, icon, checkboxState?}`. `:db/valueType`/`:db/cardinality` do **not** become a DataScript schema map — they become columns on a `note_properties` row read by the EAV accessor (S2). `:queryable?` becomes "does this property get an index on `(property_ident, value)`".

**Risks.** The temptation is to shortcut the closed-value indirection ("status.done is just the string done") — that silently kills user-defined statuses and the repeat engine's checked-property feature, and retrofitting is expensive because call sites accumulate literal comparisons. Also: our settings registry is a _user-preference_ registry with a documented scope security boundary; note properties are _data schema_. Do not merge the two tables — a note property must never be able to reach execution the way a settings key can.

### Repeating-task scheduler and post-transaction command engine (reimplement)

**Algorithm to preserve.** The three org repeater semantics exactly. `.+` = `now + n*unit`, anchored to completion. `+` = `scheduled + n*unit`, which may land in the past and stack overdue — documented behaviour, not a bug to fix. `++` = `periods = scheduled > now ? 1 : max(1, countUnitsBetween(scheduled, now))`, `delta = ceil(periods/n)*n units`, `candidate = scheduled + delta`, then `while (candidate <= now) candidate += n*unit`. Unknown or absent type falls through to `++`. Arithmetic must be **UTC and add whole units** — that is what preserves day-of-week for weekly repeats by construction, with no weekday fix-up. `frequency <= 0` must be rejected before the loop or advance-until-future spins forever. Both scheduled and deadline advance together when both are set, preserving their offset. The completion cycle ends with status back at todo **and** a strictly-changed temporal value, in the same transaction so undo covers both halves. The engine shape is also worth adopting: pure `db → txData` reactions composed in a table beat scattered side effects.

**Transliteration.** `defmulti handle-command` becomes `const ACTIONS: Record<ActionId, (ctx) => NoteEvent[]>`. DataScript datoms have no equivalent, so the engine needs a change feed emitted from the command handler as `NoteChange[] = {blockId, propertyIdent, value, added}` grouped by block. cljs-time `t/plus`/`t/in-weeks` become date-fns with **every call in UTC** — a local-time port reintroduces the DST bug the file version had to hand-patch. Journal-page materialisation becomes "ensure the daily note file exists". Actions stay pure and **must not transact themselves**, which is what keeps undo atomic. Fix the bug on the way in: frequency resolution uses `(or [A B] [C D])` where any 2-vector is truthy, leaving migrated tasks with no frequency — write an explicit if/else.

**Risks.** Timezone is the whole risk surface, and a TS port reaching for local `new Date()` arithmetic passes every test written on a Tuesday afternoon and drifts across DST. Our projection pipeline runs a single named projector, so a notes reaction engine needs its own registration — and if a reaction's output is appended asynchronously rather than in the same transaction, undo splits in half and users see a task tick Done then jump to Todo as two separate undo steps. Month arithmetic clamps (Jan 31 + 1 month), which is exactly why the trailing while-loop exists; do not "simplify" it away.

### FSRS integration layer (reimplement)

**Algorithm to preserve.** The storage split: `due` lives in its own indexable property as epoch ms and is **removed** from the state map, while `lastRating` is added to it — deserialise by re-attaching due. The default card for a `#Card` block with no state uses the block's `createdAt` for **both** `lastRepeat` and `due`, so an old block newly tagged is immediately due and old cards do not all collide at "now". The due query treats **missing** due as due, which is how never-reviewed cards enter the queue with no write — and it must agree with the default-card rule or cards flicker in and out. Rating re-pulls the block fresh before computing. The reveal machine: `init → hasCloze ? showCloze : showAnswer`; `showCloze → hasCloze ? showAnswer : init`; `showAnswer → init`, with rating buttons shown only when `next(phase) === init`.

**Transliteration.** The one genuinely hard algorithm is not Logseq's — cljc-fsrs is external and MIT, and `ts-fsrs` supplies scheduling. tick Instants become epoch ms converted only at the library boundary. The datalog `or-join` with a `missing?` predicate becomes `WHERE due IS NULL OR due <= ?`. Deck subclassing (`get-structured-children`: descendants of `#Card` count as cards) becomes a recursive CTE — one of the wins S1 bought. The deck filter concatenating query-DSL where-clauses becomes `AND (<compiled deck predicate>)` in the same statement.

**Risks.** Two small behaviours are easy to drop and both produce confusing UX: the rating buttons defer their click ~10 ms and stop pointerdown propagation, without which the click lands on the block underneath and starts editing the card being reviewed; and the due-count poller must cancel its previous interval on remount or intervals stack. `ts-fsrs`'s card shape is not byte-identical to cljc-fsrs's, so any future Logseq-graph import needs a field-level mapping written against ts-fsrs's actual type.

### Asset ingestion pipeline (reimplement)

**Algorithm to preserve.** SHA-256 of the bytes as lowercase hex, computed **before** any write; if an asset block already carries that checksum, refuse the write entirely and name the existing asset — a hard refusal, not a silent link-to-existing. The on-disk name is always `<block-uuid>.<ext>`, so renaming the title never touches the filesystem — that is what makes titles free and sync stable. checksum/type/size are required properties, so dedupe cannot be bypassed. The first file of a multi-file paste reuses the current block's uuid when that block is empty (what makes "paste into an empty bullet" feel right); subsequent files append as siblings. A filename stem of literally `image` is replaced with a timestamp, because clipboards name every paste `image.png`.

**Transliteration.** The `->uint8` coercion ladder mostly evaporates — our transport is a real multipart body server-side, so keep only the browser Blob/File path (noting one branch worth keeping if we ever accept structured-clone payloads: numeric-string-keyed objects must be sorted **numerically**). Hash on the **server** with Bun's crypto, not the client, so dedupe cannot be bypassed by a lying client. The one-transaction insert becomes one notes command emitting one event. The 100 MB cap becomes a settings-registry entry enforced server-side.

**Risks.** There is **no binary upload route today** — `/fs/write` is text-only and the attachments store writes data URLs to `~/.platform`, outside the workspace — so this is a new server route regardless of how the client half is written, and it must inherit the fs layer's path confinement or a crafted filename escapes the vault. Two asset systems that disagree about limits and locations is a real outcome unless one is explicitly made the notes path. Hard-refusing duplicates is correct but needs a good message; Logseq's version leaves the user to insert the existing asset manually, which is the weakest part of the design.

### PDF annotation ⇄ block materialisation (reimplement)

**Algorithm to preserve.** `highlight.id === annotation block uuid` in both directions, always — every jump, recolour and delete keys off that. Materialisation is **lazy**: highlights get uuids at creation, blocks only on first reference (copying a ref, dragging into a page), so the store must tolerate a highlight with no block. Colour resolution failure **aborts** block creation rather than creating a half-formed annotation. Area highlights are created collapsed so the image does not dominate the outline. Reopening sets a pending-highlight handle the viewer consumes on mount, then scrolls to a destination 200 px above the highlight and flashes it for ~1.2 s.

**Transliteration.** Datalog asset queries become SQL over the EAV table joined to blocks. The file-version sidecar (`assets/<key>.edn`, pretty-printed) is not worth reproducing even though we are file-backed — a JSON sidecar loses the human-diffability that justified it; store annotations as blocks and, if git-diffability matters, serialise into the markdown note. Replace the `identity` field (last 15 chars of a derived key, namespacing DOM ids across open PDFs) with the asset uuid — 15 chars of a shared prefix is a real collision risk. Persisting the **whole** highlight array on every change is marked `TODO: incremental` in the source; fix it on the way in with one event per changed annotation.

**Risks.** The denormalisation is a live bug source: `hl-value` holds a full copy of the highlight while `hl-page`/`hl-color`/`hl-type` index the same facts, with nothing keeping them in sync. Decide once — either the indexed properties are derived-on-write, or `hl-value` is dropped. Opening a PDF as an editor tab means a new document-id prefix, which costs ~9 hand-edited sites; none hard, all easy to half-do.

### File-graph task markup ⇄ properties (reimplement)

**Reframing.** Logseq treats this as legacy import; for us, notes are markdown files, so this is the **primary** read and write path for markers, priorities and timestamps.

**Algorithm to preserve.** Text order is fixed and load-bearing: heading hashes, then marker, then priority, then title. Every operation is **replace-first from a computed offset**, never a global replace, so the words `TODO` or `[#A]` later in the body are untouched. The offset is computed by finding the **last** embedded heading in the block's raw text (a block is not one line) and starting just past it; priority additionally skips past the marker. Marker cycle: `TODO→DOING→DONE→none`, `LATER→NOW→DONE→none`, anything unrecognised → `TODO` or `LATER` per the preferred-workflow setting; `WAIT`/`WAITING`/`IN-PROGRESS` are recognised but not in the cycle. Import mapping: `TODO`/`LATER`→todo, `NOW`/`DOING`→doing, `DONE`→done, `CANCELED`/`CANCELLED`→canceled; anything else creates a **new closed value**, memoised per import so it is created once. A block whose entire trimmed title is just a marker word is a real pattern in the wild.

**Transliteration.** `util/re-pos` (returning `[[index, text], …]`) has no JS equivalent — write a manual `exec` loop with `/g`; do not reach for `matchAll` and lose the index discipline. The mldoc timestamp AST arrives as `{date:{…}, wday, time:{…}, repetition:[[kind],[duration],num], active}` — each of kind and duration wrapped in a one-element vector; type that faithfully from the malli schema rather than guessing. Import-state atoms become a plain mutable context object.

**Risks.** The biggest risk is deciding this is import-only, building the DB path first, then discovering the write-back path has different offset semantics. Decide up front whether markdown files or the index is the source of truth. The repeat-type mapping here preserves the _file_ version's semantics by name (`Dotted→dotted-plus`), which **disagrees with org and with the DB engine** — normalise at parse time or repeating tasks fire at the wrong time after a round trip. Unknown recur units assert rather than defaulting, aborting a whole import on one malformed line; prefer a structured warning per block.

### PDF area (rectangle) highlight capture (reimplement)

**Algorithm to preserve.** Reject drags under 10×10 px. Disable text selection on the viewer for the duration and re-enable in a `finally`. The crop reads the **already-rendered** page canvas at devicePixelRatio with `{alpha:false}` and `imageSmoothingEnabled=false` — both deliberate, so text crops stay crisp and the PNG carries no transparency. The consequence to preserve and document: resolution depends on the zoom level at capture time. The source rect is in viewport coordinates converted back from the scaled position, so the crop tracks whatever zoom the user is at. A provisional image placeholder must be replaced by the real asset id before persistence, and `content.image` being non-null is the discriminator for "this is an area highlight" everywhere downstream.

**Transliteration.** `p/create` wrapping `canvas.toBlob` becomes a small promise helper. `bean/->clj` on `DOMRect.toJSON()` becomes direct property reads. `mouseup` registered `{once:true}` ports directly, but keep the mousemove removal in a `finally` rather than relying on the flag for both. The resulting File goes through the asset ingestion route with a flag that targets the annotation rather than the editing block.

**Risks.** Deleting an area highlight must also unlink its PNG or the assets directory accumulates orphans — the file version did this explicitly and the DB version relies on a cascade we would have to build. Capture resolution varying with zoom is surprising and should be surfaced in the UI, or normalised by re-rendering the page at a fixed scale into an offscreen canvas — which is the better design and worth considering instead of copying.

### Template application with dynamic variables (reimplement)

**Algorithm to preserve.** The pre-pass is the whole trick: **before** inserting anything, scan every template block's title, raw title and all property text values for `<%…%>`, keep those that are today/yesterday/tomorrow, map to journal days, **create any missing journal page first**, and only then resolve. That is why a template containing `<%tomorrow%>` never produces a dangling ref. Resolution happens at apply time, never at definition time. `sibling?` defaults to: caller's value if given; false if the target already has children; otherwise true. Copies get **fresh** uuids. Journal-day encoding: midnight-normalised local date, offset applied, then parsing the zero-padded `YYYYMMDD` string concatenation as an int.

**Transliteration.** `string/replace` with a function replacer maps directly. The regex `/<%([^%].*?)%>/` ports verbatim — `[^%]` is what leaves `<%%foo%>` alone as an escape. Journal-page lookup becomes a SQL select on an indexed `journal_day`; "create the journal page" becomes "ensure the daily note file exists". The natural-language date fallback is optional for v1.

**Risks.** Only today/yesterday/tomorrow trigger materialisation, so an NLP-parsed date produces a ref that may dangle — which reads as a bug to a user who typed `<%next friday%>`. Property text values are scanned too (so `deadline:: <%tomorrow%>` works); forgetting that surface is a silent half-feature. Do **not** merge the two near-duplicate implementations (`frontend.template` and `logseq.outliner.template`) blindly — they have different variable semantics, which is exactly the same-sounding-helper trap.

### Cloze parsing and reveal (reimplement)

**Algorithm to preserve.** **Only the last `\\` separator** delimits the cue, so an answer may itself contain the separator: split on the literal two-character sequence keeping trailing empties, cue = trim of the last part, answer = the rest re-joined. Hidden state renders `[...]` with a blank cue and `(cue)` otherwise; revealed renders `[answer]` with the answer parsed as inline markup so refs stay clickable. The anchor guard: on click, if `event.target.closest('a')` exists and `currentTarget` contains it, do **not** toggle. A `showCloze` flag from the render context overrides the local toggle, so advancing the review phase reveals every cloze.

**Transliteration.** The global macro-atom registration becomes an explicit entry in a renderer map passed through render config — no load-order-as-API. The re-joining of macro args with `', '` is a lossy artefact of Logseq's comma-splitting macro parser; parsing cloze directly from raw text (which we should, since we are not adopting `{{macro}}`) deletes that step and makes the parse simpler and more correct.

**Risks.** Inline cloze in the live-preview editor lands on two unproven engine surfaces at once — `InlineReplacementSpec.render` has zero production producers and the single-line filter drops any replacement spanning a wrap boundary. Scope cloze to the review view for v1 and price editor-inline cloze separately.

### Agenda query (reimplement)

**Algorithm to preserve.** Bounds inclusive at both ends. A block with both scheduled and deadline in range appears **once**. The status clause is a hard join, so a bare date on a non-task block never appears — deliberate. Exclusion is by status **ident** (done, canceled), so a user-added custom status is always included, which is the correct default. Results sort recursively by outline order so a matching child renders under its matching parent, then group by page.

**Transliteration.** Datalog `or` with a shared binding becomes `WHERE (scheduled BETWEEN ? AND ?) OR (deadline BETWEEN ? AND ?)` over the EAV table. Fix the bug on the way in: Logseq mixes a UTC start bound with a locally-computed end bound, shifting the window by an hour near midnight and across DST — pick one basis, and given the repeat engine is UTC, make this UTC too. Also reconsider the "today's journal only" restriction, which the source itself notes surprises users.

**Risks.** Low. The only trap is the hard status join: wanting bare dates on non-task blocks later is a different query, not a tweak to this one.

### File-based org repeater text rewriting (reimplement)

**Algorithm to preserve.** Round-tripping a timestamp with **no** repetition must be textually identical — the property to test first and hardest. Serialisation: `yyyy-MM-dd EEE`, optional ` HH:mm`, optional repeater = symbol + num + letter with `{plus:'+', dottedPlus:'.+', doublePlus:'++'}` and `{hour:'h', day:'d', week:'w', month:'m', year:'y'}`; the zero-padded time is emitted only when the original had one.

**Transliteration.** The arithmetic comes from the DB engine's module, **not** from this file, whose semantics are demonstrably wrong: it implements `.+` as repeat-from-scheduled-until-future (i.e. the DB version's `++`) and `++` as a single step (i.e. roughly `+`) — and since the importer maps them across by _name_, a file graph silently changes when its tasks fire. Delete the `keepWeek` fix-up entirely: it exists only to patch local-time DST drift, and UTC whole-week arithmetic makes it unnecessary; keeping it on top of UTC arithmetic double-corrects.

**Risks.** The temptation is to reuse this file's `repeatUntilFuture` because it looks like working code. It is not the same function as the engine's advance-until-future — it always takes at least one step even from a far-future date, and it carries the weekday fix-up. Two implementations of "advance a repeater" that differ subtly is exactly the duplicate-helper trap: there must be **one** arithmetic function, with this module doing only text.

### Shortcut binding index and conflict classification

**Algorithm to preserve.** Comparison always happens on **parsed canonical step vectors**, never on strings, so `mod+k` / `meta+k` / `⌘k` compare equal. Three-way classification: exact match **blocks**, chord-prefix overlap **warns**, cross-context overlap is non-blocking. The crux is an asymmetry nobody derives from first principles: **prefix overlap counts as a conflict only within one context**, because two contexts own independent prefix trees. Contexts that cannot be active simultaneously never conflict at all. Accepting a reassignment strips the key from every loser and offers an undo restoring each previous binding individually.

**Transliteration.** The two-level `reduce-kv` index becomes `Map<string, {display, refs: Map<PlatformCommandId, FocusArea | 'any'>}>` keyed on `steps.map(canonicalStep).join(' ')` — JS Maps have no structural keys, so the parsed vector must be serialized. Closure's `parseStringShortcut` becomes `parseHotkey` from `@tanstack/react-hotkeys` per step, with modifiers sorted into a fixed order. `handlers-co-active?` becomes `panesCoActive(a, b)` over `FocusArea`, where `'any'` is co-active with everything and two distinct concrete panes never are — a stronger and simpler rule that lets the whole global-handler expansion set be deleted. A user binding of `false` maps onto our explicit `null` override.

**Risks.** Must be built over the **resolved** bindings, not the declared defaults, or the conflict banner and the `shadowedBy` label on the same row disagree — and we would add a sixth copy of a predicate the codebase already warns about having five of. Prefix classification is dead code until multi-step chords exist, so it must land with or immediately before the chord dispatcher. Today's `keybinding-row.tsx` passes a flat `conflictCount` into `ChordRecorder`, so a user cannot tell a genuine collision from a key legitimately reused in another pane — this is the gap being closed.

### Plugin renderer registry with predicate matching

**Algorithm to preserve.** A cheap provider-set-emptiness check short-circuits before any per-plugin walk, so a block render costs one Set check when nobody is providing — and one Set covers all three storage types. **Predicates are synchronous, total, and false-on-throw**; a promise-like result is logged as an error and treated as false, never awaited, because matching runs during render. That single rule is the difference between a working render path and a torn one. Highest priority wins, descending, with registry order as tiebreak. Block-properties renderers return **all** matches (they compose via prepend/append/replace); block renderers return only the first. The declarative condition language `{has, equals, in, not, any, all}` evaluates recursively with nil meaning true.

**Transliteration.** The register-factory closure becomes `{register, get}` over `Map<PluginId, Map<Key, Renderer>>` plus a `Set<PluginId>` provider set, where unregister removes the pid from the set only when no renderers of that type remain. `medley/find-first` is `Array.find`; `compare-and-set!` guarding the debounced rebuild becomes a boolean plus `queueMicrotask`. `serialize-property-value-for-plugin` disappears — it exists only to survive the clj→js boundary. Change one thing deliberately: unknown condition operators should fail **closed** with a warning, not open; Logseq's fail-open means a typo'd operator matches every block silently.

**Risks.** The natural editor-side landing surfaces are unproven: `registerBlockProvider` has zero production consumers, no browser tests, and re-resolves the full block list on every `setContent` and `applyEdit` — O(all blocks) per keystroke. `InlineReplacementSpec.render` has no production producer either. Routing plugin rendering through them is unproven work, not integration work. A predicate that touches the DOM or reads layout reintroduces the forced-layout bug class we already fixed once.

### Plugin package resolution and load state machine

**Algorithm to preserve.** Status transitions are **asserted, not queued**: load requires unloaded|error, unload requires loaded, and a pending plugin rejects rather than waiting. Two dispose stacks — runtime (cleared on every unload) and registration (only on uninstall) — both run in insertion **order** with each call individually try/caught and explicitly **not** `Promise.all`, because iframe teardown must follow UI teardown. A plugin that has been unloaded owns no DOM node, no injected style, no listener and no sandbox. Ids are stable across reloads. `beforeunload` is bounded so a hanging plugin cannot wedge the app, and its failure is logged but never blocks teardown. A `finally` always transitions to a terminal status so a throwing disposer cannot strand the plugin in `unloading`. The typed package error carries the `package.json` path so the UI can offer a targeted cleanup.

**Transliteration.** Already TypeScript, so this is a near-copy with substitutions: eventemitter3 → a typed emitter or the plugin store; `deferred()` → `Deferred<T>` with `AbortSignal.timeout`; Debug → evlog wide events; `IllegalPluginPackageError` → a `defineErrorCatalog` entry carrying `{url, packageJsonPath}`. The `lsp://` path-encoded URL scheme is dropped and replaced by one opaque per-plugin origin. The `?v=new Date().getDay()` cache-buster (at most one stale-SDK day per week — a real bug) becomes a content hash. Keep the behaviour of writing a minted id back into `package.json`: it is what makes settings survive a reinstall.

**Risks.** `libs/` carries no LICENSE file while the repo root is AGPL, so a near-copy of this file is the single clearest derivation in the domain — the label must be applied before anyone copies. Dropping the URL scheme drops the security boundary: without replacement origin isolation, plugin frames share an origin with the host. And do not lose the check that strips `devEntry` for dot-root-installed plugins, which exists specifically so a marketplace package cannot point at a dev server.

### Registry-wide plugin registration and preferences

**Algorithm to preserve.** A **shared ready barrier** resolves only after every plugin in the batch is constructed — and resolves in the `finally` too, so an exception cannot hang every plugin's `main()`. That barrier means no plugin's `main()` runs while other plugins are still mutating shared registries; nobody adds it retroactively without first hitting a nondeterministic ordering bug. Ids are unique — a duplicate during a registration pass is rejected, not overwritten. Enable/disable no-ops only on the two-part guard (already-disabled **and** not-loaded), because a plugin can be `disabled:true` and still loaded mid-transition. The error-handling asymmetry is a design decision that reads as a bug until you need it: a broken _package_ is skipped so it does not occupy its id, while any other failure **is** registered so the UI can surface the error and offer removal.

**Transliteration.** Keep the sequential `await`-in-`for-of` for the barrier but parallelise the IO inside each load — the sequencing constraint is about registry mutation order, not IO. `console.table` perf info becomes one wide evlog event per plugin plus a summary. `preferences.json` becomes a settings-registry key or a dedicated document under the platform dot-root — never a fresh localStorage key. The `isRegistering` plain boolean guarding the duplicate check corrupts under concurrent `register()` calls; make registration explicitly non-reentrant with a queued promise.

**Risks.** The ~13 lifecycle events the Clojure host listens to are what let the app clear commands, themes and pinned items without the core knowing those concepts exist. Collapsing them into fewer, fatter events makes the core grow host knowledge — the exact mistake the editor packages are structured to avoid, repeated one layer up.

### Plugin storage path sandboxing

**Algorithm to preserve.** Every filesystem operation on a plugin-supplied path passes through **one** assert before any IO — a single checkpoint, not a check per call site — and a denied path throws before touching disk. Both root and candidate are normalized before comparison, which is what stops `a/../../b` and mixed separators. Listings return paths **relative** to the sandbox root so the host layout never leaks. The sub-root uses `basename(pluginId)` as a second line of defence against an id containing separators. Clear **re-validates every listed entry** before unlinking it — the listing itself is not trusted.

**Transliteration.** Node path interop is identical in TS; promesa becomes await. Keep the lexical `path.relative` check but **add the realpath check Logseq is missing** — `path.relative` is purely lexical, so a symlink inside the storage dir pointing outward passes and escapes; the clear operation's re-validation is right-instinct-but-incomplete without it. `binary-content?` sniffing exists only to route around transit and is dropped. The denial throw becomes a structured error with code/status/why/fix.

**Risks.** This must be a narrower confinement **inside** the existing workspace confinement, never a widening of `assertInside` — a shared helper satisfying both is how a traversal hole gets introduced. And a straight transliteration ships the known symlink-escape hole.

### Keystroke recorder state machine

**Algorithm to preserve.** A modified key commits **immediately** and never accumulates — a modifier chord is always a complete step. An unmodified key pressed after a commit starts a **new** sequence rather than extending the old one. Bare modifier presses are ignored. Backspace drops one step **before** commit and clears everything **after** commit — the asymmetry is the branch easiest to get wrong from a description. Sequences never exceed the maximum step count. Every code path either restarts or cancels the 400 ms timer, so it never points at a stale keystroke.

**Transliteration.** `use-ref`/`set-ref!` become `useRef` for the same reason: a raw DOM handler reading React state gets a stale closure. The `cond` fallthrough becomes guard clauses. Do **not** reproduce the leading-space return from `keyname` that makes append a bare string concat — return the step and `join(' ')` explicitly; that trick is exactly the load-bearing detail a port loses. Keep our existing `isBindableHotkey` gate applied per step.

**Risks.** The current widget sets `recording=false` on blur and treats Escape as cancel; a sequence recorder needs Escape to cancel mid-sequence while still being recordable, and today's handler conflates the two. Hard sequencing constraint: **do not ship the sequence recorder before the sequence dispatcher**, or a user records a chord nothing can ever fire — a silent, unattributable failure.

### plugins.edn declarative sync

**Algorithm to preserve.** The comparable projection is derived **from the schema** (`(->> Plugin rest (mapv first))`), so the file format and the diff can never drift apart. Diffing runs on the **whole projection** rather than on id, which is what makes a version bump surface as install+uninstall of the same id — correct replace semantics a rewrite would get wrong. An equal comparison returns an empty diff and literally nothing happens. Every install/update/remove rewrites the file, and comments and formatting survive a programmatic edit. A reader failure and a schema failure produce different messages because the user's fix differs.

**Transliteration.** The projection becomes `Object.keys` on the valibot schema entries. `clojure.set/difference` over sets of maps relies on structural value equality, which JS does **not** have — key the sets on a canonical serialized projection, or use a Map by id compared with our existing `jsonEqual`. `rewrite-edn` becomes jsonc-parser `modify`/`applyEdits`, already wrapped in `apps/server/src/settings/json-document.ts`. The boolean coercion of `:theme`/`:effect` becomes valibot defaults.

**Risks.** Only earns its keep once plugins are installed from somewhere. Scope matters: this is a file that **names code to install**, so under our own rule it is application/machine scope and cannot live in the workspace settings layer — a manifest shipped inside a cloned repository choosing what code runs is exactly the threat model that restriction exists for.

### Settings-schema to form renderer

**Algorithm to preserve.** The settings store is the single source of truth and the form is a projection — every write goes through the store, never local state, so an external write (from the plugin itself or the raw JSON view) updates the form. A missing value always falls back to the schema default. Enum values normalise into a **Set** so single-select and multi-select share one code path. An unknown type is surfaced visibly (a loud "setting not handled" row), never silently dropped. `object` is a deliberate non-feature — a link to the raw JSON rather than a generated editor. An empty schema renders a message, not an empty form.

**Transliteration.** `condp contains?` over sets becomes a `Record<SchemaType, Widget>` keyed off our existing `SettingWidget` union, extended with the variants we lack (color, range, textarea, date). The 1000 ms debounce on an uncontrolled input is worth keeping — a controlled input fights the user's typing at that delay — but it **must flush on blur and unmount**, which Logseq does not, so an unmounted form silently drops the last keystrokes. `keydown` must be `stopPropagation`'d or typing in a settings field fires global shortcuts.

**Risks.** The entire point of `SETTINGS_REGISTRY` is compile-time typing; a generic runtime form renderer is a second rendering path for settings and the two will diverge unless the dynamic widgets **are** the same components the static page uses, parameterised. Inherit the structure, not the limitation: `enumChoices` doubling as both label and value should be fixed in the schema rather than carried over.

### Shortcut registry, contexts, and chord dispatch (reimplement)

**Algorithm to preserve.** A binding is a **sequence** of chord steps, not a single chord. The dispatcher re-reads the binding map on every event so a live rebinding takes effect without any reinstall. Context decides at **dispatch time** via a predicate, never by installing and removing handler instances. Exactly one live dispatcher, so `refresh!`-style teardown cannot silently drop a modal context. A binding that must always win is excluded from suppression. Keep the context **partition** as data: block-editing-only, editor-global (editing or a selection exists), global-non-editing-only, always-preventDefault, and the autocomplete group installed only while a popup is open — mapped onto `requires` plus `pane`.

**Transliteration.** The registry shape is already ours, so what is left is the dispatcher. Closure's `KeyboardShortcutHandler` install/uninstall per group collapses into the single keydown listener we already have plus `activePlatformKeyBindings(bindings, focusedPane)`. `:before` middleware in group metadata maps onto existing per-binding flags. Keyword `:fn` values resolved through namespace munging exist only to survive advanced compilation — delete. `:inactive?` evaluated once at module load (which is why toggling developer mode needs an app refresh) becomes a predicate read per dispatch. **Do not reproduce the chord dormancy:** Closure throws on prefix collision and Logseq catches and downgrades it to a debug log, leaving the chord silently dead — resolve by longest-match with a ~500–1000 ms sequence timeout.

**Risks.** `@tanstack/react-hotkeys` matches one chord; a sequence layer above it holds pending state and must not fire a single-key binding that is also a sequence prefix, or every single-key binding feels laggy. Every existing binding is a one-step sequence, so this must be a **widening** of `PlatformKeyBinding` rather than a parallel path, or the resolved-bindings helpers and the settings rows fork. Sequence state is global mutable state in the hottest input path and needs explicit reset on blur, focus-area change, and dispatch.

### Plugin settings store (reimplement)

**Algorithm to preserve.** `disabled` lives **inside** the settings document, so enable/disable is one write followed by load/unload rather than a separate field with its own persistence. Schema defaults fill only missing keys and never overwrite a user value (user wins). Every mutation emits `change(next, prev)` and one handler both persists and notifies. Exactly one persist subscription exists per plugin at any time — the re-subscribe path must clear the previous unsubscribe and guard against a stale disposer from a concurrent reload clobbering the live one. `patch` deep-merges with arrays **replaced**, not concatenated.

**Transliteration.** eventemitter3 becomes a zustand store read through `useSyncExternalStore`. `deepmerge` with `arrayMerge: (_, src) => src` becomes a small recursive merge. `mergeSettingsWithSchema` becomes: build a valibot schema at runtime from the plugin's declared entries, then parse on read — a malformed stored value becomes a diagnostic rather than a silently-typed `any`, which is the upgrade over Logseq where nothing validates. `diffSettings`'s truncated one-line string becomes a wide evlog event with added/removed/changed key arrays and **never** a stringified value (that path throws on cyclic values upstream). Implement `reset()` properly rather than resetting to `{}`.

**Risks.** The `plugin.<id>.*` namespace must live in its own document **and** its own layer, or a plugin's runtime schema starts participating in scope resolution and the static guarantees of `SETTINGS_REGISTRY` stop being static. Scope is a security question here too: a plugin setting that selects a binary, sets env, or binds a key is application scope, never window. The work spans contracts + server + web, so it needs one owner or the three halves disagree about who validates.

### Command registration: placements and key normalization (reimplement)

**Algorithm to preserve.** One logical command expands to N placement registrations (palette, keymap, slash menu, up to three context menus) and returns exactly **one idempotent** unregister that removes all of them. Palette entry, keybinding and surface entry are created and destroyed together. Plugin lifecycle teardown removes every command by plugin id regardless of whether the plugin called its own unregisters. The keybinding `mode` picks the context, so an "editing" shortcut only fires while editing.

**Transliteration.** Two lessons matter more than the code. Logseq ships **two disagreeing key normalizations** — the SDK never strips `:` and the host never lowercases — and papers over it by composing both at execute time; pick **one** and apply it at a single boundary. And the `when` field is stored as metadata and **never evaluated**, because v1 has no context-expression layer; Platform already evaluates its closed `CommandWhen` union in `keymap/utils/when.ts` through `CommandBus.inspect()`, so extend that evaluator rather than shipping a dead field or a parallel context engine. Namespaced keyword ids become a branded template-literal type with one parse/format pair. Action steps as `[keyword & args]` dispatched by multimethod become a discriminated union plus a handler `Record`.

**Risks.** `PlatformCommandId` is derived from the static command table; admitting runtime ids widens it and every exhaustive switch needs re-checking — including the persisted recents list, which would then hold ids no build recognises. `CommandWhen` is a closed union with one exhaustive evaluator shared by keybindings, palette, and menus. Layer plugin predicates into that typed boundary deliberately; do not add an arbitrary expression interpreter beside it.

### Theme registration and per-mode persistence (reimplement)

**Algorithm to preserve.** At most one custom theme applied at any time. **Ejection always precedes injection**, unconditionally and before any decision about the new theme, so there is never a two-stylesheet window. Light and dark selections are independent; removing a provider clears only the side that belonged to it. Restoring a saved choice at startup must neither rewrite the preference nor re-fire the change hook. A reload must not visibly drop the theme.

**Transliteration.** A Logseq theme is a CSS file injected as a `<link>` after all app styles so it wins on equal specificity — arbitrary selectors overriding anything. Our theming is token-based with an explicit rule against raw palette colours, plus material utilities that depend on specific token relationships holding, so a theme becomes a **validated token set**, not a stylesheet: `Map<themeId, ThemeTokens>` applied as CSS custom properties on `:root`. `preferences.themes {mode, light, dark}` becomes two registry keys plus the existing appearance mode — never a new localStorage key. Themes are never de-duplicated upstream (a `provideTheme` in a loop grows the array unbounded); key by `themeId` so re-registration replaces.

**Risks.** Our surfaces are translucent by design via `--surface-opacity`, `--surface-blur`, `--surface-saturation` and `--surface-wallpaper`; a token set a third party can fully replace can break vibrancy and contrast at once, and the failure looks like a rendering bug rather than a theme bug. Constrain the schema to the token names in `packages/ui/src/styles/globals.css`, validate contrast pairs — or ship curated themes only.

### Proxy API namespace and hook dispatcher (reimplement)

**Algorithm to preserve.** A hook is installed on the host exactly when a plugin has **at least one** listener and uninstalled when the count drops to zero. The host keeps `hook → {pluginId → opts}` and delivers only to actual subscribers — a high-frequency hook must be **indexed, never broadcast**, which is the same reasoning behind our coalesced delta frames. Hook names must encode identically on both sides or the message silently goes nowhere, so the encoding belongs in one shared module.

**Transliteration.** The JS `Proxy` get-trap becomes an explicit typed method table in `packages/contracts`, so the API surface is enumerable, greppable and type-checked instead of implicit. `safeSnakeCase` plus the leading `_`/`$` strip plus the four-way lookup fallback are all **deleted** — methods are keyed literally by `(namespace, method)`. The `Symbol.for('proxy-continue')` sentinel becomes an explicit local-override map. The trailing-nstag argument convention (which forces `datascriptQuery` to `inputs.pop()`) is replaced by carrying the namespace in the envelope. Per-block hooks with the uuid encoded into the hook **name** become a `(hookName, subjectId)` pair in the subscription record.

**Risks.** Deleting the conversion layer removes a class of shape bugs and adds a class of omission bugs — every payload shape must now be written down by hand. Logseq needed a macro at 188 endpoints and our `orchestration-ws.ts` already shows the cost of a hand-listed table, so generate it from the contracts types from day one. Do not carry the hook-name regex convention across: it misroutes any method literally named `on*`/`once*`/`off*` that is not a hook.

### config.edn validation and deprecation detection (reimplement)

**Algorithm to preserve.** Deprecation is a **separate, non-blocking pass** from validation — an invalid file still reports its parse error, and a valid-but-outdated file still gets its warning. The message is per key and says **why** the key no longer applies, not merely that it is unrecognised. A deprecated key never blocks a write. Errors anchor to a specific key with a link to the file. An empty config is valid.

**Transliteration.** Validation itself is already better here (valibot per key, `unknown-key | scope-not-allowed | invalid-value`, and a layer that recovers what it can from a broken document). What we lack is the deprecation pass: `file-only-config` becomes a `Record<string, string>` next to `SETTINGS_REGISTRY`, plus a `deprecated-key` member on `SettingsDiagnosticKind`. Drop the i18n-key derivation from the config key — we have no i18n layer, and its failure mode is silently rendering `{Missing key}` for any forgotten translation. The hardcoded `subs … 36` slice off the reader's duplicate-key prefix is brittle; use a regex if an equivalent is needed.

**Risks.** This must stay a **diagnostic**. The moment a deprecation entry starts rewriting the user's document it has become a migration shim and violates the greenfield rule — correct greenfield behaviour is to tell the user what to delete, not to heal it.

## Graph lifecycle: multi-graph, sync, export/publish, import, backup, startup

22 modules — 1 port, 12 reimplement, 9 skip. The heaviest skip ratio in the map, and the reason is one decision: with a **server-authoritative single writer**, the entire offline-merge tier (client op queue, rebase pipeline, E2EE, multi-tab election) stops existing.

**Strategy.** Read the seven skips as one connected choice, not seven independent ones. Logseq's sync design earns its 1924-line rebase pipeline because two offline clients can edit the same graph; ours has one writer, so the same guarantees come from a SQL transaction plus an append-only log we already run (`orchestration_events` with an autoincrement `sequence` and a `(aggregateKind, aggregateId, streamVersion)` unique index that _is_ the optimistic-concurrency check). Two rules from that tier are worth banking now because they are unrecoverable later: **one persisted row equals one user action, atomic**, and **persist the canonical semantic op at write time, never reconstruct it at replay time**. What we do build here is the invariant-repair tier (order, cycles, sanitization), the import and backup paths, and — because our notes are files in the user's real repository — the filename allocation and write-if-changed discipline that keeps a watcher→index→write loop from forming. The importer is the single largest unit in the whole map and also, for us, the most valuable: it is not a migration tool, it is the ingest pipeline.

### Entity checksum

This is the **only** module in the domain where transliteration earns its exposure, because the arithmetic must be byte-identical across implementations forever and having the reference to diff against is worth real money. Note the scope honestly: only the digest/combine/serialize core transliterates; the delta machinery is rebuilt, because it is written against two immutable DataScript db values we do not have.

**Algorithm to preserve.** Exact int32 arithmetic: `fnvStep = Math.imul(h ^ code, 16777619) | 0`, `djbStep = (Math.imul(h, 33) + code) | 0`, seeds 2166136261 / 5381, the unit separator (code 31) mixed through the **same** steps rather than through `digestString`, and 16-hex serialization as two unsigned 8-hex halves. Combination is component-wise int32 add/sub, so it is **commutative** and iteration order is irrelevant — that is the property letting two sides agree despite different apply orders. Reference values are normalized to the **target's uuid**, which is what makes the digest independent of local ids and why a uuid change forces recomputation of every referrer. The **counted-multiset** path is mandatory whenever a touched uuid appears more than once: a set difference silently loses a tuple and the checksum drifts permanently. Eligibility must be tested in **both** the before and after images.

**Transliteration.** Clojure vectors are value-equal map keys; TS needs a canonical string key. `volatile!` memo caches become Maps. The three DataScript index scans map onto our EAV table more directly than onto datoms — the `(uuid, attr, value)` tuple _is_ our row shape. `dbBefore`/`dbAfter` do not exist: capture the pre-image of touched rows inside the writing transaction and pass `{before, after, ops}`. The E2EE attribute-set branch is deleted. Keep an equivalent of the `LOGSEQ_CHECKSUM_ASSERT=1` dev assertion that recomputes after every local write and throws with the offending op.

**Risks.** It is a divergence **detector**, not integrity — collisions are accepted — and it earns its keep only once a second writer exists, so with one writer it buys a dev-mode assertion and nothing else. Budget it as instrumentation. The attribute set must be frozen in lockstep with the projection schema; changing it silently means the two sides never converge again. If zero exposure is wanted, the algorithm above is complete enough to build clean-room, at the cost of losing the ability to diff.

### File graph → DB importer (reimplement)

Overlaps the [Markdown→block extraction](#markdownblock-extraction-file-graph-import) row in the data-model domain, which is the ✅ inner kernel (`with-parent-and-order`, duplicate-id handling); this row is the pipeline around it.

**Algorithm to preserve.** The six-stage shape. (1) Read config **first**, because it parameterizes filename format, hidden-file rules and everything downstream. (2) Strict partition into config / assets / documents, with **assets before documents** because document parsing needs asset metadata. (3) A deterministic dependency-first sort so re-running the same folder yields the same graph. (4) A pre-pass reserving stable ids for entities that will be _referenced_ before they are _created_. (5) Strictly **sequential** per-file import — never `Promise.all` — so later files see entities earlier files created, with per-file progress and per-file error capture. (6) Cross-file reference repair as a **post**-pass, because it can only run once everything exists. A page's identity is its uuid, not its title.

**Transliteration.** 3169 lines of heavily threaded `->>`/`cond->` wrapped around a parser we consume as an ISC artifact anyway (S7) — the pipeline shape is the asset, the Clojure is not. `notify-user({msg, level, ex-data})` becomes one evlog wide event per file plus a `defineErrorCatalog` entry. Progress becomes SSE via the existing `toSse`, matching `/fs/search/events`. File enumeration reuses `readTree`/`WorkspaceIndex` rather than a fresh walk.

**Risks.** Open-ended: the tag/property → class conversion choices are **product** decisions dressed as porting decisions, which is why Logseq exposes them as import options. Running the import against the single platform SQLite file holds the write lock and stalls chat event appends — batch per file inside one IMMEDIATE transaction and stream progress, or stage into a separate ATTACHed file. Deterministic ordering is easy to lose to a directory-listing order that differs across platforms; sort explicitly.

### EDN export/import (reimplement)

**Algorithm to preserve.** **No entity ids in the output** — identity is title or uuid. A page reached only as a property value or a tag target gets a **shallow** copy (journal day, or just the title) so the export stays bounded instead of transitively dragging in the whole graph. Implied tags are never emitted, or the importer double-applies them. The closed-value set for a property is the **union** of its declared values and any referenced value whose content matches, so values referenced but never formally declared survive the round trip. Timestamps are excluded by default so exports diff cleanly. A whole-graph export refuses to run if validation fails.

**Transliteration.** The **format** is the asset, not the 1455 lines of entity-lazy-map threading and `clojure.data/diff` walking. EDN becomes JSON with the valibot schema in `packages/contracts` serving as both wire contract and pre-handover validation gate. "Reuse an existing entity where title or uuid matches" becomes an UPSERT keyed on uuid falling back to title. Prefer the **raw** title on export — the rendered form has block references inlined and does not round-trip.

**Risks.** "Graph-agnostic" only holds if every reference resolves by title or uuid. Our markdown-file-backed graph introduces a third identity — the file path — and the moment a path leaks into the format, exports stop being portable across vaults. Enforce that at the schema level, not by convention.

### Server batch apply with failure attribution (reimplement)

**Algorithm to preserve.** Entries apply strictly in order. On failure the reply names the entries **already applied**, the one that failed, and where known the missing block uuids, so the client marks the applied prefix done and rolls back only the failing entry — that is what lets a client keep 49 of 50 accepted edits instead of discarding the batch. A partial batch that advanced the cursor must still broadcast `changed` to peers **before** the rejection. A stale repair or rebase entry whose target is missing is an applied **no-op**, not an error. An empty delete op whose input was also empty is a hard invariant violation and must never be retried.

**Transliteration.** The tempid-span chunker exists entirely because of a 128 MB Durable Object budget and because DataScript tempids span items — deleted. `reset! conn dbBefore` on failure becomes SQLite's own rollback, strictly better than restoring an in-memory value. `d/listen!` around a critical section becomes the existing projection pipeline cursor. The reject payload becomes a variant of our command-receipt `error`/`resultJson`, riding machinery that already exists.

**Risks.** Our command receipts are keyed **per command**, not per batch entry; if notes ops arrive batched, receipts need a per-entry result or the attribution we are building this for is lost exactly at the boundary. Decide batching granularity when the op contract is written.

### Sync client lifecycle and reconnect (reimplement)

**Algorithm to preserve.** Four behaviours, each of which has bitten Logseq hard enough to be written down. (1) Backoff `min(30000, 1000 * 2^attempt) + randomInt(250)`, counter reset on a successful open. (2) A 60-second watchdog that force-closes a socket OPEN but silent for 600 seconds, and reschedules one found CLOSING/CLOSED — **verifying client identity** (workspace, graph, socket object identity) before acting, so a stale timer cannot kill a newer connection. (3) **Authoritative versus non-authoritative** cursor updates: hello/changed _set_ the remote position, pull/ok and batch/ok only _raise_ it via max, so an out-of-order response can never roll the tracked position backwards. (4) Pull coalescing on the smallest pending cursor.

**Transliteration.** The whole concurrency model is `queue = queue.catch(noop).then(task)` on a plain variable — one line in TS, replacing a `swap!` on an atom holding a promise. `set!` on `.onmessage` becomes `addEventListener` with an `AbortController`, which also fixes the detach-before-close dance. Malli coercers become the valibot schemas already in `packages/contracts/src/orchestration-ws.ts`.

**Risks.** Our WS client already reconnects; adding a second policy produces two competing timers and a reconnect storm. This must land as an **edit to the existing orchestration WS client**, not a notes-local socket. The identity checks are the part people delete as redundant right before the stale-timer bug appears.

### Snapshot import with schema-first replay (reimplement)

**Algorithm to preserve.** Property and class definitions are written **before** any row that uses them — not cosmetic; the store mis-indexes or rejects otherwise. Rows stage into a **temp** table, never into the live graph, until the stream completes. Replay in batches with a yield between them. Local-only columns are regenerated, never imported. An import id guards against a stale in-flight import writing into a graph that has since been replaced. Every failure carries the **stage** it broke in — init, fetch, prepare, stream, finalize — which is what makes download failures debuggable.

**Transliteration.** Sniff the gzip magic bytes (`1f 8b`) rather than trusting `Content-Encoding`, which lies. Transit framing becomes NDJSON — one JSON object per line, no framing needed and greppable in a terminal, a real debugging asset over opaque blobs. `p/loop`/`p/recur` over a lazy datom seq becomes an async generator. Keep the module-level import-state singleton, but as a **named lock**, so concurrent imports are impossible by construction rather than by accident.

**Risks.** The temp staging table shares the single platform SQLite file with chat events and projections, so a large import holds the write lock and stalls the orchestration WS. Stage into a separate file and ATTACH it, or measure and accept the stall — do not discover it in production.

### Vault file writer and filename allocation (reimplement)

Same source file as the [Markdown mirror](#markdown-mirror-reimplement) row, read for the opposite direction: Logseq derives markdown from the DB, we allocate a path when a note is created or renamed.

**Algorithm to preserve.** `writeIfChanged`: read current content, **byte-compare**, and return skipped without touching disk when identical — never mtime or size as a proxy. Filename stem: NFC-normalize; replace `<>:"|?*\/` and every `\x00-\x1F` with `_`; strip trailing spaces **and** dots (Windows drops them silently, so `foo.` and `foo` collide); truncate; reject blanks and the reserved device names (CON/PRN/AUX/NUL/COM1-9/LPT1-9) case-insensitively **and regardless of extension** — `CON.md` is still CON. Collision disambiguation gathers all notes normalizing to the same stem, sorts by a **stable identity**, and lets 1-based position pick the suffix — sorting by anything mutable renames files on unrelated edits. Queue: merge jobs per target path (a delete supersedes a pending write), one timer per root, queuing while a timer is pending must **not** reschedule it, and the flush swaps the whole map out atomically.

**Transliteration.** Half of Logseq's module duplicates primitives we own: `child-path!` becomes `paths.resolve()`/`assertInside` (which additionally realpaths, so it is strictly stronger), and the snapshot write reuses `temporaryPath` + `rename` from `apps/server/src/fs/write.ts` rather than a second atomic-write implementation. `defonce` atoms become module-level Maps in `write-queue.ts` (stateful, so never `utils/`). Not-found detection sniffs the error message string upstream; normalize on `err.code === 'ENOENT'` via our existing `statOptional`. Fix one bug while porting: the 160-character truncation counts JS characters while filesystems count UTF-8 **bytes**, so 160 CJK characters still overflows the 255-byte component limit.

**Risks.** If `writeIfChanged` is added but any write path bypasses it, the watcher→index→write loop returns and is hard to attribute — enforce it by making `writeTextFile` the only exported writer, not by convention. Our workspace is the user's real repository, so an allocated note path can collide with an existing source file: seed the index from the on-disk vault before the first allocation. Case-insensitive filesystems make two stems differing only in case collide on disk but not in the index — normalize case for the **collision key** while storing the original name.

### Backup filesystem policy (reimplement)

**Algorithm to preserve.** The reservation trick: `mkdirSync(dir)` **without** `recursive`, treating EEXIST as "try suffix+1" — an atomic name reservation with no lock file and no read-then-write race. Write to a temp file in the **same** directory, rename onto the target, and only **then** write metadata, so a backup directory either holds a complete backup or does not exist. On any failure remove the temp file and, if the target never landed, the whole reserved directory, so a failed attempt never consumes a name. Retention is **per source** — automatic backups never prune manual ones. The metadata timestamp is the ordering authority; mtime is a display fallback. Throttle by reading the newest same-source backup's metadata **before** reserving anything.

**Transliteration.** Reuse `paths.resolve`/`assertInside` and `temporaryPath` + `rename` rather than re-deriving them. `cljs.reader/read-string` on metadata becomes JSON; `required!` assertions become a valibot schema in a sibling `contracts.ts`.

**Risks.** The non-recursive `mkdirSync` **is** the concurrency guarantee; a well-meaning refactor to `{recursive: true}` deletes it silently and two processes overwrite one backup — that comment earns its place. Prior question worth asking before building any of it: if notes are markdown files in the user's git repository, git already _is_ the backup, and this module only earns its keep for the derived SQLite graph.

### Parent/extends cycle detection and repair (reimplement)

**Algorithm to preserve.** Detection returns the cycle **path**, not a boolean, because the victim heuristic needs the edge list. The safe replacement target must be ancestor-checked against the victim (walk the parent chain with a seen-set) or the repair recreates a cycle; the default safe target for a block is its page root. Repair iterates with an **edge-key dedupe** and a bounded iteration count, because breaking one cycle can expose an overlapping one — the dedupe plus the bound is what guarantees termination. Never retract an edge that no longer exists.

**Transliteration.** The right structure for us is the **opposite** of Logseq's: they repair after the fact because datalog cannot cheaply answer "is X an ancestor of Y", while SQLite answers it in one recursive CTE — so the ancestor check belongs in move-op **validation**, and the repair pass demotes to a recovery tool for data written by an earlier build or an import. Use `UNION`, not `UNION ALL`, so an already-cyclic graph still terminates the query. `volatile!` plus a recursive `letfn` DFS becomes an explicit stack loop; recursion depth is a real hazard on deep outlines. With one writer there is no peer database, so the remote-informed victim branch reduces to "the op that arrived second loses".

**Risks.** Prevention only covers ops routed through the validator; an import or a direct SQL write bypasses it, so the recovery pass must exist and be runnable on demand rather than deleted as dead code. Worth knowing before budgeting: this namespace has **no production caller** upstream (tests only) and its protocol doc is stale, so it is not battle-tested code.

### Migration engine (reimplement)

**Algorithm to preserve.** Two behaviours we lack, on top of an engine that is already stricter than Logseq's. (1) A database whose version is **ahead** of the app is a hard refusal with a user-facing "update the app" message — never a partial migration, never a silent skip, which is what our ledger does today with unknown recorded versions. (2) The built-in **reseed merge**: for each built-in item keep the **existing** uuid but always take the new title/name and always force the built-in flag true, then rewrite every reference in the seed data to the existing uuid. The version stamp is written in the same transaction as the step's data.

**Transliteration.** The engine itself is a skip — `apps/server/src/db/migrations.ts` is already forward-only, numbered, and applies each migration with its ledger row in one IMMEDIATE transaction, immune to the two-process race. `clojure.walk/prewalk` reference substitution becomes a recursive rewrite over the seed JSON; the "every entity having attribute X" datalog query becomes a `DELETE`. Skip the deterministic built-in sync-repair transaction with forced-zero timestamps — it exists only so several peers converge on identical datoms.

**Risks.** Adding the newer-than-app refusal changes startup on any developer machine that has run a newer branch: make it a loud structured error, not a silent read-only mode, or it will be diagnosed as a hang. The reseed's identity preservation is the subtle half — get it wrong and every built-in reference in the graph repoints on upgrade.

### Transaction sanitization (reimplement)

**Algorithm to preserve.** A delete expands to the **full descendant set minus the entities explicitly touched by the same batch** (unless the caller asked for a full subtree wipe — options are selected per op kind, not globally). Sanitization is idempotent, adds nothing but implied descendant deletes, and drops ops for entities the receiver legitimately does not have **silently** rather than erroring.

**Transliteration.** Roughly half the module is DataScript and E2EE bookkeeping that vanishes (negative-integer tempid guards, encrypted add/retract collapse, kv-entity ignore sets, the migration-deleted attribute list). `getBlockFullChildrenIds` becomes one recursive CTE using `UNION` so a pre-existing parent cycle still terminates. `cond->>` threading of conditional transducers becomes sequential `if` steps. The migration-deleted attribute set becomes knowledge owned by the migration ledger — but it must stay **append-only** or an older client's op fails server-side forever.

**Risks.** Getting the preserved set wrong deletes blocks the user just edited in the same batch — write the test where a delete and an edit of one of its descendants arrive together.

### Two-phase backup retention (reimplement)

**Algorithm to preserve.** Sort newest-first by parsed timestamp with **unparseable names sorting last** (ts = −1) and the name as tiebreak. `keepHourly = min(6, keepVersions)`. Phase 1 keeps one file per distinct hour until `keepHourly` distinct hours have been seen; phase 2 then keeps one per distinct day. Unparseable names get **unique** per-file bucket keys so they are never deduped against each other. Stop as soon as the kept count reaches `keepVersions`. The newest file is always kept, and deletion is idempotent.

**Transliteration.** 146 lines of pure filename arithmetic, fully specified — nothing here needs the source open, so paying exposure for it would be a bad trade. `loop`/`recur` with four accumulators becomes a for-loop with four locals and a `continue` for the skip branches. Hour flooring is `ts - (ts % 3_600_000)`, correct because the filename encodes UTC — do not substitute a local-time date API.

**Risks.** Deriving retention purely from filenames means any filesystem that rewrites names (case folding, unicode normalization on some volumes) silently changes the bucketing. Keep the timestamp in the filename **and** in the metadata file, and let metadata win when they disagree.

### Duplicate sibling-order repair (reimplement)

**Algorithm to preserve.** Group by `(parent, duplicated value)`, sort the colliding siblings **by uuid string**, and regenerate n keys strictly between the duplicate and the next-greater sibling value. The uuid tiebreak is the whole convergence property: every peer seeing the same duplicate derives byte-identical keys and the repair stops instead of ping-ponging. New keys must lie strictly between so untouched siblings keep their relative order. The repair is itself an ordinary op and re-applying it is a no-op.

**Transliteration.** It **cannot** be transliterated: it calls `gen-n-keys` on Logseq's base-62 library while our `packages/contracts/src/order-key.ts` is base-26 lowercase with **no between-bounds n-key generator at all** — copying would import the wrong alphabet and the wrong validity rule. Add `generateOrderKeysBetween(before, after, count)` first. Clojure `compare` on base-62 needs the library's digit order; our alphabet is code-point monotone, so plain `<`/`>` on strings is correct and `localeCompare` must never be used. Fix a bug on the way in: Logseq takes the **first** sibling order greater than the duplicate (`some`), not the minimum, which can generate keys leaping over an intervening sibling — take the minimum.

**Risks.** Our `isValidOrderKey` rejects a trailing minimum digit, so a naive n-between generator emits keys the validator then rejects — generator and validator must be written together. Repeated bisection grows key length without bound; cap it and fall back to a section rewrite with `generateSpreadOrderKeys`. Silent order corruption is the worst failure mode in an outliner: blocks appear to reorder or vanish and nothing errors.

### Hybrid full-text search

The combined view of the four search rows under [Queries, search, and the reference graph](#queries-search-and-the-reference-graph) — schema, lanes, snippets, fusion — which carry the per-module detail. What this framing adds:

**Algorithm to preserve.** The lane fan-out **is** the design: three cheap SQL strategies beat one clever one, and the `enoughExact` short-circuit is what keeps typing an exact page title cheap. Merge is concatenate-in-fixed-order then a single walk building an insertion-ordered id→result map, taking the **max** of each score component on a repeat id rather than overwriting. Dedupe twice: by id after fusion, by uuid after mapping.

**Transliteration.** The DDL and triggers transliterate verbatim and land on the same engine they were written for; the bind-order gymnastics disappear with parameterized queries; `d/pull-many` becomes **one** `IN (…)` query, never a loop — the difference between one index scan and 400. Substitute our own `fuzzyRankScore` in the fuzzy lane. Drop the vector lane, which makes the RRF branch dead until a second engine exists.

**Risks.** Obsidian's `line:` / `section:` / `block:` operators need **positional data in the index**, so section boundaries and line offsets must be decided **before** the schema commits — retrofitting positions into an FTS-only index is a full reindex. Our index must be file+section shaped, not block shaped, so the is-this-a-page bonuses need re-deriving. One SQLite file backs the whole platform today, and this adds real write traffic alongside chat event appends.

### Linked references with include/exclude filters

Same module as [Linked references with include/exclude filters](#linked-references-with-includeexclude-filters); that section carries the prose. What this framing adds: the traversal only needs "node has refs, node has a parent", so a **heading-section tree satisfies it as well as a block tree** — which is what makes backlinks-with-filters available to a file-first product at all. That in turn means section boundaries must be in the per-file metadata record before this can run, and retrofitting positions later means a full reindex.

### Search-result snippet windowing

Same module as [Snippet windowing and term highlighting](#snippet-windowing-and-term-highlighting); that section carries the prose. What this framing adds: our incumbent `apps/web/src/features/search/utils/match-display.ts` (148 lines) solves only the easy half — one match, a fixed 96/24-char budget, no sentence boundaries, no multi-term, no merge/split — so this is a replacement in the same pass, not a second implementation.

### Property type system

**Algorithm to preserve.** The type set in UI order (default/text, number, date, datetime, checkbox, url, node, asset) and — critically — the **two allow-lists**, which are not decoration: cardinality may only be switched for `{default, number, url, node, asset}`, and closed values apply only to `{default, number, url}`. A closed value is itself an **entity**, so it can carry icon, colour and an explicit order — which is what lets `High/Medium/Low` sort by severity rather than alphabetically. A **ref-typed (node)** property stores an entity id, never a rendered title, so renaming the target never breaks a saved filter or a stored value. One property name has one type vault-wide; changing the type reinterprets existing values everywhere, so coercion must be centralized in one place and **total** (every old value maps to something, or to an explicit unparseable marker).

**Transliteration.** Keywords become string unions; malli becomes valibot. The `:db/ident`-entity representation becomes a row in the EAV property table plus a typed descriptor (S2) — Logseq expresses the open schema through their DataScript fork's dynamic schema map, and our equivalent is the property row carrying its own type and cardinality as data. Explicitly do **not** route this through `packages/contracts/src/settings/keys.ts`: the settings registry is for app knobs with a scope-as-security-boundary rule, and note properties are user data. Keep the descriptor shape as **one** typed module rather than scattering type knowledge across the panel, the sorter and the filter — that scattering is what makes property type changes unshippable later.

**Risks.** This is more thought-through than Obsidian's model (whose "link" type is just text containing `[[…]]`, and which pays for cardinality with a type explosion), so adopting it is a genuine differentiator — but ref-typed properties mean every property write needs a resolution step (title → entity id) and an unresolved state, which Obsidian users will not expect from a plain YAML file. The frontmatter must still round-trip as readable text or the file-is-truth premise is broken. Closed values ordered by explicit order when every value has one, else declaration order: mixing the two per-value gives an unstable comparator.

### Plugin host (reimplement)

**The licensing decision of the whole port lives here.** `libs/` is already TypeScript, so "porting" means copy-paste, and copying 5,585 lines of AGPL into our host makes the entire application a derivative work **including the network clause** — for a subsystem whose design can be learned in an afternoon from the API surface, which is factual rather than expressive. Read it for shape, derive the registration surface from the feature list, and write transport, sandbox and teardown against our own workbench.

**Algorithm to preserve.** The seven table-stakes registration capabilities, judged against what the load-bearing Obsidian plugins actually need: (1) index read plus change subscription (Dataview); (2) **custom view types bound to file extensions**, with a leaf lifecycle of open/save/close/serialize-state — the Excalidraw class, and the one Logseq structurally cannot do; (3) code-fence renderers; (4) command and hotkey registration; (5) a settings schema rendered by the host from a descriptor array; (6) CSS/theme injection; (7) file CRUD through the same atomic-write guarantees the host uses. Lifecycle invariants worth keeping verbatim: every injected style and UI element is **tagged with its plugin id** and removed on unload, or disabling a plugin leaves its DOM and CSS behind forever; deferred RPC promises are GC-swept or a chatty plugin leaks unboundedly; the handshake **times out** rather than hanging startup; all plugin-supplied HTML is sanitized before the host mounts it into its own DOM (an iframe does not protect the host from HTML the host itself mounts); stored settings are always merged **over** schema defaults so a schema change never orphans values.

**Transliteration.** There is no Clojure here — that is the problem, and it inverts the usual calculus: normally translation cost is a tax, here it is what keeps the license clean. Do not vendor Postmate; build the handshake and the tagged request/response protocol directly, or better, decide first whether plugins run in an iframe at all. Obsidian does **not** sandbox — plugins are Node-privileged, which is why installing one is a trust decision — and you cannot have both Excalidraw-class plugins and a tight sandbox without a much larger capability-broker design. Pick knowingly and write the decision down. The settings-schema descriptor maps onto our existing widget vocabulary but must **not** go into `settings/keys.ts`.

**Risks.** If the registration surface ships without `registerView` plus extension binding, an entire class of plugin becomes permanently unhostable and retrofitting means redesigning the workbench widget model. Two isolation models in one system (iframe plus shadow-DOM sharing the host realm) is a smell worth not reproducing. And nothing here is safe to start before the sandbox question is answered.

### Palette / quick-switcher result grouping (reimplement)

**Algorithm to preserve.** Group order is a **pure function of the input string and the active filter** — never of arrival order — so async groups landing does not visibly reshuffle results. Four mutually exclusive input shapes: leading `/` means scope-picking (filters first), a mid-string `/` reads as a path (files rise), an active filter suppresses everything else, otherwise the default order. The **create affordance** appears only when the input is non-blank, is not a reserved config filename, and no existing note's **sanitized** title exactly equals the sanitized input — that last check is what stops "Create page Foo" sitting above the actual page Foo. Flattening assigns a monotonically increasing `itemIndex` across **all** groups, which is what lets arrow-key navigation cross group boundaries with zero group-aware logic in the key handler. Group headers show the backend's `matchedCount`, not `items.length`, so "Notes (247)" is honest while showing 10. Highlight resolves as explicit ?? fallback ?? first-overall and recomputes on every result change so a late async group does not strand it.

**Transliteration.** We already have the palette, the per-kind group modules, the recents store and `fuzzyRank`; what is missing is exactly this **policy**. The one genuine trap is `volatile!` + `vswap!` as a shared counter across a lazy `for` — in TS you must materialize the arrays eagerly before assigning indices, or the counter mutates during render and produces duplicate keys. The grouping function stays pure in `utils/` while the store read lives in the hook.

**Risks.** Non-contiguous `itemIndex` silently breaks keyboard nav (skipped or repeated rows) and ships easily because mouse selection still works. The create-affordance sanitization must match whatever the note-creation path actually uses, or the palette offers to create a note that then collides with an existing file.

### Template variable expansion (reimplement)

**Algorithm to preserve.** Unknown placeholders **pass through unchanged** — never blanked, never an error — so a typo is visible rather than silently deleting content. Date arithmetic works in **local** time on a midnight-normalized clone (clone `Date`, `setHours(0,0,0,0)`, then `setDate(getDate() + offset)`), and the day key is built by zero-padded string concatenation, **never** `toISOString` or any UTC formatting — that is the single most common bug in date-template code and it produces yesterday's note for everyone east of UTC in the evening. Time formats with `hourCycle: 'h23'`. The `<%([^%].*?)%>` pattern's `[^%]` guard is what leaves `<%%` alone as an escape. Matching is case-insensitive after trimming. A link resolves by stable id when the target exists and by title when it does not.

**Transliteration.** Five hardcoded substitutions across 207 lines — porting Clojure to get five substitutions is not worth the derivation. `string/replace` with a function replacement receives the full match vector in Clojure and separate arguments in JS. `goog.date.DateTime` becomes plain `Date`. Chrono NLP parsing is an optional dependency decision, not a port. Keep the expander pure in `utils/`; the insertion belongs in the hook and must go through the editor's `applyEdits` so it lands on the undo stack.

**Risks.** Almost none technically; the risk is expectation. Templater is a scripting host with prompts, file operations, cursor placement and arbitrary JS; this is a regex with five cases. Shipping it and calling it "templates" invites the comparison — state the gap in the UI or the docs rather than letting it be discovered. If we want the ecosystem's templating story, that is a sandboxed script host with a context object, i.e. a plugin-API problem.

### Vault file writer / graph view / table view / query compiler

Cross-references, not repeats: the [vault file writer](#vault-file-writer-and-filename-allocation-reimplement) is under Graph lifecycle; [graph view derivation](#graph-view-derivation-reimplement) is under Page surfaces; the [view data pipeline](#view-data-pipeline-reimplement) and the [query compiler](#simple-query--executable-compiler-reimplement) are under Queries. Two additions from the Obsidian framing worth recording. First, Obsidian's search surface is a genuinely different language from Logseq's — operator syntax (`file:`, `path:`, `tag:`, `line:`, `section:`, regex) plus quoted phrases, negation, OR and parens, none of which Logseq has (its search is one fuzzy string plus clickable group chips) — so the DSL's _surface_ is a from-scratch build even though the compiler pipeline shape transfers, and structural terms must be applied as index predicates **before** the FTS query so the candidate set stays small. Second, the graph view must add an **unresolved-link** concept Logseq has no equivalent for, because creating `[[foo]]` there eagerly creates page foo, while Obsidian dims unresolved links and counts them.

### Two skips worth stating plainly

**Block tree → markdown serializer.** Document-first mode deletes the reason it exists: its core job is emitting bullet scaffolding — every block prefixed with indentation and `-` — which is exactly the serialization we are refusing. Our piece table _is_ the document and writes go through `apps/server/src/fs/write.ts`. Salvage exactly one rule for the places where we programmatically mutate markdown text: a code fence must be `max(3, 1 + the longest backtick run anywhere in the content)`. The under-skipping risk is real — someone reads "markdown serializer" and wires it as the write path, silently rewriting the user's documents into an outline on first save.

**Fuzzy match scorer.** `packages/contracts/src/fuzzy-rank.ts` (296 LOC, in production across the palette, file picker, model picker, composer search and session rail) does multi-term AND with per-piece best-field selection, weighted label/path/keyword fields, exact/prefix/word-boundary/substring/fuzzy tiers and a seven-key deterministic comparator. Logseq's is a single-pass subsequence scorer adapted from a public gist whose `idx` accumulator is decremented every iteration and **never added to the score**, and whose final `cond` has an unreachable duplicate branch. Adopting it would be a downgrade plus exposure. Two ideas are worth folding into ours as additive changes: NFKC-normalize and strip diacritics before comparison (so `ｆｏｏ` matches `foo` and `resume` matches `résumé`), caching the normalized candidate on the index record; and cap candidate length, because the matcher has no length guard and a pathological title costs a full scan per keystroke.
