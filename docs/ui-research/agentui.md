# AgentUI (agentui.pro)

Surveyed 2026-09-25. Full source dump: `references/agentui/` (gitignored). `src/` holds every registry file, `md/` holds each component's docs page, and `registry.json`, `r-index.json` and `llms.txt` are the raw indexes.

## 1. What it is

- 19 shadcn-registry items for agent chat. They cover messages, a follow-the-live-edge scroller, the composer, a todo list, a code block, a file diff, a tool result, tool approval, an approval card with questions, citations, streaming response, image generation, an agent activity stream, three loading states, an AI sidebar, and a chat app that composes the rest.
- **License: MIT.** Every item's frontmatter (`md/*.md`) says so. There is no pricing, no paid "pro" tier and no public GitHub repo; the ".pro" is only the domain. Source is served openly at `https://www.agentui.pro/r/<slug>/raw`, and the shadcn JSON at `/r/<slug>.json`.
- Stack: React 19, Next.js ("use client"), Tailwind v4, **`motion` (framer) everywhere**, `lucide-react`, `shiki` (only code-block, file-diff, tool-result and tool-approval), `clsx` and `tailwind-merge`. No Radix and no Base UI. Every control is hand-rolled on `motion.button` and similar elements.
- Style: large radii (`rounded-2xl`), `border-border/60` hairlines, raw palette status colours (`emerald-500`, `rose-500`, `amber-500`), and opacity-alpha text (`text-foreground/90`). Almost all of it breaks our Design Language, so **we port ideas. We do not copy files.**
- The quality is in behaviour, not looks. Almost every component has a status lifecycle: it auto-opens when work starts and auto-collapses to a summary when it ends. Heights stay fixed while content streams. Reduced motion is handled per component.

## 4. Steal list (ranked)

1. **Streaming highlight keeps previous tokens.** _Port the idea._ Change `packages/markdown/src/hooks/use-highlighted-code.ts` and `components/highlighted-code.tsx`: when `highlighted.key !== key` but the new `code.startsWith(previousCode)`, render the previous token lines and leave only the new tail plain. First confirm the flash exists with a streaming-fence scenario (see the no-flicker rule). If it exists, this is a bug fix, not polish.
2. **Minimap previews.** _Port the idea._ In `features/chat/components/timeline-minimap.tsx` and `utils/timeline-minimap.ts`, give each mark a prompt excerpt taken from `items`, not from the DOM (the timeline is virtualized), plus the first line of the reply. Render them in the existing `TooltipContent`: `text-xs` for the prompt, `text-muted-foreground text-2xs` for the reply. Cut at a word boundary with `…`. Small, and it makes the rail usable.
3. **Plan/todo status marks.** _Port the idea as CSS/SVG, no `motion`._ Add one `StepStatusMark` SVG (dashed circle, arc, check path, ×) whose `stroke-dashoffset` is animated by `transition` on the motion tokens. Use it in `composer-active-plan.tsx` and any plan step rows. Collapse the plan on "all complete" and reopen when a step goes back to pending. Keep `text-success`/`text-destructive` tokens and `TickerNumber` for the count we already have.
4. **Approval card: parameters and a resolved state.** _Port the idea._ In `pending-approval-panel.tsx`, split the approval detail into key/value rows when it parses as an object (command, cwd, path), and keep the `<pre>` fallback. Show the decision on the matching timeline row, `activity-row.tsx` with `icon==='approval'` ("Allowed once", "Denied"), so the transcript records what was allowed. This fits the approval-rules work from Plan 145.
5. **Live tail window for the running turn.** _Port the idea, owner decision needed._ `live-activity-row.tsx` would show the last 3 entries in a fixed-height, `overflow-hidden` region with a top mask fade, newest at the bottom. A **fixed** height suits our virtualized timeline, because the row measures once and does not churn. On completion it becomes the existing `ActivityGroupRow` summary.
6. **Duration in the summary.** _Port the idea._ Append "· 1m 12s" (tabular) to `activityGroupSummary` from the first and last `createdAt` in the group. For reasoning-only groups say "Thought for 12s".
7. **Inline diff stat on edit rows.** _Port the idea._ In `activity-row.tsx`, render `DiffStatLabel` when the entry carries per-call counts. Needs data: work-log entries have `changedFiles` but no per-call `+/-`. Check whether the provider payload has it before building anything.
8. **Height reveal for disclosures.** _Port the idea._ Add a `Collapsible` variant in `packages/ui/src/components/collapsible.tsx` that transitions `height: var(--collapsible-panel-height)` with `data-starting-style`/`data-ending-style` and our duration tokens. Use it only off the virtualized timeline (composer plan, approval details, settings). Inside the timeline it collides with `timeline-viewport.tsx`'s disclosure-settle logic.
9. **Send/stop in one slot.** _Low priority._ `chat-input-submit-button.tsx` would cross-fade the icon inside the same `Button` instead of mounting a second Stop button beside it. Measure first; the current two-button layout may be deliberate (stop while you type a correction).
10. Skip: the grid "Churning" loader and the scramble/cascade phrase text (we have four loaders and the rule is no new ones), the `motion` dependency, AI Sidebar, Image Generation, and Citations. Our markdown links already carry favicons.

## 5. Cost / risk

- Nothing drops in. Every file imports `motion`, `lucide-react`, hairline borders, raw palette colours and `rounded-2xl`. Copying one means rewriting it against `@workspace/ui` primitives, Phosphor icons and tokens, so treat the source as a spec.
- Adding `motion` (~35 KB gz) just for springs is not justified. Every steal above works with CSS transitions and our `--duration-*` and `ease-*-strong` tokens.
- Animated heights inside the TanStack-virtualized timeline are the main risk. Keep motion out of rows that change size, or make the size fixed (steal 5).
- Their `useCallback`, `useRef` and effect patterns are pre-Compiler style. Ported code must go through `compiler:memos`.
