# Vercel AI Elements (elements.ai-sdk.dev)

Surveyed 2026-09-25. Upstream clone: `references/ai-elements/` (vercel/ai-elements @ 6a9d5b1, 2026-08-21). Components are in `packages/elements/src/*.tsx` and docs in `apps/docs/content/components/(chatbot|code|voice|workflow|utilities)/*.mdx`. There is also an older fork at `references/ellie/apps/web/src/components/ai-elements/` (March 2026, partly moved to Base UI; missing `question.tsx`).

## 1. What it is

- 49 shadcn-registry components installed with `npx ai-elements add <name>`. Groups: chatbot (19), code (15), voice (6), workflow/xyflow (7), utilities (2).
- **License: Apache-2.0, not MIT** (`LICENSE`, © Vercel). Copying code is allowed, but the file must keep the license notice and say what changed. A port of the idea needs neither.
- Stack: shadcn/ui on **Radix** (`asChild`, `data-[state=open]`, `@radix-ui/react-use-controllable-state`), `lucide-react`, `tw-animate-css` enter/exit classes, and **`ai` (AI SDK v6) types** (`ToolUIPart`, `UIMessage`, `LanguageModelUsage`). Also `streamdown` (+cjk, code, math and mermaid plugins), `shiki`, `use-stick-to-bottom`, `tokenlens` (cost table), `ansi-to-react`, `motion` (Shimmer only), `@xyflow/react` and `@rive-app` (Persona).
- Style: bordered cards (`rounded-md border`), raw palette status colours (`text-green-600`, `text-yellow-600`), uppercase tracking headings, `memo` and `useMemo` everywhere. None of it fits our tokens, Base UI or the React Compiler rules.
- The architecture is compound parts: `Reasoning` / `ReasoningTrigger` / `ReasoningContent`, with context carrying `isStreaming` and state. The pieces are thin. What is worth taking is the **state machines** (reasoning auto-open/close, tool state → badge, confirmation request/accepted/rejected) and a few **parsers** (stack trace).

## 3. Steal list (ranked)

1. **Reasoning as a real disclosure.** _Port the idea._ Put reasoning entries on their own path in `features/chat/components/activity-row.tsx`. The label reads "Thinking" (live, OrbitLoader in the icon slot per our loader rules) → "Thought for 12s" (duration from the entry `createdAt` span, `tabular-nums`). The body renders through `AssistantMarkdown` at `text-xs text-muted-foreground` instead of `<pre>`. Auto-open while streaming and auto-close when it ends, unless the user toggled it (the expansion store already exists: `state/chat-work-log-expansion-store.ts`). Delete the `Reasoning` branch in `utils/work-row.ts`.
2. **Context breakdown.** _Port the idea._ In `packages/client-core/src/chat/context-usage.ts`, keep `inputTokens`, `outputTokens`, `reasoningOutputTokens` and `cachedInputTokens` on `ContextUsage`. In the `context-usage-ring.tsx` popover, add a thin bar (a `bg-muted` track with a tone fill) and up to four `justify-between` rows, omitting any row the provider did not report.
3. **Tool detail sections.** _Port the idea._ In `activity-detail-section.tsx`, highlight **Input** as JSON through `HighlightedCode` when it parses, and tint **Output** with `bg-destructive/10` + `text-destructive` when the entry failed (`isWorkLogFailure`).
4. **Clickable stack frames and paths in tool output.** _Port the idea, write our own parser._ A pure `utils/stack-frames.ts` in chat, rendered in `activity-detail-section.tsx`. Frames become editor links through the markdown file-link resolver, and `node_modules`/`node:` frames get `text-muted-foreground`. Test it per call site against real Bun, Node and Vitest traces.
5. **Resolved approval label.** _Port the idea._ On the approval work-log row (`activity-row.tsx`, `icon==='approval'`), say what was decided ("Allowed once", "Always allowed", "Denied") from the `.resolved` entry that `live-activity.ts` already pairs by `requestId`.
6. **ANSI in command output.** _Port the idea and reuse our code._ Only if the logs show escapes in tool output. Move `features/git/utils/ansi-spans.ts` to `lib/` and render with it in `activity-detail-section.tsx`.
7. **Screenshot attachment.** _Copy the approach_ (a ~40-line rewrite, no licence issue). Add it to `chat-input-attach-button.tsx`. The browser prompts for a screen or window, and cancelling returns null quietly.
8. **Export conversation as Markdown.** _Port the idea._ A `session-menu.tsx` item built on the existing plan-export helper pattern.
9. Optional polish: `text-shimmer` band width proportional to label length; CSS-counter line numbers in code blocks.

## 4. Cost / risk

- There is no code to drop in: Radix (`asChild`, `data-[state]`), lucide, borders, raw palette colours, and `memo`/`useMemo` that the Compiler rules would strip. Anything kept verbatim needs an Apache-2.0 header. Rewriting from the idea is cheaper than adapting the files.
- Steals 1–5 are feature-local (chat) plus one client-core type. None needs a new dependency.
- Auto-open/close reasoning inside the virtualized timeline changes row height after the fact. It needs the existing disclosure-settle path in `timeline-viewport.tsx`, and a scenario must check that the reader's scroll position holds when the reasoning block collapses above it.
- The `tokenlens` cost numbers are a static price table and go stale. Do not adopt it.
