# Resident, tier and paged results, 2026-09-28

The integrated candidate opened, edited and saved all six plain-text sizes through **200 MiB**.
Every passing save was checked against the exact expected bytes by SHA-256. This report records
local verification; it does not assert that the candidate is deployed.

## Provenance and method

[Captured result rows and source identifiers](resident-20260928.json) preserve the baseline and
final measurements. Baseline: `/work/tmp/fregat-evidence/112-baseline-v2-20260928/`, Platform
`8ca59fd7d`, Editor `ad59752e`. Final: `/work/tmp/fregat-evidence/112-final-resident-20260928/`,
Platform source identifier `4f587e900`, Editor `fcb3fb5e`. The final build includes integrated
working-tree changes. The exact integrated diff was not captured by the source identifiers, so
these are **dirty integration measurements**. A clean committed-build confirmation remains pending.

Chromium 153.0.8010.12, Bun 1.4.2, fresh browser/API per case, production web assets, deterministic
`folded-functions-v1` ASCII corpus, ten-second settle, 30 keys spaced 80ms apart. Latency is
keydown to the next animation frame, not display presentation. CPU profiling was enabled. Each
row is one trial, not a distribution across machines or repeated runs. Heap is the main renderer
isolate after GC; backing storage and workers are separate. Peaks are sampled RSS, not retained heap.

The final fixture starts 30 bytes below its named size and reaches the limit after typing. The
baseline started at the named size; its 200 MiB renderer crashed during save, before a useful save
result. That baseline would also have exceeded the file limit by 30 bytes had it survived. The
crash-to-pass comparison therefore covers both implementation changes and the corrected fixture.

## Worker attribution and feature tiers

The candidate uses machine settings measured in **Mi UTF-16 code units**, each 1,048,576 units.
The file-open limit remains **200 MiB of source bytes**. These units coincide only for ASCII.
Analysis is enabled through 10 Mi code units; the minimap through 50 Mi code units. Bounds are
inclusive. Analysis covers syntax, language services, folding/indentation inference, Markdown
structures and whole-document helpers. Editing, undo and saving remain available above the tiers.
The 10 Mi analysis default comes from the final highlighting validation below.

The 50 MiB ASCII fixture retains its minimap at the inclusive threshold: its worker uses about
176.7 MiB after open (JS heap plus backing). The final 100/150/200 MiB rows have no minimap worker;
the remaining idle Shiki worker uses about 2.5 MiB. Thus these large rows measure resident plain
text, not syntax throughput. The pre-tier 200 MiB minimap cost motivated the independent ceiling.

The live `editor-feature-tiers` scenario lowers limits on an open document, observes analysis
pause while the minimap remains, then pauses both, edits/undoes/saves, and restores the features
by raising limits. Evidence: `/work/tmp/fregat-evidence/20260928T183608Z-scenario-editor-feature-tiers/`.
The final 200 MiB saved screenshot was also inspected: text, edited prefix and large-file notice
are visible, with syntax and minimap absent.

## E015: resident, streamed and paged contracts

The [Editor proof](../../../editor/docs/performance/e015-paged-proof.md) keeps full-buffer editing
separate from bounded read-only ranges. Streaming construction retains the complete buffer and
indexes; it reduces construction copies without making the editor paged. In its generated Unicode
corpus, 200 MiB construction changed from 1776ms/784.8 MiB sampled JS peak to 832ms/318.9 MiB;
steady JS heap remained 304.8/307.1 MiB. This standalone generator is not network throughput.

The 300/600 MiB paged proof retained an 8 MiB raw cache, about 2.3 MiB JS heap and 8.16 MiB backing,
with two reads in flight. Initial decoded ranges took 2.4/2.3ms; full indexes 2.10/4.29s. A complete
index plus sweep fetched about twice the file size. It checks Unicode, CRLF, copy, line jumps,
eviction, cancellation and changed revisions. UTF-16 is refused. The immediate disposal sample
for streamed 200 MiB still retained its buffer; no general reclamation claim follows.

Platform connects this controller to revision-checked filesystem read sessions. Above the resident
limit the error offers read-only access. The real browser scenario opened a sparse 300 MiB file,
navigated to line 3000, copied 128 displayed rows and observed session release after leaving.
Evidence: `/work/tmp/fregat-evidence/20260928T183651Z-scenario-editor-paged-readonly/`; the line-jump
screenshot was inspected. This fixture has 4096 populated lines followed by sparse padding; it is
not the standalone Unicode sweep. The run completed but recorded development font 403s, the
expected resident-read 413, and prefetch/log warnings. A clean integrated rerun remains distinct
from this functional proof.

Decision: proceed with bounded read-only access; keep editable residency at the verified open
limit. Editable paging requires dirty-page, history and save contracts and is not implemented.

**Decision: the analysis default is 10 Mi code units**, the largest size where both engines pass
inside the scope. At 15 Mi Shiki fails and Tree-sitter peaks at 7.7 GB; at 20 Mi both fail.
Tree-sitter paints first colours 6x sooner than Shiki at 10 MiB and uses half the renderer memory.

What still costs at 5–10 MiB with analysis on, from the typing CPU profiles:

- Every diagnostics publish rebuilds the whole highlight overlay mask
  (`refreshHighlightOverlayMask` in Editor `virtualizedTextViewHighlights.ts`), reading one code
  unit per range edge through `TextSnapshot.readRange`. Overlay ranges come from LSP
  unnecessary/deprecated diagnostics and spellcheck, so the cost scales with diagnostics in the
  whole document.
- Each of those `readRange` calls also runs the performance-diagnostics hook, which alone took
  532 ms of a 30-key window at 5 MiB.
- The TypeScript language server tree grows to 3–4 GB at 10–15 MiB; it, not Shiki or Tree-sitter,
  sets the memory ceiling.

An in-place minimap token projection was measured at 10 MiB and made no difference (minimap worker
heap 171 → 171 MiB Shiki, 78 → 78 MiB Tree-sitter; `/work/tmp/fregat-evidence/112-minimap-owned-10-20260928/`),
so it was not landed.
