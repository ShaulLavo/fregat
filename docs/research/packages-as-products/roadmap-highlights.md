# Roadmap highlights for product pages

Input for [Plan 336](../../../plans/336-packages-as-products.md) Track B (pitch) and Tracks C/D
(READMEs, sites). It lists the planned work worth a "planned" line on each product page, ranked
by how much a visitor would care, with each item's real state.

Read on 2026-10-08 at Fregat `0df5eb872`: [PLAN.md](../../../PLAN.md), the
[plan index](../../../plans/README.md) and every file in `plans/` (status lines for all of them,
full reads of the candidate plans), the [Editor backlog](../../../plans/editor-backlog.md),
the package `PLAN.md` stubs (they only link to the root roadmap), the
[native plan of plans](../../../plans/native-plan-of-plans.md), [tui-plan](../../../plans/tui-plan.md),
[docs/next-wave.md](../../next-wave.md), [docs/product-vision.md](../../product-vision.md), the
[1000% parity vision](../../../plans/editor-1000-parity-plan.md), tree-sitter-x `origin/master`
and its TextMate-scope plan, and the current `apps/site` copy. Progress was checked against
`git log`, source directories and npm.

## How to read the verdicts

- **Announce: yes.** Approved, the owner wants it seen, and the line can be written without a
  date or an unproven number. Label it "planned" and link the plan (Plan 336 decision 3).
- **Only once started.** Approved, but no code exists yet, it sits behind other plans, or a
  visitor would read it as a promise we cannot yet back. Add the line when the first unit lands.
- **No.** Internal, far off, parked, an idea, or too small to sell.

Status words follow the plans: Approved (not started), In progress, Partly shipped, Shipped.

## Shipped, but nobody advertises it

The plans treat these as done; no README or site mentions them. Each needs its evidence linked
before it appears in copy.

**Fregat**

- Agents keep working while you are away: Claude `/goal` and Codex thread goals shown and
  controllable, scheduled "sleeping" sessions kept alive and cancellable ([144](../../../plans/144-unattended-agent-work.md) phases 1–3).
- An agent's edit comes back with the type errors it introduced, so it fixes them unprompted
  (Claude; [140](../../../plans/140-editor-agent-advantage.md) P4, #99).
- Agent review mode: ask the same or a second model to review uncommitted work, a turn, a branch
  or a commit; findings land as comments on the diff lines ([169](../../../plans/169-agent-review-mode.md)).
- Per-hunk keep/undo of an agent's diff and a review draft ([139](../../../plans/139-acting-on-agent-diffs.md)).
- "Fix with AI" from any error toast, diagnostic, Problems list or hover ([diagnostic fixes](../../../plans/diagnostic-ai-fix-plan.md)).
- Usage, cost and rate-limit meter, per-turn usage history, cache savings ([141](../../../plans/141-usage-and-rate-limits.md)).
- External MCP servers managed from one page for both harnesses, with sign-in from any device
  ([174](../../../plans/174-external-mcp-servers.md)).
- Voice dictation in the chat composer (#903, [docs/chat-dictation.md](../../chat-dictation.md)).
- Web Push notifications (`apps/web/public/sw.js`) and device pairing for the phone.
- Commit history with a branch and merge graph, filters and historical diffs
  ([git panel plan](../../../plans/git-panel-implementation-plan.md)).
- New drafts placed across machines by capacity and preference (#272).
- PDF tabs and an editable CSV table view ([156](../../../plans/156-documents-in-the-editor.md)).
- Opening very large files: 200 MiB plain text reads at 27 ms p95, larger files open in a paged
  viewer ([112](../../../plans/112-large-file-ceiling.md)).
- Theme studio, bundled themes paired with wallpapers, and a setting for nearly everything with a
  browsable defaults reference.
- More harnesses than the pitch names: Cursor (ACP, off by default) and OpenCode (partial driver)
  adapters exist beside Claude Code and Codex. Do not advertise them until they are on by default.

**Singapore** (the README lists none of these)

- An undo tree: branches are kept, and you can browse, compare and restore them (E017, E019).
  Fregat persists it across file closes (E018).
- Cursor jump history that survives edits, per view (E020).
- English spellcheck in a worker, shared by every editor on the page (`@singapore-editor/spellcheck`).
- Markdown live preview on the plain Markdown buffer (`@singapore-editor/markdown`).
- A TypeScript language server in a worker with full parity to the server path (E054,
  `@singapore-editor/typescript-lsp`).
- Measured engine wins with reports: syntax token work per keystroke 155 ms → 0.004 ms on 500,000
  tokens (E035); find 20–250× faster on 500,000 lines (E008); 20,000 paragraph replacements leave
  4 pieces instead of 20,002 (E006); AVL sequence tree 22–34% faster on random edits (E040).
- Diagnostic fades and strikes painted in each token's own colour, verified in Chromium, Firefox
  and WebKit (E053).
- `decode`, a plugin that makes a file type itself out as it opens; `panes`, zero-dependency split
  panes; a Solid adapter beside React.

**ghostty-webgpu**

- The first terminal frame is server-rendered into the page's HTML and the live renderer takes
  over in place ([285](../../../plans/285-ghostty-site-first-frame-and-real-shell.md)).
- The GPU frame is built in Zig inside the wasm module; only changed byte ranges are uploaded
  ([283](../../../plans/283-ghostty-output-and-input-latency.md)).
- A DOM renderer and a "Redraws" overlay that shows which cells repaint.
- Reads native Ghostty config (`docs/config-resolver.md`) and plugs into `@fregat/hotkeys`.

**hotkeys**

- Key lookup through a chord trie: 0.04 µs against TanStack Hotkeys' 83 µs over the Editor's 255
  bindings ([203](../../../plans/203-fregat-hotkeys.md); Bun microbenchmark, re-run before quoting).
- One library drives three products: Singapore, ghostty-webgpu and Fregat's web app and TUI (PR #603).
- A terminal-input adapter, so the same keymap runs in a TUI.
